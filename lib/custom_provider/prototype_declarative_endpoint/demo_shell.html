PROTOTYPE自定义调用端点：定义格式与模板语言细则

Wayfinder #2119 · 票 #2123。这是一份可以点的草案，不是产品界面。

要回答的问题：「JSON 结构模板 + {{ }} 占位符 + 唯一的 $each + JSONPath 优先级数组 + 纯字典映射 + header/query 鉴权」这套声明式定义，写成 JSON Schema 后，能否把三份起步模板（通用提交+轮询、NewAPI 视频、ComfyUI 工作流）从「填参数 → 渲染请求 → 读响应 → 归一状态 → 取产物」完整跑通，中途的每一条约定（整串占位符保留原生类型、空值删键、整数状态字符串化查表、只收字符串命中、枚举缺项不发请求……）在真实回包形状面前是否站得住。

用法：左栏选一份起步模板（可直接改 JSON 再「应用」），右栏用「引导走查」按顺序点，或在「自由操作」里任意组合提交 / 轮询响应。所有 HTTP 往来都是假的：你选哪条响应，供应商就「回」哪条。

待你拍板的约定

下面每条都已在本页按「原型选择」实现；走查时觉得哪条别扭，就是要改的地方。

  1. 响应根是 body。JSONPath 的 $ 指向响应体；headers / status_code 经 extract 对象的 source 指定，而不是 n8n 式的 $.body.… 三分对象。
  2. 四档而非五档。status_map 只能映射到 queued / running / succeeded / failed；expired 不由声明式产生（抽样 0 家需要）。timeout / cancelled / aborted 一律归 failed。
  3. {{ api_key }} 只在 auth 节可用。请求体 / URL 里出现即校验失败——代价是凭证入体的旧式接口不支持。
  4. 轮询允许 POST + body（ComfyUI 托管平台需要）。submit / poll 是同一种请求对象。
  5. 整串单占位符保留原生类型；混合文本一律串化；值为 null 的整串占位符删掉所在键 / 元素；混合文本里遇到 null 报错。
  6. 枚举映射只对 duration / aspect_ratio / resolution / generate_audio 开放，键按字符串化查表，缺项不发请求。数字→字符串枚举（"5"）走这里，不给模板加转换。
  7. 提取只收字符串命中（默认 accept: string），状态字段可声明 accept: scalar 以收整数码；数组 / 对象 / null 一律跳到下一条路径。
  8. json_decode + then 是评估项：固定后缀、非表达式，换来 JSON-in-string 两家可用。要不要进首期？
  9. 素材只有四个来源（start_image / end_image / reference_images / reference_audio_files）与两种编码；列表型只能经 $each；MIME 白名单不匹配即不发请求。
  10. 能力声明与 VideoCapabilities 同名同义；supported_durations / resolution 仍留在模型行 DB，不进定义文件。
  11. ComfyUI 模板把 workflowId 当 {{ model }}（模型行填工作流 id）。可接受的复用，还是需要独立变量？
  12. 自托管 ComfyUI /history 的产物不是 URL（filename / subfolder / type 要拼 /view?…），本原型不覆盖；托管平台形态（返回 fileUrl）可覆盖。
  13. 路径校验器是手写子集解析器（本页所用），前端是否引入 json-p3 做即时求值预览仍是 #2122 的未决项。
