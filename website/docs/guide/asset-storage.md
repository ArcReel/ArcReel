# 素材库与对象存储 {#object-storage-and-asset-library}

在「设置 → 素材库与存储」中可以配置两项独立功能。两者均为可选，默认直接使用本地文件进行制作。

- 如果希望模型引用经供应商审核通过的图片，请配置素材库账号并与推理凭证绑定，然后[上传图片](#upload-to-asset-library)或[选择已有素材](#select-from-asset-library)。
- 想把之后保存的图片放在自己的 TOS 存储桶，请[启用对象存储](#remote-image-storage)。
- 想迁移素材，请查看[全局资产库](#asset-library-across-projects)和[项目 ZIP](#asset-library-in-project-zip)对图片版本与关联的处理。

## 配置连接与凭证 {#configure-asset-storage}

火山方舟与 BytePlus 的供应商素材库可以保存经过审核的素材，生成时以 `asset://` 引用。

- **对象存储**：你自己的 TOS 存储桶，填写区域、Endpoint、桶名与 Access Key。只保存连接不改变图片的保存位置，新增图片默认仍保存在本地；要把新增图片保存到这个桶，另在「新增图片保存位置」中选择「对象存储」，见[新增图片保存到对象存储](#remote-image-storage)。Endpoint 填 TOS Endpoint（如 `tos-cn-beijing.volces.com`），不支持 `tos-s3-` 开头的 S3 兼容 Endpoint。保存后可以用「测试连接」确认凭证与桶可以访问。
- **素材库账号**：访问素材库控制面的 Access Key，与推理用的 API Key 分开保存，需要具备素材库权限。添加账号时选择站点（火山引擎中国站或 BytePlus 国际站）并填写项目，默认项目为 `default`。供应商按项目隔离素材，推理凭证需要属于同一个项目。控制面请求只发往所选站点的官方地址，不使用推理凭证的 Base URL。供应商素材仅归属于创建它的云账号，因此关联与入库任务会记录提交时所用 Access Key ID 对应的云账号。如果将账号的 Access Key ID 更换为另一个，原有关联会留在原云账号下且不再用于生成，未完成的入库任务也不会改用新的 Access Key 继续推进，你需要在新账号下重新上传或选择图片。只修改 Secret Access Key 不影响已有关联。
- **推理凭证绑定**：为每条火山方舟密钥或自定义供应商选择它可以使用的素材库账号。修改推理凭证的密钥或 Base URL，或修改账号的站点、项目与 Access Key ID 后，绑定显示「需要重新确认」，确认前不使用该账号的素材。绑定只表示你确认这条推理凭证与账号对应，供应商仍按自己的权限校验每次调用。

所有 Access Key 仅在设置页输入，后续查看时只显示首尾几位字符。

## 上传图片到素材库 {#upload-to-asset-library}

在项目资产卡片或角色详情中衍生的更多操作菜单中选择「上传到供应商素材库」，可以为每个素材库账号上传这张图片当前选中的版本。上传前需要配置对象存储：ArcReel 把图片副本写进你的存储桶，签发 24 小时内有效的下载地址交给供应商，再提交入库，因此 ArcReel 不需要公网地址。

- 供应商异步审核入库，状态依次为「等待上传」「提交中」「供应商处理中」，完成后变为「可用」或「失败」。关闭窗口不影响入库，只有「可用」的关联会用于生成。失败时显示供应商返回的错误码与原因。
- 关联属于图片的具体版本。入库期间改选其他版本，结果仍归属提交时的版本；新选中的版本需要另行上传，切回旧版本时仍可使用旧版本的关联。
- 提交请求的结果不确定（如网络中断）时，状态显示「结果待确认」。ArcReel 按提交记录在素材库中查找这次上传的素材，不会重复创建。长时间没有结果时，可以解除关联后重新上传。
- 「解除关联」仅解除 ArcReel 中的关系，既不会删除 ArcReel 中的图片，也不会删除供应商素材库里的素材。供应商素材的改名与删除在供应商控制台进行。解除后可以重新上传。
- 首次上传时，ArcReel 在账号的项目里创建名为 `ArcReel` 的素材组。供应商要求创建素材组前在控制台签署授权，未签署时上传失败并显示供应商的错误码。

存储桶里的中转副本都在 `arcreel-relay/` 前缀下，由 ArcReel 后台自动清理：入库有结果后，副本自写入起至少保留 1 小时再删除；一直没有结果时，保留到下载地址过期后 1 小时。删除失败时自动重试，清理不涉及桶内其他对象。删除连接或更换桶、Endpoint 时，可立即删除或放弃这些副本，见[更换或删除连接](#remote-image-storage)。

图片已经[保存到对象存储](#remote-image-storage)时，不另写中转副本，直接为桶里的这张图片签发下载地址。入库期间在 ArcReel 中删除这张图片并彻底清除，桶里的图片也按上面的期限保留，供应商仍能取图，期满后不再被使用时才删除。

## 从素材库选择已有图片 {#select-from-asset-library}

在项目资产卡片或角色详情中衍生的更多操作菜单中选择「从供应商素材库选择」，可以按账号查看素材库里的素材名称、类型与可用状态，并选择一张已入库的图片作为这张资产图或衍生图。选择不需要配置对象存储。

- 只有状态为「可用」的图片素材可以选择。ArcReel 向供应商查询素材，从供应商返回的访问地址取回原图，再按上传图片的方式保存为一个新版本：新版本出现在版本历史里，可以预览、局部修改，也可以切回之前的版本。
- 导入的新版本会自动与所选素材建立「可用」关联，并记录对应素材库账号的站点、区域与项目；原有历史版本不会继承该关联。
- 取不回原图时不导入，例如素材已在供应商侧删除、访问地址已失效或网络中断。素材原图须为 PNG、JPEG 或 WebP 格式，大小不超过 30 MB。导入失败时图片保持原来的版本，也不建立关联，可以稍后重试或换一张素材。
- 导入过程不会压缩或缩放原图，以确保保存的版本与供应商素材一致：资产图直接保留原图内容；衍生图固定保存为 PNG 格式（PNG 原图原样保存，JPEG 与 WebP 原图则按原像素转换为 PNG）。

## 保存到全局资产库与应用到其他项目 {#asset-library-across-projects}

「加入资产库」发现同类型、同名的条目时，可修改名称后加入，或选择「覆盖已有」更新该条目。资产图或其衍生图有生成或图片编辑任务排队或执行时，请等任务结束后再加入资产库。角色音色试听期间可以照常加入。

把项目资产保存到全局资产库，或把全局资产库里的资产应用到其他项目时，资产图与衍生图当前版本的「可用」关联随图片一起带过去，仍属于原来的素材库账号、站点、区域与项目。

- 带过去的是关联的副本，由各自的项目或全局资产库独立持有：在一处解除关联或换图，不影响其他副本。
- 生成时仍按这次实际使用的推理凭证判断关联是否适用。推理凭证绑定的是另一个账号时，带过去的关联不适用，照常发送图片内容。
- 只带「可用」的关联。尚在入库或入库失败的任务不带过去，需要时在目标项目里重新上传。
- 删除来源项目或资产后，全局资产库以及已应用该资产的其他项目仍可照常使用，供应商素材库中的素材也不会被删除。

选择「覆盖项目里的同类资产」时，如果项目资产有排队或执行中的任务（包括角色音色试听），该资产会保留原样，批次中的其他空闲资产仍可应用。任务结束后可以重试覆盖，也可以选择「以新名称加入」。

## 项目 ZIP 与供应商素材关联 {#asset-library-in-project-zip}

导出项目 ZIP 时，包里图片版本的「可用」关联随图片一起带走，仍属于原来的素材库账号、站点、区域与项目。在另一台 ArcReel 导入后，推理凭证绑定的素材库账号与原账号属于同一个云账号时，生成直接使用这些素材，不需要重新上传。

- 导入的关联只在推理凭证绑定的账号与原账号属于同一个云账号、且站点、区域与项目都相同时使用；否则关联保留但不使用，照常发送图片内容。素材能否使用最终由供应商按账号判断。
- 只带「可用」的关联。尚在入库、结果待确认或入库失败的任务不带，导入后在目标项目里重新上传。
- 「仅当前版本」的 ZIP 只带随包的版本的关联。没有随包带上版本记录的图片（例如生成的资产图）不带关联。
- ZIP 里不含素材库账号的 Access Key、签名地址或对象存储信息。包里的图片被改过时，对应的关联不导入，图片照常导入。

## 生成时使用素材库 {#generate-with-asset-library}

参考生视频提交前，ArcReel 先确定视频通道这次实际使用的推理凭证，找到这条凭证已确认绑定的素材库账号，再逐张检查参考图当前选中的版本在这个账号里有没有关联。上传与导入建立的关联按同样的规则使用。

- **关联可用**：这张参考图以 `asset://` 素材引用发出，其余参考图照常发送图片内容。参考图的数量、顺序与提示词里的图片编号不变。
- **没有适用的关联**：照常发送图片内容。推理凭证没有绑定或绑定需要重新确认、当前版本没有上传或导入过、模型不接受素材引用时，都按没有适用的关联处理。
- **关联尚未可用或入库失败**：关联处于「等待上传」「提交中」「供应商处理中」「结果待确认」或「失败」状态时，不改发图片内容，也不向供应商提交请求。提交前的检查、批量生成预览与费用预估就会指出这个问题，不给出这一单元的预估费用；执行时再按实际发出的图片检查一次，状态在提交之后才变化的，生成在执行时失败。提示点名第几张图片：可以等入库可用后再生成；入库失败时提示中带有供应商的错误码。也可以解除关联，改发普通图片。

只有火山方舟与 BytePlus 的 Seedance 2.0 与 2.5 系列模型的参考图使用素材引用。是否适用看模型挂接的调用端点，不看模型 ID 本身：调用端点为「火山方舟 (Seedance 2.0)」或「火山方舟 (Seedance 2.5)」时适用，「火山方舟 (Seedance 1.x)」不适用。内置供应商与自定义供应商的模型按同一规则判断。首帧、尾帧、分镜图与图片生成仍然发送图片内容。切换推理凭证后，按新凭证的绑定重新判断，之前账号里的关联不再适用。

供应商以输入图片未通过审核拒绝请求时（错误码以 `InputImageSensitiveContentDetected` 开头，例如 `InputImageSensitiveContentDetected.PrivacyInformation`），ArcReel 不自动上传、不重试生成，也不切换供应商。错误提示给出供应商的错误码，并提示把相关资产图上传到供应商素材库，等入库可用后重新生成。仅当请求中只有一张参考图且不含首尾帧时，提示才会明确指出这张图片；若供应商报错未指明具体图片，ArcReel 不会自行猜测。被拒的图片已经以素材引用发出时，提示改为在供应商控制台检查该素材。

## 在对话中使用素材库 {#asset-library-in-agent}

ArcReel Agent 和通过远程 MCP 连接的外部 Agent 可以完成同样的素材库操作，与资产卡片使用同一组关联记录：

- 查询一张图片当前版本的关联与入库状态，以及可用的素材库账号；
- 浏览素材库账号里已有的素材，并把你选定的图片保存为资产图的新版本；
- 在你明确要求时，把指定图片上传到素材库；
- 在你同意后解除关联，ArcReel 图片与供应商素材都不删除。

Agent 只在你明确要求时上传。生成被供应商审核拒绝后，Agent 会转述原因并说明可以上传，由你决定，不自动上传或重新生成。上传后 Agent 立即得到入库任务，不等待供应商审核；你可以稍后让 Agent 查询状态。素材库账号、对象存储与推理凭证绑定仍在「素材库与存储」分区配置，Agent 看不到其中的密钥，也不能改名或删除供应商素材库中的素材。

## 新增图片保存到对象存储 {#remote-image-storage}

对象存储连接默认仅用于素材入库时的图片中转。若希望将新增图片持久化保存在存储桶中、本地仅保留可清理的缓存，可在「素材库与存储」分区的「新增图片保存位置」中选择「对象存储」。这是一项实例级全局设置（默认为「本地」），不支持按项目或单张图片单独设置。

**最小配置**

1. 配置对象存储连接，并用「测试连接」确认凭证与桶可以访问。
2. 在「新增图片保存位置」中选择「对象存储」，选中后立即生效。没有配置连接时不能选择。

连接的 Access Key 需要对这个桶上传、读取（含查询对象信息）与删除对象的权限；「测试连接」只检查能否访问桶，不检查这些对象权限。删除权限用于清理中转副本、回收不再使用的图片对象。

**生效范围**

- 设置只影响之后新保存的图片版本：生成与局部修改的图片、宫格图与切分出的分镜图、手动上传的资产图、分镜图、衍生图与宫格图、从素材库选择的图片、导入的项目 ZIP，以及保存到全局资产库和应用到项目的图片。
- 已有图片与历史版本不搬迁，仍从各自原来的位置读取。切回之前的版本、从回收站恢复，都沿用那个版本原来的位置，不算新保存的图片。
- 改回「本地」只影响之后新保存的图片，桶里已有的图片照常读取。同一个项目里可以同时有本地图片与远端图片。
- 以下图片不建版本历史，始终保存在本地：分镜的尾帧、角色原图与商品原图、项目的风格参考图。视频与音频也始终保存在本地。

**中转副本与图片对象**

存储桶中的对象按前缀分为两类，分别管理：

| 前缀 | 内容 | 清理方式 |
| --- | --- | --- |
| `arcreel-relay/` | 素材入库时的中转副本 | 入库有结果或下载地址过期后由后台删除，见[上传图片到素材库](#upload-to-asset-library) |
| `arcreel-materials/` | 保存到对象存储的图片，按内容命名，同样的图片只存一份 | 只要还有版本历史、回收站、已删除项目、全局资产库、其他项目或入库中的任务在用就保留；不再被任何一处使用（如在回收站中彻底删除）后由 ArcReel 删除 |

不要在 TOS 控制台手动删除或改写 `arcreel-materials/` 下的对象，否则对应图片无法预览、生成或导出。中转清理不涉及这些对象。

**本地缓存**

远端图片在本地有一份缓存，供预览、生成与图片处理直接使用。缓存只是副本，清理后需要时自动从对象存储取回并核对内容，打开工作台、查看状态不会触发下载。

- ArcReel 后台每小时清理一次闲置超过 24 小时的缓存。
- 需要立即释放空间时，调用 `POST /api/v1/object-storage/work-cache/cleanup`。请求体可以带 `min_idle_seconds`，只清理闲置超过这个秒数的缓存，缺省为 `0`。返回清理的文件数 `removed`、释放的字节数 `freed_bytes`，以及因正在使用而保留的文件数 `kept_in_use`。
- 清理只删除已确认保存在对象存储、且与远端内容一致的缓存；本地图片、正在使用的文件与桶里的对象都不受影响。

**备份与迁移**

- 远端图片的内容只在桶里，备份 ArcReel 数据目录不包含它们。启用后需要同时保留这个桶。ArcReel 会删除不再使用的图片对象，要能恢复较早的备份，须同时备份桶里 `arcreel-materials/` 下的对象，或为桶开启版本控制，见[备份与恢复](../ops/deployment.md#backup-and-restore)。
- 迁移到另一台 ArcReel 时导出项目 ZIP。导出前 ArcReel 先取回缓存已清理的远端图片，ZIP 里是图片的实际内容，不含桶名或访问密钥；另一台 ArcReel 按自己的「新增图片保存位置」重新保存这些图片。

**更换或删除连接**

- 桶里还有项目、回收站、全局资产库等正在使用的图片对象，或有图片正在保存时，不能更换桶、Endpoint 或区域，也不能删除连接，只能更新 Access Key。没有引用或只被入库任务使用的图片对象不影响更换或删除连接。
- 「新增图片保存位置」为「对象存储」时不能删除连接，先改回「本地」。
- 如果在保存图片的同时更换了连接，当次保存会失败并保留原有图片，重试后图片将写入新的存储桶。
- 项目正在删除或被导入的项目替换时，保存到这个项目的图片会失败，项目原有的图片不受影响。
- 删除连接或更换桶、Endpoint 时，默认勾选「同时删除 ArcReel 写入桶里的待删除文件」。ArcReel 会用当前凭证立即删除没有引用的图片对象、只被入库任务使用的图片对象及全部中转副本，不等待保留期。更换桶或 Endpoint 时，保持勾选保存前会再次确认。只改区域时不显示此选项，原有保留与清理规则不变。
- 取消勾选后，桶内文件不动，ArcReel 清除对应记录。勾选后删除失败的，页面报告一次失败数量和原因，连接仍照常变更，记录同样清除。放弃或删除失败的文件可在原桶的控制台清理，ArcReel 不再自动重试；桶内其他文件不受影响。
- 如果存在尚未得出结果的入库任务，对话框会提示受影响的任务数量。连接切离旧桶后，这些任务会随之失败；原图仍保存在 ArcReel 中，解除关联后即可重新上传。

**故障处理**

- **提示「图片没能保存到对象存储」**：这次的新版本不会出现，之前的版本、产物与文件不变。用「测试连接」确认连接，检查 Access Key 的上传权限与网络后重试；也可以先改回「本地」继续创作。导入项目 ZIP 时出现这个提示，这次导入没有写入任何项目，检查连接后重新导入。
- **区域、Endpoint 或桶填错，图片一直保存失败**：先把「新增图片保存位置」改回「本地」，再编辑连接改正，或删除连接后重新配置。保存失败的图片没有被任何地方使用，不妨碍修改。改正 Endpoint 或桶时，对话框显示清理选项，已有记录按「更换或删除连接」的规则处理。原 Endpoint 不可达时，删除失败按网络原因报告一次，记录照常清除；这些对象没有写进桶里，不需要处理。写进过原来的桶但没有删除成功的，需要在 TOS 控制台清理。切勿按前缀批量删除 `arcreel-materials/` 下的对象：如果改正前后指向的是同一个桶，其中有正在使用的图片。
- **预览、生成或导出时提示「没能从对象存储取回这张图片」**：先检查网络和读取权限。项目回收站只保留图片在存储桶中的引用，没有图片副本。如果桶里的对象被删除或改写，请从桶备份或历史版本把原内容放回原来的对象键，再重试。找不回原内容时，可以改用还能读取的图片版本，或重新生成、上传图片。
- **提示图片保存在原来的对象存储桶里，当前连接已删除或指向另一个桶**：连接的桶或 Endpoint 已不是保存这张图片时的设置。把连接改回原来的桶与 Endpoint 后即可读取。
- **提示新增图片设为保存到对象存储，但还没有配置连接**：配置连接，或把「新增图片保存位置」改回「本地」。
- **保存图片变慢**：图片在保存版本的过程中上传到对象存储，确认保存后才出现新版本。上传期间，同一项目的其他图片保存会排队等待；图片较大或网络较慢时更明显。导入项目 ZIP 时，图片在导入请求中逐张上传。
