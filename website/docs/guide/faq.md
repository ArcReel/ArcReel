# 常见问题 {#faq}

本文汇总 ArcReel 当前版本中最常见的安装、配置、制作与排障问题。第一次使用时，建议先阅读[完整入门教程](./getting-started.md)。具体供应商和模型能力以设置页当前显示为准。

## 使用 ArcReel 前需要了解哪些能力边界？ {#capability-boundaries}

- 媒体生成依赖第三方模型服务，生成速度、可用性、内容策略和成本受供应商影响。
- 长篇内容仍需要人工审核分集、角色资产和关键剧情节点，ArcReel 的目标是增强创作者，而不是完全取消审核。
- 不同视频模型对参考图数量、视频时长、首尾帧、音频和地区可用性的支持不同。
- Windows 原生环境可以运行部分基础流程，但 Agent 沙箱等 POSIX 能力会降级；优先使用 Linux、macOS、WSL2 或 Docker。
- 生产环境应使用 PostgreSQL、HTTPS、强密码和定期备份，不建议直接把未加保护的 `1241` 端口暴露到公网。

## 安装、部署与更新 {#install-deploy-update}

### 推荐怎样安装？Windows 可以直接运行吗？ {#how-to-install}

首次使用建议按[入门教程的 Docker 步骤](./getting-started.md#deploy-arcreel)部署。Windows 用户推荐使用 WSL2 或 Docker Desktop，原生 Windows 环境下的 Agent 沙箱存在[运行限制](../ops/deployment.md#container-permissions-and-sandbox)。

### Docker 启动后打不开，或者容器反复重启怎么办？ {#docker-wont-start}

在使用的 Compose 目录查看 `docker compose ps` 与 `docker compose logs arcreel`，先查[服务无法启动](../ops/deployment.md#service-wont-start)。`SANDBOX_UNAVAILABLE` 或 `SANDBOX_BWRAP_BROKEN` 按[容器权限与 Agent 沙箱](../ops/deployment.md#container-permissions-and-sandbox)处理。

### 默认登录账号是什么？忘记密码怎么办？ {#default-login}

默认用户名是 `admin`，可通过 `.env` 中的 `AUTH_USERNAME` 修改。`AUTH_PASSWORD` 留空时，首次启动会生成密码并回写到当前部署目录的 `.env`，不会把明文密码打印到日志。

忘记密码时，修改 `.env` 中的 `AUTH_PASSWORD`。Docker 部署需要重建容器以重新载入环境变量：

```bash
docker compose up -d --force-recreate
```

源码部署则直接重启 ArcReel 服务。切勿在公网部署环境中关闭身份认证。

### 修改 `.env` 后为什么没有生效？ {#env-changes-not-applied}

修改 Compose 目录中的 `.env` 后，执行 `docker compose up -d` 重新创建受影响的容器。普通重启沿用创建容器时的环境变量。变量说明见[环境变量](../ops/deployment.md#environment-variables)。

### Docker 怎样更新？更新会丢失项目吗？ {#docker-update}

先备份，再按[升级步骤](../ops/deployment.md#upgrade)拉取镜像并启动。启动时会迁移数据库和项目结构。需要回到旧版本时，请恢复升级前的备份。设置页「关于」可以检查更新并打开发布页。

### 项目和配置存在哪里？怎样备份或迁移？ {#where-is-data}

默认 Docker 部署的数据根为 Compose 目录下的 `projects/`，同目录下还有 `.env` 和 `claude_data/`。使用 PostgreSQL 部署时还需备份数据库，启用图片对象存储后还需保留存储桶中的对象。参见[持久化目录](../ops/deployment.md#sqlite-volumes)和[备份与恢复](../ops/deployment.md#backup-and-restore)。

## 首次配置与 Agent {#setup-and-assistant}

### 开始制作前需要配置哪些凭据？ {#required-credentials}

项目对话使用独立的 [Agent 供应商](./providers.md#assistant-providers)，文本、图片、视频和配音则使用各自的[生成模型配置](./providers.md#media-and-text-providers)。如果生成失败，请先检查项目设置中实际选用的模型。

### 怎样让 Agent 开始或继续制作？ {#start-or-resume-assistant}

在项目右侧打开 Agent，直接说明“开始制作”或“继续制作”即可。Agent 会检查项目当前状态，从尚未完成的阶段继续，并在需要审核剧本、资产或分镜时等待确认。

如果 Agent 提示未登录、无法启动或没有可用模型，先到设置页确认 Agent 凭据已经保存、消息调用探测成功且处于激活状态。模型发现告警不一定阻断消息调用，但应核对实际模型 ID。无需在 Agent 面板另行登录 Claude 网页账号。

### 出现 `Failed to start Claude Code`、启动超时或 `Control request timeout` 怎么办？ {#assistant-startup-failure}

这些提示表示 Agent 进程没有正常启动或未能及时完成初始化，不等同于剧本内容错误。依次检查：

1. Agent 凭据是否已激活，模型 ID 是否与服务端实际开放的 ID 完全一致。
2. Docker 容器或服务器能否访问 Agent API，代理、DNS 和 TLS 是否正常。
3. Docker/WSL/本地环境的 Agent 沙箱是否通过启动检查。
4. 在设置页「关于」中下载诊断日志，查看报错时间点附近的具体上游状态码。

连通性检查只代表最小请求成功；长会话仍可能受到额度、上下文长度、限流或代理超时影响。

### Windows 从源码启动后，Agent 提示事件循环不支持创建子进程怎么办？ {#windows-reload-agent}

在 Windows 原生环境用 `--reload` 启动后端时，uvicorn 会改用不支持子进程的事件循环，Agent 无法拉起 Claude Code。界面显示「后端的事件循环不支持创建子进程」，旧版本只显示 `Failed to start Claude Code:`，冒号后为空。

去掉 `--reload` 重新启动后端：

```bash
uv run uvicorn server.app:app --port 1241
```

也可以运行 `uv run python -m server.app`，它在 Windows 上不启用 reload，监听地址取 `LISTEN_HOST` 与 `LISTEN_PORT`。不启用 reload 时，修改代码后需要手动重启后端。

### 子智能体报错 `Refusing to use … as an isolation worktree` 怎么办？ {#subagent-isolation-worktree}

Agent 派发子智能体时，可以要求子智能体在隔离的 worktree 中运行。ArcReel 让子智能体与 Agent 共用项目目录，Claude Code 会先用 git 确认这个目录可以作为隔离目录，确认不了就拒绝这次派发。按报错中的原因处理：

- **`git could not be run to resolve it`**：运行环境里没有 git。官方镜像从 v0.37.0 起内置 git，Docker 部署更新镜像即可，步骤见[Docker 怎样更新](#docker-update)。从源码启动时，安装 git 后重启后端。
- **`git resolves its working tree to …`**：项目目录位于 ArcReel 源码仓库内。从源码启动时，默认数据根 `projects/` 就在源码仓库内。把数据根移到源码仓库之外：
  1. 停止后端。
  2. 把数据根整个目录移到源码仓库之外，例如 `~/arcreel-data`。报错中的路径是 `<数据根>/projects/<项目名>`，去掉末尾的 `/projects/<项目名>` 就是数据根。数据根里还有默认 SQLite 数据库、日志和 Vertex 凭据，需要整体移动。
  3. 把 `ARCREEL_DATA_DIR` 设为新目录的绝对路径。通常写在 `.env` 中；如果启动环境（如 shell 或 systemd 服务配置）已经设置了这个变量，改那里的值，否则 `.env` 中的值不会生效。
  4. 启动后端。已有的 Agent 会话会在启动时自动关联到新路径。

## 供应商、模型与 API {#providers-models-api}

### ArcReel 支持哪些供应商和模型？ {#supported-providers}

支持范围以设置页当前的内置供应商、模型列表和能力标记为准。一个供应商被支持，不代表它的所有模型、账号区域和输入形式都可用；图片、视频、文本、语音以及参考图、尾帧、时长和分辨率能力都按具体模型判断。

不要仅根据模型名称猜测能力。新增或调整模型后，应重新确认其媒体类型、调用端点和账号权限。

### Base URL 应该怎样填写？ {#base-url-format}

优先选择内置供应商，让 ArcReel 使用内置地址。自定义供应商应填写服务商 API 文档给出的协议根地址，不要填写控制台网页地址，也不要盲目为所有地址追加同一个 `/v1` 或 `/v1/messages` 后缀。

如果请求返回 `404 page not found`，通常需要核对：

1. 当前选择的是哪种发现协议和调用协议。
2. Base URL 是否指向正确区域和 API 根路径。
3. 服务端是否真的实现了对应的模型列表和生成端点。

### 怎样接入自定义供应商？ {#custom-provider-setup}

按[自定义供应商](./providers.md#custom-providers)添加接口地址、凭证和模型。获取到模型列表后，为实际生成所用的模型核对媒体类型和调用端点。

### 获取模型列表失败，或者出现 `model_not_found` 怎么办？ {#model-list-failure}

按以下顺序检查：

1. 使用服务端公布的精确模型 ID，不要使用展示名称。
2. 确认 Base URL、账号区域与 API Key 匹配。
3. 确认账号已开通该模型，并有相应模态的调用权限。
4. 确认模型已启用，媒体类型和调用端点配置正确。
5. 检查项目级设置是否仍覆盖着旧模型。

部分兼容服务没有实现模型列表接口，此时可以手动登记模型；但如果真实调用仍返回 404，应由服务提供方确认路由和权限。

### 为什么连通性检查成功，实际生成仍然失败？ {#connection-ok-generation-fails}

连通性检查主要验证凭据、网络和模型发现是否可用，不会完成一次真实的付费图片或视频生成，因此无法覆盖：

- 模型的生成权限、余额和并发额度
- 参考图、尾帧、分辨率、宽高比和时长限制
- 自定义模型的媒体类型与调用端点
- 异步任务的轮询和结果下载

先确认项目实际使用的供应商和模型，再查看失败任务中的完整上游状态码与错误信息。

### 遇到 401/403、429 或网络超时怎么办？ {#auth-rate-limit-timeout}

- **401/403**：检查 API Key 是否有效、是否与 Base URL/区域匹配，以及账号是否开通目标模型。
- **429**：检查余额、套餐额度、RPM 和并发限制；降低对应图片、视频或语音通道的并发，等待额度窗口恢复后再试。
- **网络或超时**：从部署 ArcReel 的服务器检查 DNS、TLS、代理和 API 域名连通性。浏览器能访问不代表服务器容器可以访问。

提交生成请求后发生读超时，可能出现“上游已经创建并计费，但 ArcReel 没收到响应”的不确定状态。不要连续盲目重试，应先到供应商控制台检查是否已有任务，避免重复计费。

## 项目流程与任务 {#project-workflow-and-tasks}

### 项目模式以及分镜和参考生视频怎样选择？创建后能改吗？ {#choose-mode-and-route}

创作类型与生成模式在创建项目时确定，创建后不可更改。需要审核每个分镜的起始画面时选「分镜图生视频」；希望直接把资产图等素材交给视频模型时选「参考生视频」，并先确认所选模型支持对应输入。需要多宫格分镜时，在支持的分镜图生视频项目中开启，详见[模式选择表](./workflows.md#mode-selection-table)。

供应商没有收到预期的图片时，检查该分镜的起始图或视频单元引用的资产图，再核对[模型的生效能力](./providers.md#model-settings)。

### 源文件支持哪些格式？ {#supported-source-formats}

当前支持 `.txt`、`.md`、`.docx`、`.epub` 和 `.pdf`。上传后会统一抽取为 UTF-8 文本。

无法提取文字的扫描版 PDF 不能直接使用，需先做 OCR 识别；旧版 `.doc` 文件请先转换为 `.docx`。若 TXT/Markdown 出现乱码，请转换为常见文本编码后重新上传。

### 为什么下一阶段不能进入，或 Agent 没有继续执行？ {#stage-blocked}

先看集页的「制作状态」与失败任务。按界面的提示补齐前置条件：

1. 旁白/解说或剧情演绎先确认脚本规划。已有正式脚本可在时间线编辑。需要用新的脚本规划覆盖时，再走一次内容确认。
2. 检查脚本引用的资产及所需资产图。分镜图生视频还需可用的分镜图。
3. 等待排队或运行中的任务。任务失败时展开详情，按提示修正输入或配置。

各阶段的审核项见[标准生产阶段](./workflows.md#production-stages)。

### 任务排队、运行、失败、取消或服务重启后应该怎么办？ {#task-states}

图片、视频和语音使用独立任务通道。只有处于排队中的任务可以取消；任务一旦开始运行便无法取消，已发出的供应商调用会继续跑完并将结果照常保存为产物，避免已产生的费用白白浪费。对结果不满意时，可以在版本历史里换回旧版本，或重新生成。取消存在依赖关系的任务时，界面会提示将一并取消的排队中下游任务。

任务面板没有适用于所有任务类型的统一重试按钮。失败后先展开错误信息并修正配置或输入，再回到对应资产、分镜或视频入口重新生成。不要在原因未明时重复点击生成。

有一类失败例外：视频已在供应商侧生成成功、只是没能下载回来时，任务面板会给出「重试下载」。这个动作接续原来那笔供应商任务、只重取产物，**不会重新提交、也不再计费**，因此这类失败应当用它恢复，而不是回到生成入口重做——重做会新建一笔付费任务。

批量任务部分失败时，不需要把已成功的内容全部重做。资产、分镜和整集视频生成会按缺失项补齐，已成功结果不会因单项失败被删除。服务重启后，可安全恢复且已记录上游任务 ID 的视频任务会自动继续轮询；无法恢复的任务则会标记为失败，由你决定是否重新提交。

为避免重复计费，系统不会无条件把所有运行中任务重新入队。重新生成前先检查已有结果和供应商控制台任务。

## 画面、视频与声音 {#visuals-video-audio}

### 怎样提高角色一致性？ {#character-consistency}

1. 先生成并审核角色资产图，再批量生成分镜和视频。
2. 确认剧本中的目标分镜实际引用了该角色。
3. 修改角色资产图后，重新生成受影响的分镜和视频；旧结果不会自动更新。
4. 先用少量分镜验证所选模型的参考图能力，再扩大批量。

生成分镜时，ArcReel 会把该分镜引用的角色、场景和道具资产图作为参考；分镜图生视频的视频再以分镜图作为首帧，参考生视频则直接使用资产图。生成模型仍无法保证逐帧绝对一致。

### 怎样让相邻分镜更连贯？ {#shot-continuity}

在分镜图生视频中，非首分镜、未标记为新段落且上一张分镜已经生成时，系统会把上一张分镜作为衔接参考。它有助于延续构图、色调和场景，但不能保证两个独立生成的视频无缝拼接。

单独提交分镜图时，如果上一分镜图已经生成或正在生成，系统也会将它计入图片模型的参考图上限；超过上限时会在创建任务前提示调整参考图、设为章节切分点或更换模型。

先锁定资产和分镜再生成视频，确保相邻分镜的地点、时间、服装和出场角色描述一致。重要转场可以使用支持尾帧的模型，或在剪映等后期工具中处理。

### 首帧和尾帧怎样使用？ {#first-and-last-frame}

分镜图生视频中的分镜图就是视频首帧。每个分镜还可以选择或上传尾帧，但只有当前视频模型明确支持尾帧时才能生成；不支持时系统会拒绝请求，而不是静默忽略。更换分镜或尾帧后，已有视频不会自动更新，需要重新生成对应视频。

参考生视频没有独立尾帧设置。

### 为什么场景资产图里出现了人物？ {#people-in-scene-images}

场景资产图的提示词会要求画面中不出现人物，但图片模型仍可能不完全遵循约束。此时重新生成场景图，或使用指令式图片编辑移除人物。

场景资产图与剧情分镜图不同：场景资产图应聚焦环境，分镜图则会根据剧情显示人物。

### ArcReel 支持配音吗？ {#voice-over-support}

当前 Web UI 的独立旁白配音（TTS）仅对旁白/解说开放，可逐段试听或生成全集旁白配音，并随剪映草稿导出。旁白交付方式是项目设置：选「TTS 配音」时，项目保存自己的 TTS 模型、音色和语速，创建时以全局默认值预填，之后修改全局默认不影响已有项目；选「后期配音」时 ArcReel 不生成旁白配音，由你在剪辑时自行配音。交付方式可随时在项目设置里切换，已生成的内容不会因此过期。部分模型不支持语速调整，此时语速输入框不可用。

视频模型自带人声、角色参考音频和旁白配音（TTS）是三种不同的能力。角色声音默认采用提示词约束：把角色的声音描述写进提示词，由视频模型按描述配音，不同片段之间的音色只能大致相近。如需让视频模型直接复用角色的原声，请在项目设置中将「角色声音绑定方式」改为「参考音频」，并满足以下条件：项目使用参考生视频模式、所选视频模型支持参考音频、每个有台词的角色都已配置参考音频。分镜图生视频模式不支持参考音频。

## 费用、数据与导出 {#cost-data-export}

### 在哪里查看费用和 Token？怎样控制成本？ {#view-and-control-cost}

项目费用面板会显示图片、视频、文本和音频调用，以及预估与实际费用；设置页可按时间和供应商查看调用统计。

预估依据当前模型的价格声明和项目结构，不等于供应商最终账单。模型对应不上模型目录中的已知模型、供应商未返回 usage 或模型目录里没有适用的单价时，这次调用记为「未定价」，不计入合计。不同币种应分别核对，不要直接相加。最终金额以供应商账单为准。

建议先用少量分镜验证模型、提示词和参考图效果，再扩大批量生成；每个阶段审核通过后再进入下一阶段，避免早期资产问题扩散导致大面积返工。生成超时后先检查供应商控制台是否已有任务，不要连续重试。

不存在适用于所有项目的固定“每分钟价格”。应结合项目费用预估、实际调用明细和供应商账单评估。

### 删错了内容还能找回吗？ {#recover-deleted-content}

能。项目内的删除，无论由你还是 Agent 发起，都会成为项目回收站里的一条删除记录，保留 30 天。在工作区的「文件」里打开「项目回收站」分区，选择记录点「恢复」。恢复只新增，不覆盖现有内容；原名或原编号已被占用时，恢复的对象会换名或换编号，提示里会写明新名。

删除整个项目则进入项目列表页的「已删除项目」。各类对象怎样删除和恢复、合并资产后的恢复，以及 Agent 的删除与恢复能力，见[文件视图与项目回收站](./files-and-trash.md)。

### 项目 ZIP 与全站备份有什么区别？ {#project-zip-vs-full-backup}

项目 ZIP 用于导入、迁移单个项目，可以选择仅导出当前版本或包含完整版本历史。它不包含全局供应商设置、登录配置、任务与费用记录、Agent 会话或 Agent 记忆。图片的可用供应商素材关联随项目 ZIP 带走，导入后的使用规则见[项目 ZIP 与供应商素材关联](./asset-storage.md#asset-library-in-project-zip)。

项目回收站不包含在项目 ZIP 中，完整数据根备份会保留其中的删除记录。项目回收站的用法见[文件视图与项目回收站](./files-and-trash.md)。

删除的项目会进入项目列表页的「已删除项目」，连同它的项目回收站保留 30 天，可以整体恢复或彻底删除，详见[已删除项目](./files-and-trash.md#deleted-projects)。

导入的项目与现有项目同名时，选择「覆盖现有项目」等同于删除现有项目后再导入：现有项目排队中的任务取消，任务、使用记录与 Agent 会话按已删除项目保留，不带入导入的项目；现有项目连同 Agent 记忆进入「已删除项目」。需要同时保留两个项目时，选择「自动重命名导入」。

需要灾难恢复时，请使用前文的全站备份方式，同时保存项目目录、数据库与所需凭据。

### 剪映草稿为什么看不到，或者缺少片段？ {#jianying-draft-issues}

先确认选择了正确的剪辑时间线和剪映版本。解压后，草稿目录下应直接出现与该时间线对应的文件夹。仍然看不到草稿或无法出片时，按[剪映导出故障排查](./jianying-export.md#troubleshooting)处理。

### 有手机 App 吗？支持哪些平台？ {#mobile-app-support}

ArcReel 是自托管 Web 应用，目前没有独立的 iOS 或 Android 原生 App。手机可以尝试通过浏览器访问，但不承诺完整的移动端编辑体验。

服务器推荐 Linux、macOS、WSL2 或 Docker。Windows 原生环境只保证项目创建与基础流程，正式部署建议 WSL2 或 Docker Desktop。

### 可以商用或二次开发吗？ {#commercial-use}

ArcReel 按 [AGPL-3.0](https://github.com/ArcReel/ArcReel/blob/main/LICENSE) 发布，并附带 [NOTICE](https://github.com/ArcReel/ArcReel/blob/main/NOTICE) 中的署名和修改声明要求。ArcReel 名称与 Logo 不在 AGPL-3.0 授权范围内。

如果希望在不承担 AGPL 开源义务的前提下进行商业使用，请联系 [support@arc-reel.com](mailto:support@arc-reel.com) 了解商业授权。具体项目是否合规应由使用者根据实际分发和部署方式自行评估；本说明不构成法律意见。

## 故障诊断与求助 {#diagnostics-and-support}

### 只显示“服务器内部错误”，怎样找到真正原因？ {#internal-server-error}

前端的通用错误提示无法反映根本原因。请先展开失败任务的错误详情，再查看服务端日志与供应商返回的状态码。Docker 部署可在 Compose 目录执行：

```bash
docker compose logs arcreel
```

也可以在设置页「关于」中下载诊断日志。诊断包会尝试遮蔽系统摘要中的已知凭据，但不会在下载时对已有日志再次全文脱敏；分享前必须人工检查整个诊断包，并删除 API Key、Token、密码、完整 `.env`、私人接口地址和项目内容。

### 怎样提交一个可以有效排查的问题？ {#how-to-report-issue}

提交 [GitHub Issue](https://github.com/ArcReel/ArcReel/issues) 或寻求社区帮助时，请提供：

- ArcReel 版本
- 操作系统以及 Docker、WSL 或源码部署方式
- 失败的具体步骤和可重复操作
- 实际选择的供应商、模型与任务类型
- 错误发生时间、短错误关键词、上游状态码和任务 ID
- 已人工脱敏的相关日志

不要公开 API Key、Token、密码、完整 `.env` 或未经检查的诊断包。只有截图和“这个怎么处理”通常不足以定位问题。
