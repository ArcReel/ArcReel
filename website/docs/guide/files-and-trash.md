# 文件视图与项目回收站 {#files-and-trash}

本页说明如何在工作区浏览项目文件，项目内的删除去了哪里、怎样恢复，以及整个项目被删除后的处理。项目内的一切删除，无论由你还是 Agent 发起，都成为项目回收站中的一条删除记录，保留 30 天，期间可以恢复。

## 文件视图 {#file-view}

在工作区侧栏打开「文件」，按磁盘目录树浏览项目里的全部文件，每个文件和目录都显示大小。大目录按需展开。锁文件、迁移备份和内部元数据这类基础设施文件不显示。

选中文件可以预览图片、视频、音频和文本（含 JSON）；文件较大时不在页面中预览。任何文件都可以下载。

每个文件标有它在项目中的角色：

| 角色 | 含义 | 能否在文件视图里删除 |
| --- | --- | --- |
| 结构文件 | 项目的结构数据，如 `project.json`、剧本、脚本规划、版本历史记录、产物清单和剪辑时间线 | 否 |
| 正式文件 | 项目正在使用的文件，如分镜图、视频和资产图 | 否，可跳到所属界面处理 |
| 历史版本 | 版本历史中的一个版本 | 可以，当前版本除外 |
| 未引用文件 | 没有被项目数据、产物清单或版本历史引用的文件，如 Agent 写下的杂项文件 | 可以 |
| 派生文件 | 由其他内容派生、可以重新生成的文件，如缩略图 | 否 |
| Agent 配置 | `CLAUDE.md` 与 `.claude/` 下的 skill | 否 |
| 项目记忆 | Agent 的项目记忆 | 否，可跳到项目记忆界面编辑 |

被引用的文件可以从文件视图跳到它所属的界面（资产、分镜、集或剪辑时间线）。那里会说明删除的影响，所以修改和删除都在所属界面完成。`source/` 下还没有用上的源文件，引导你回「分集」视图处理：加入整本源文、作为一集的原文，或删除。

选中未引用文件或历史版本，点「移入项目回收站」即可删除，不再弹确认框；提示里带「恢复」按钮，可以立即反悔。多选删除时，每个文件各成一条删除记录，之后可以单独找回其中一个。当前版本的快照不提供删除。

## 删除去了哪里 {#where-deletions-go}

- 项目内容的删除不再是硬删除。删集、删资产、移除分镜、删源文件、删剪辑时间线等操作的确认框都会说明内容移入项目回收站、保留 30 天。
- 重新生成或编辑产生的旧版本留在版本历史里，不进项目回收站。项目回收站里只有被主动删除的内容。
- 项目回收站在工作区「文件」的「项目回收站」分区。每条删除记录显示对象、删除时间、发起方（你或 Agent）和占用空间。对象按类型显示名称，例如「集『标题』」「源文件『文件名』」「第 N 集的规划草稿」「角色『名称』」；文件类记录显示路径。分镜、视频单元和尾帧按删除时的位置与正文开头显示，例如「分镜 标题 · 5：正文开头…」，同一集删掉的多条记录据此区分。
- 项目回收站不属于项目内容：不出现在文件目录树里，不包含在项目 ZIP 中。

## 各类对象的删除与恢复 {#objects}

### 恢复的通用规则 {#restore-rules}

- 恢复只新增：被恢复的对象作为新内容加回，不覆盖现有内容，也不与现有内容合并。原名称或编号已被占用时，以新名称或新编号加回。少数放不回去的情况见本节下文。
- 原名或原编号空闲时沿用；已被占用时换名或换编号。分镜与视频单元例外，一律换新编号。换了的名字或编号会在恢复后的提示里写明。
- 恢复的产物照常判定时效：删除之后它的输入变过的，显示为过期（stale），需要重新生成。
- 刚恢复的内容可以再删一次，重新进入项目回收站。
- 同一条删除记录同时被恢复多次时只生效一次，后到的请求会提示记录已不存在。
- 没有空出的位置放回对象时，这次什么都不恢复，删除记录仍保留。腾出位置后重试，或下载记录中的文件。
- 升级 ArcReel 之前产生的删除记录，升级后同样可以恢复。

### 文件与历史版本 {#files-and-versions}

删除未引用文件或历史版本后，原路径空闲就回到原路径。原路径已有该资源的当前文件时，恢复的文件作为该资源的历史版本加回，不覆盖当前版本；其他情况下以 `名称 (n)` 的新文件名恢复。历史版本恢复后重新登记进该资源的版本历史，保留提示词，版本号重新分配。

### 集 {#episodes}

在集页或「分集」视图选择「移入项目回收站」。集原文、剧本、脚本规划、剪辑时间线与成片、宫格、各分镜与视频单元的媒体和版本历史，一起成为一条删除记录。重新规划采纳新方案时选择「一并删除」退下的集，同样如此。

恢复的集沿用原集 ID，排在播出顺序末尾。它一律作为自带原文的集恢复，删除前的集原文成为这一集的源文：原本切自整本源文的那段原文保持未切分，不会和之后重新规划出的集争抢原文范围。

### 资产与衍生 {#assets}

在资产卡片的菜单里选「删除」。资产图、原图、参考音频、版本历史和名下的衍生一起成为一条删除记录。单独删除角色的某个衍生，则只记这个衍生。

恢复资产时：

- 原名空闲就沿用原名。名字不区分大小写，也不区分资产类型；旧版本留在盘上的同名图或版本历史同样算占用。
- 原名已被占用，例如删除后又新建了同名资产，就以 `名称 (n)` 恢复。资产图、版本历史和衍生随之改名，现有资产不受影响，之后可以再把它并入现有资产。
- 剧本里的引用在删除时没有被改写，所以原名恢复后，原有的引用自动接上。换名恢复的资产不会接管这些引用，它们仍指向现有的同名资产。

新建与回收站里某条记录同名的资产时，界面会提示可以从项目回收站找回之前的资产图。

单独删除的衍生要求本体还在。本体也在项目回收站里时，先恢复本体，再恢复衍生；本体已彻底删除时只恢复其中的文件。

### 合并资产后的恢复 {#after-merge}

合并时，各集脚本规划、正式脚本、草稿和提示词正文里对被并资产的引用已经改指保留资产。被并资产的描述、资产图及版本历史、声音设置、原图和参考音频，则作为一条删除记录移入项目回收站。

恢复被并资产时，系统只做新增：

- 被并资产回到项目里，原名空闲则沿用，已被占用则以 `名称 (n)` 恢复。
- 已改指保留资产的引用不会改回，恢复后仍指向保留资产。需要用回被并资产时，在对应位置手动改回。
- 合并时迁到保留角色名下的衍生留在保留角色名下，不随被并角色回来。
- 保留资产不受影响。

### 分镜与视频单元 {#entries}

在分镜详情或参考生视频工作台选择移除，该分镜或视频单元连同它的分镜图、尾帧、视频、配音、缩略图、字幕、呈现和版本历史一起成为一条删除记录。没有任何媒体的条目也会成为记录。

内容确认或整份重新生成覆盖正式脚本时，旧脚本里的条目同样成为删除记录。

恢复的条目回到原来的集，插在原来的前一个条目之后；原来排在最前就插回最前，前一个条目已不在时放到集末尾。同一批移除了相邻的多个条目时，按原顺序依次恢复，位置最接近删除前。

分镜与视频单元的编号只分配、不复用，恢复的条目一律换新编号，原编号空闲也不沿用：剪辑时间线里引用原编号的片段仍显示为已删除，不会把旧裁切套到恢复回来的条目上。媒体与版本历史随新编号加回，分镜图、视频与配音按恢复后的条目照常判定时效；字幕和呈现这类派生文件不加回，需要时重新生成。恢复的分镜不再属于原来的宫格，按普通分镜规划。

### 宫格、尾帧与参考音频 {#grids-end-frames-audio}

- 宫格：重新生成宫格时退下的旧宫格成为删除记录，包含宫格记录、联合图和版本历史。原宫格 ID 空闲时整体加回。
- 尾帧：清除分镜的尾帧时，尾帧图成为删除记录。原位置空闲则回原位，被占用则换新文件名。分镜此刻没有可用尾帧时，恢复的尾帧重新设为它的尾帧；否则作为未引用文件留在项目里。
- 参考音频：在角色的声音设置里删除参考音频，或换成不同扩展名的音频时，旧文件成为删除记录。原位置空闲则回原位，角色此刻没有可用参考音频时，恢复的文件重新设为它的参考音频。原位置被占用时换新文件名，作为未引用文件留在项目里。

所属的集、分镜或角色已不存在时，这三类记录降级为只恢复文件，见[无法按原结构恢复](#degraded)。

### 源文件与规划草稿 {#sources-and-drafts}

- 源文件：在「分集」视图删除源文件，或上传同名文件替换旧文件时，源文本和它的原始上传件一起成为一条删除记录。恢复的源文件一律是未纳入整本源文的源文件，由你在「分集」视图决定加入整本源文、作为一集的原文，或删除，恢复不会擅自改动集原文的切分。原路径被占用时，源文件与原始上传件一起改名为 `名称 (n)`。
- 规划草稿：丢弃待修复或可编辑的草稿、丢弃未确认的脚本规划、选择「从空白开始」时，被丢弃的草稿成为删除记录。恢复要求所属的集还在。原路径空闲就回原位，脚本规划的产物登记一并补回；原路径已有文件时以 `名称 (n)` 恢复，作为未引用文件，不带登记。

### 剪辑时间线 {#edit-timelines}

删除剪辑时间线时，它的全部修订、已渲染的成片和导出的剪映草稿一起成为一条删除记录。恢复时原 ID 空闲就沿用，成片和草稿的登记一并补回，输入此后变过的显示为过期。显示名在同一集内已被其他剪辑时间线占用时，恢复的那条在名字后加编号。

### 项目记忆与 Agent 配置 {#memory-and-profile}

- 删除项目记忆文件或清空记忆时，内容成为删除记录；清空时所有记忆文件合成一条。
- 重置 Agent 配置时，被覆盖的定制文件和项目独有的 skill 合成一条删除记录。与内置配置一致的文件不进记录。

两者恢复时，原位置空闲就回原位，已有文件则以 `名称 (n)` 的新文件名恢复。

### 生成完成时目标已删除 {#target-deleted-during-generation}

生成任务完成时，如果它的目标（资产、分镜、视频单元等）已在生成期间被删除，生成结果不会写回项目，也不会让已删除的对象重新出现。结果文件成为项目回收站里的一条删除记录，说明为「生成完成，目标已删除」；任务按成功计，费用照常计入。界面会弹出提示，说明结果已移入项目回收站，可在「文件」视图中找回；资产图批量生成的汇总里，这类结果单独计数。

恢复这条记录时，文件回到原路径；原路径已有该资源的当前文件时，作为历史版本加回。目标本身也在项目回收站里时，先恢复目标，再恢复这条记录。

## 无法按原结构恢复 {#degraded}

出现以下情况时，恢复降级为只恢复文件：

- 记录来自较早的版本，在升级流程中无法处理。
- 对象所依附的上级已不存在，例如衍生的本体、宫格所属的集、参考音频所属的角色。

降级时，其中的媒体等文件按原路径加回，提示会写明找回了几个文件。剧本、剪辑时间线这类结构文件留在这条删除记录里，只能下载。这类记录不再有「恢复」按钮，之后只能逐个下载其中的文件。

分镜、视频单元、剪辑时间线和宫格所属的集，或衍生的本体，还在项目回收站里时，不会降级：恢复会提示先恢复这一集或这个角色，记录原样保留。先恢复它们，再恢复这条记录，即可按原结构恢复。

恢复途中遇到磁盘空间不足、没有权限这类读写错误时，同样不会降级：本次恢复失败，记录原样保留，排除问题后重试即可。

## 保留期、彻底删除与清空 {#retention-and-purge}

删除记录保留 30 天，从删除时间起算，到期后自动清除。清除在应用启动时进行，运行期间也会定期进行。需要保留项目回收站里的文件时，应在到期前恢复。

在「项目回收站」分区可以彻底删除单条记录，或清空项目回收站。两者都不可恢复，需要二次确认，并且只能由你在界面上执行。

项目回收站存放在项目目录的 `.arcreel/trash/` 下。完整数据根备份会保留其中的删除记录，项目 ZIP 导出不包含。恢复备份不会重置记录的保留期，详见[持久化目录](../ops/deployment.md#sqlite-volumes)。

## 已删除项目 {#deleted-projects}

删除整个项目时，项目移入项目列表页的「已删除项目」，连同它自己的项目回收站保留 30 天，排队中的任务随之取消。用归档覆盖现有项目时，被覆盖的旧项目同样进入「已删除项目」。

在项目列表页顶栏的「已删除项目」中，可以整体恢复项目，项目回到删除前的样子；也可以彻底删除，需要二次确认。恢复时原名已被新项目占用，项目会以加后缀的新名字恢复。到期后自动清除。

## Agent 的删除与恢复 {#agent}

- Agent 不能直接删除或覆盖媒体文件和版本历史。Agent 不能用写入、编辑或 Shell 命令修改这些目录，只能经项目回收站删除。
- 你明确要求删除某个未引用文件或非当前的历史版本时，Agent 可以把它移入项目回收站。被引用的文件会被拒绝，Agent 会请你到所属界面处理。
- Agent 自己的结构操作同样进项目回收站：移除分镜或视频单元、覆盖正式剧本、合并资产、替换源文件、丢弃草稿。这些记录的发起方显示为 Agent。
- 对话时可以让 Agent 列出删除记录，与你确认是哪一条后恢复。恢复的结果会写明对象是否换了名或换了编号，是否降级，以及哪些文件只能下载。
- 彻底删除和清空项目回收站只能由你在界面上执行，Agent 没有这两项能力。
