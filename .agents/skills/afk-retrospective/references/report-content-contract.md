# 报告内容契约

team-lead 根据 evaluator 简报编写最终报告。正文使用中文 Markdown；关系、流程或时序比短文更清楚时使用 fenced Mermaid。固定的是读者必须获得的信息，不是标题或布局。

## 推荐强度

- `强烈建议`：触发路径已验证，收益明确，改动范围可控，没有未决的产品取舍。
- `值得探索`：问题或摩擦真实，但方案、成本或责任归属仍需设计。
- `推测性`：方向合理，但关键触发路径或收益尚未充分验证。正文明确缺失证据。
- `无需处理`：已覆盖、重复、收益不足，或知识更新已完整替代工程改动。正文明确原因。

推荐强度表达处理建议，不同时承担严重程度、紧急度或证据置信度。需要这些信息时在正文中分别说明。

## 工程候选

每篇正文都让用户无需打开来源即可回答“是否值得继续处理”，并覆盖：

- 当前路径与问题；
- 可复查证据；
- 预期行为改变；
- 受影响者、触发条件和结果；
- 实施范围、回归风险与未知项；
- 推荐强度的理由；
- evaluator 的实质分歧。

## 知识候选

知识候选使用统一的建议动作；动作描述要做什么，推荐强度描述是否值得优先做，两者正交：

- `create`：新增知识；
- `revise`：修订现有知识，身份保持不变；
- `retire`：现有知识不再成立；
- `supersede`：用新的知识实体取代旧实体，仅 ADR 支持；
- `none`：无需知识维护，且推荐强度必须为 `无需处理`。

CONTEXT 与 agent instructions 是当前态文档，支持 `create / revise / retire / none`。ADR 保留历史，支持全部动作：`revise` 保持核心决策不变，`retire` 把旧决策标为 `deprecated`，`supersede` 新建 ADR 并把旧 ADR 标为 `superseded by ADR-NNNN`。ADR 文件自身的 `proposed / accepted / deprecated / superseded` 是生命周期状态，不写入报告的 `action`。

每篇正文覆盖当前知识缺口、现有材料为何不足、建议动作及内容，以及不处理会造成的重复返工。`revise / retire / supersede` 必须用 `target_ref` 指向现有载体；`create / none` 省略它。动作和推荐强度由 team-lead 根据全部调查结果决定。

## 待裁决项

每篇正文解释 team-lead 无法自行决定的原因，以及各选项共享的背景。结构化选项分别说明改变、收益、代价与不可逆部分；选项之间互斥。

## 批次概览

概览展示结构化 Issue 结果。有可行动的工程或知识候选时，选择一个 Top recommendation 并用一句话说明为什么先处理它。
