# 模型选择

每个阶段启动前显式选择模型，并记录实际模型名与一句选择理由。角色目标是规范；下面的模型名是默认偏好，不是启动前置条件。某个别名不可用时，直接选择满足同一角色目标的可用模型，不建立固定 fallback 表。

## 实现

按 issue 的改动范围、跨模块程度、歧义与风险，从 `fable` / `opus` / `sonnet` 中选择。批次计划必须展示每个 issue 的实际选择与理由，用户确认后沿用；替补接管时保持原选择，除非账本另有裁决。

## 本地审查

选择擅长独立推理与代码审查的强模型；默认偏好 `opus`。本阶段必须由未参与实现的干净上下文承担，模型选择不得破坏该隔离。委派时把实际模型名与理由 append 到账本 `decision`。

## AI 审查循环

在 PR、diff 与前两段 handoff 已具备后，按实际复杂度选择模型。把实际模型名与理由 append 到账本 `decision`，再启动负责循环的 agent。
