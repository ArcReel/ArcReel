# Coding Standards

ArcReel's coding standards are project conventions that require judgment when reviewing a diff and cannot be replaced by tools. They prevent repeated AI mistakes. The body is split by domain under `docs/standards/`.

## Usage

1. List changed file paths in the diff, consult the table below, and read every matching standard. Do not read unmatched standards.
2. In each standard, a level-three heading is the rule itself; the body explains the reason, consequences of violations, and exceptions. Report violations with the file and rule heading.
3. Requirements already enforced by lint, type checking, `scripts/audit_tests.py`, or `scripts/audit_conventions.py` are not repeated in the standards or reported again during review.

## Maintenance

Submit mistakes that warrant improving the environment as lesson candidates during the closing self-check. The sweep records them in `docs/LESSONS.md` and promotes them when thresholds are reached. Recording, counting, promotion, and retirement rules are in [`docs/agents/lessons.md`](docs/agents/lessons.md). Use these criteria when adding, changing, or deleting rules:

- **Where it belongs**: use the classifications in [retro](.agents/skills/retro/SKILL.md). Mechanically decidable requirements belong in lint rules, tests, or checks in `scripts/audit_conventions.py`. Distinguish implementation-time and review-time knowledge by rework cost: knowledge with high rework cost if misapplied (choosing the wrong layer or structure, such as serializing session calls through SessionActor, refreshing after writes through `refreshAfterWrite`, or integrating editable content with `useEditUnit`) belongs in architecture or reference documentation, reached through navigation pointers during implementation. Requirements with low rework cost belong in review standards.
- **Whether it should exist**: apply a counterfactual test. A rule is justified only if removing it would cause reviewers to miss a class of real, recurring problems.
- **How to split**: split files only when their applicable paths differ substantially. The sole benefit of splitting is that reviewers read only the files matching their changes.

Applicable paths come from each file's `paths` frontmatter. The table above and path mappings in `.coderabbit.yaml` are generated by `uv run python scripts/audit_conventions.py --fix`; CI checks that they match the frontmatter.
