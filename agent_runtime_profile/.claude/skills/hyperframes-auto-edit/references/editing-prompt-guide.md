# ArcReel HyperFrames Editing Prompt Guide

本参考把 ArcReel 剧本展开成可执行剪辑计划。它是默认决策方法，不得覆盖用户明确 Instruction、正式剧本文案、媒体真实时长或 HyperFrames 技术合同。

## 六段式结构

`Route → Spec → Beats → Copy → Technique → Negatives`

- Route：根据成片而不是关键词选工作流语义。剧情/品牌叙事用 `general-video`；旁白解说和课程用 `faceless-explainer`；真人口播素材用 `talking-head-recut`；短促无旁白动效才用 `motion-graphics`。
- Spec：写明真实总时长、画布宽高、横竖屏、声音版本和素材范围。
- Beats：每拍写起止秒、概念、情绪、BG/MG/FG 层次、对象动作和转出方式；所有拍连续覆盖整集。
- Copy：只使用正式剧本或字幕原文；需要标题时从原文提炼短语，不改变事实和台词。
- Technique：明确 hard cut / trim / splice / blur crossfade / push / Ken Burns / punch-in 等动作及持续时间；不能只写“更高级”“动一下”。
- Negatives：写明不允许的旁白、库存素材、外部 URL、额外角色、花哨转场、文案改写等。

## 每拍五要素

每个主要元素都回答：它是什么、做什么动作、在哪里、长什么样、什么时候发生。用户只给了种子要求时，补充氛围层、次级运动、微细节、对象级转场和镜内呼吸点，但不能新增剧情事实。

## 按剧本类型选择节奏

### 叙事 / 品牌 / 广告

价值在前，证据在后：`hook → value → evidence → peak → breathe → CTA`。第一拍直接给观看理由，英雄镜头只在峰值使用强转场，其余保持克制。

### 旁白解说

声音是时间之主。每句或每个语义段对应一拍；关键词可比声音早约 50ms，画面不能晚于旁白。字幕与正式时间戳对齐，镜头运动不能抢台词。

### 课程 / 教学

优先可理解性：`goal → concept → example/demo → summary → practice`。章节切换明确、信息密度稳定、动画服务解释。讲解主体一般不铺持续音乐；若用户要求音乐，保持更低存在感。

### 真人口播

A-roll 是主场：先清理停顿和重复，再按语义加入 B-roll/PiP，最后加字幕、音乐和装饰。论点和转折回到人脸，不让字幕遮脸。

## 用户 Instruction 合并规则

把用户原文逐条放进 `User Overrides`，再把它落实到对应的 Spec / Beat / Copy / Technique / Music / Negative 项。不要只在计划顶部复述却不改变时间线。

- “快一点”：缩短具体拍段或转场，不能让媒体越界。
- “保持顺序”：不重排视频单元，只优化镜内节奏与转场。
- “不要字幕/音乐”：删除对应计划，不做“默认补全”。
- 指定文案：只有用户明确授权时才替换正式 copy，并把替换标为用户覆盖。
- 指定某秒修改：使用 composition 全局时间，关联到真实 source range。

## 音乐方向

需要 BGM 时从剧本提取：类型、情绪起点、情绪峰值、结尾状态、速度感/BPM、主乐器、避免的风格。始终要求一条连续的纯器乐背景配乐，无演唱、说唱、对白、合唱、哼唱或人声采样；不要为每个镜头生成不同歌曲。

默认混音基线是 15%（`data-volume="0.150"`）。旁白存在时音乐必须让位于人声；淡入、淡出或 duck 只能向下自动化，不能超过 15%。

## 质量检查

- 每个 Beat 有明确的时间范围，总和与真实成片时长一致。
- 每个主要元素有具体动作动词，环境装饰有轻微次级运动。
- 强转场数量克制，普通段优先 hard cut 或短 crossfade。
- 没有外部媒体 URL、随机/墙钟动画、重复元素 id 或视频原生音轨重复播放。
- 用户 Instruction 在计划和最终 HTML 中都有可见落实。
