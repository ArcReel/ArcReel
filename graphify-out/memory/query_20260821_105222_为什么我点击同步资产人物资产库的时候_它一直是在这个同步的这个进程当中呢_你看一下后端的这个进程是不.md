# Q: 为什么我点击同步资产人物资产库的时候，它一直是在这个同步的这个进程当中呢？你看一下后端的这个进程是不是真实的还在进行当中，还是只是前端展示的问题？

## Answer

Expanded from the original query via graph vocabulary: [background, job, worker, sync, status, progress, poll, asset, catalog]. The durable backend job completed successfully at progress 12/12, but the browser continued polling once per second. Root cause: enqueue serializes an in-memory timezone-aware UTC updated_at with +00:00, while SQLite reloads DateTime(timezone=True) as a naive datetime and status serialization omits the timezone. In Asia/Shanghai, Date.parse treats the naive terminal timestamp as local time, approximately eight hours older than the queued timestamp, so the Zustand stale-response guard rejects every succeeded response and retains running forever. Relevant nodes: BackgroundJobWorker, BackgroundJobRepository, sync_catalog_status(), CharacterCatalogSyncMonitor, sync_character_catalog().
