# 后端保留核心库和服务端，按领域拆分子包

后端继续保留 `lib/` 和 `server/` 两个顶层目录，以及 `server.app:app` 启动入口。核心库按领域组织，纯技术支撑放在 `lib/infra/`。服务端保留 HTTP、Agent、MCP 等交付边界和应用编排。即使某段领域逻辑目前只被单个入口调用，仍按职责归属核心库。

曾考虑让各领域同时持有核心、路由和 Agent 工具。HTTP、Agent、MCP 和生成 worker 共享领域逻辑，垂直切片会把 Agent 注册、权限和会话上下文分散到各领域。两个根保留了可检验的依赖边界，同时避免重改部署启动契约。

分包表达领域归属。已有的模块依赖环保留在实际导入契约中，路径迁移本身无法消除依赖环。目录命名与拦截规则见 [架构概览](../../website/docs/dev/architecture.md) 和 [导入契约](../../pyproject.toml)。
