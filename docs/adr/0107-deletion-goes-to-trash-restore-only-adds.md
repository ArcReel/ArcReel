# 删除一律进回收站，恢复只新增，删除记录借迁移链跨版本恢复

项目内的删除过去都是硬删除；只有结构移除按 `docs/adr/0003` 把媒体留在盘上成为未引用文件，`docs/adr/0080` 为项目回收站预留了位置。决定：删除分两层，项目整体删除成为已删除项目、整体恢复，项目内的每次删除成为项目回收站中的一条删除记录，两层都保留 30 天。恢复只新增、不覆盖、不阻塞：被恢复的对象作为新内容加回，原身份空闲则沿用、被占用则换新身份，不与现有内容合并，也不因冲突拒绝。删除记录除被删文件外，还带一份删除前项目结构文件（`project.json`、剧本、规划草稿、版本历史、产物清单、剪辑时间线、源文文本）的快照；恢复一律走同一条流水线：把快照与被删文件在临时目录铺成项目，跑归档导入所用的迁移链（schema 相同时为空操作），取出对象，按落地规则加回当前项目，再补录。项目 schema 几乎每个发行版都变，这样删除记录跨版本仍能恢复，迁移步也不需要知道回收站存在。

## 落地规则

| 被删对象 | 恢复后 |
| --- | --- |
| 集 | 沿用原集 ID（集 ID 不复用，见 `docs/adr/0096`），一律作为自带原文的集，删除前的集原文成为该集源文，排在播出顺序末尾；剧本、规划草稿、剪辑时间线与媒体一起加回 |
| 资产（含衍生） | 原名空闲则沿用，剧本里仍指向该名的引用自然接上；被占用则加后缀，可再走资产合并 |
| 分镜条目、视频单元 | 回到原集，插在原前驱之后，前驱已不在则放到集末尾；原 id 被占用则发新 id；所属集也已删除时只能随集恢复 |
| 整本源文中的文件 | 作为未纳入整本源文的源文件，由创作者决定是否接回 |
| 剪辑时间线 | 名字被占用则加后缀 |
| 历史版本、未引用文件 | 回到原路径；原路径已有文件时作为该资源的历史版本加回，不覆盖当前版本 |

## Considered Options

- **把领域对象恢复回原位**：每类对象各要一套冲突规则（集原文范围已被重新规划占用、资产已同名重建、剧本已被多轮修改），恢复结果可能比删除前更乱。
- **只回收文件，结构文件只能下载**：结构删除实际找不回来，回收站形同虚设。
- **原地软删除**：迁移会顺带升级被删对象，但每条读取路径都要过滤，被删对象还继续占着资产名与整本源文的范围。
- **删除记录只存摘下的结构片段**：跨过 schema 升级后，要么降级为只恢复文件，要么每个迁移步都要额外改写片段这种半截形状；迁移链只能处理完整项目。
- **回收站自定一套与版本无关的格式**：等于另造一套与项目 schema 同步演进的序列化。

## Consequences

- 被删的集即使原本切自整本源文，恢复后也不再占用整本源文，原范围留作未切分的原文。
- `docs/adr/0003`「结构 remove 只移除剧本引用，项目内已有文件继续保留」由本 ADR 取代：结构移除连带的媒体与版本进项目回收站。资产删除不再把资产图与版本历史留在原位，同名重建时提示可从回收站找回。重插新条目与覆盖正式剧本时清掉的媒体、Agent 运行 profile 重置覆盖的定制、源文件、规划草稿、剪辑时间线、宫格、尾帧、参考视频单元、参考音频与项目记忆的删除同样进回收站。
- 被覆盖产生的旧版本留在版本历史，不进回收站；删除某个版本才进。
- 删除记录以整条为单位恢复与彻底删除。未引用文件与历史版本的删除没有结构关系，不带快照。
- 恢复只把取出的对象加回当前项目，临时项目迁移得出的项目级状态（如集 ID 高水位）不带回。临时项目迁移失败时降级为只恢复文件：媒体回到原路径或作为历史版本加回，结构文件只能下载。
- 项目回收站放在项目私有区，不随项目归档导出；已删除项目放在数据根下，连同它自己的项目回收站。
- Agent 不再能直接写媒体目录与 `versions/`（Agent 沙箱与工具钩子同步收紧），只能经走回收站的删除工具删除；Agent 可以列出与恢复删除记录，清空与彻底删除只开放给创作者。
- 资产库、用户记忆不在本 ADR 范围内；删除时正在执行的生成任务沿用现有处理。
