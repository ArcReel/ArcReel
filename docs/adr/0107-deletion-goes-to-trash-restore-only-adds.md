# 删除可恢复，恢复只新增，并复用项目迁移链

项目内容删除进入项目回收站，整个项目删除后成为已删除项目。恢复只新增，不覆盖或合并当前内容。原身份空闲时可沿用，被占用则分配新身份。分镜和视频单元总分配新编号，避免旧剪辑片段把以前的裁切应用在恢复出来的新身份上，见 [ADR 0090](0090-edit-timeline-named-follows-current-not-artifact.md)。切出集恢复为自带原文的集，原文范围继续由当前分集账本管理。

删除记录保有可供迁移的项目结构快照，恢复时经项目迁移链升级，再从中取出要恢复的对象。如果单独保存结构碎片，每个迁移步都必须同时维护两套格式；而采用原地软删除又会让已删对象继续占用名称与源文范围，并迫使所有读取入口都做过滤。

主动删除分镜或视频单元仍保存带结构快照的删除记录并直接恢复；首次确认生成正式脚本不写入项目回收站。重做覆盖已有正式脚本时，不逐条复制项目结构快照，而是按此次覆盖存一条仅下载记录，保存覆盖前的正式脚本及实际移除的当前与历史素材，供按原路径逐文件辨认并下载，其中的分镜图和视频可在创作界面选定目标后手动上传复用，不会自动装回旧条目或原有关系。单个资源重新生成或编辑产生的旧版本留在版本历史。Agent 通过项目回收站删除项目内容，清空与彻底删除由创作者执行。远端可恢复版本的引用规则见 [ADR 0118](0118-formal-objects-retained-by-holder-references-and-collected-in-one-place.md)。

## 结构恢复降级与可重试保留

带结构快照的删除记录经 [恢复流水线](../../lib/project/trash_restore.py) 的 `restore_structural` 在临时项目中完成恢复。降级仅发生在源文编码迁移、项目迁移链升级与对象提取规则三个阶段，铺设临时目录与最终加回落地不走降级；落地在领域锁与项目锁内复核记录未变化，失败时撤销本次新建的文件并原样保留记录。

- 提取规则抛出 `RestoreBlocked`（如所属集仍在回收站）时直接传播，不降级且保留记录，待前置条件恢复后重试。
- `FileNotFoundError` 之外的 `OSError`（如磁盘满或权限故障）属于可排除后重试的读写故障，直接传播且保留记录，避免降级消耗记录导致结构丢失。
- 其余异常（含永久性的 `FileNotFoundError`）发生时：若记录不含独立文件（`record.files` 为空），降级无法加回任何内容，直接报冲突并保留记录不消耗；若存在被删文件，则降级为仅恢复暂存树中合格的非结构文件，原记录中的结构文件转为仅下载留存，不含结构文件时消耗记录。

## 项目退役期间阻止旧任务向同名目录落盘

由于执行中的生成任务不被取消（见 [ADR 0006](0006-cancel-only-queued-tasks.md)），整项目删除或覆盖导入替换现有项目时，旧任务可能在项目目录移走或同名新项目装入后继续落盘。退役流程在单服务进程内通过 [项目退役](../../server/services/project/project_retirement.py) 与 [任务项目认领](../../lib/project/task_project_claim.py) 阻断这类错位写入：

- `retiring_project` 在将目录移成已删除项目前，按任务 ID 作废该项目的运行中任务认领，覆盖任务已被认领但尚未进入执行上下文的窗口；作废标记在任务退出认领上下文时移除。
- `ensure_task_project_claim` 仅在当前任务上下文操作自身认领且已作废的项目时阻止落盘，不影响其他项目操作，也不取消已发出的上游供应商请求。
- 若退役过程或事务提交失败，回滚数据库事务并恢复这些任务的认领；恢复前已经观测到作废并放弃落盘的任务不会重放。
