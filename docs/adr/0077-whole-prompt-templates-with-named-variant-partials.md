# 提示词按生成环节保存完整模板，用命名片段表达变体

每个环节提供一份能直接阅读的完整提示词模板，共享措辞抽取为片段，因源文件类型、资产类型或创作类型带来的措辞差异则通过命名变体选择。原先散落在常量、字符串拼接与注册表中的提示词难以审校，多个调用方也会重复写画风和排除项。实体模板使设置页可展示实际内容，维护者可以定位一个环节的完整指令。

内置模板随核心库分发，模板目录是渲染器的构造依赖。这样服务端可直接读取随包内容，也能在测试中使用独立目录。创作 Agent 的配置源会由 SDK 按文本加载，负责不同的运行时职责。

- 措辞差异写命名变体，取值计算留在代码。正文只可按槽位有无决定可选内容。用模式比较生成布尔槽位会把同样的分支藏在模板之外，设置页仍无法枚举各模板变体。
- 变体族按声明在加载时校验完整性。允许显式空文件表达某一变体无内容。片段名使用字面量，列表循环留在列表片段，让加载器能提前发现缺失引用。
- 槽位保持明确的数据形状。可缺失的值保留键并传空值，缺键显式失败，避免措辞编辑时悄悄丢掉项目数据。两处以上共享的措辞才抽取片段，少量专用措辞保留在环节正文。
- 支持纯文本回贴的模板可显式启用幂等去重。它只用于完整行的包装内容，行内措辞和列表数据不参与去重。模板包装变更不追溯影响产物时效，见 [ADR 0070](0070-prompt-forms-and-single-rendering-exit.md)。

具体执行和限制由[模板引擎](../../lib/prompts/prompt_templates/engine.py)持有。模型消费的模板正文和片段不按界面语言维护。
