# GenerationContext consolidates generation-task provider resolution: resolve once and use actual backend identity

Execution configuration (ProviderModel per media lane, resolution tiers, supported_durations, and other capability limits) derives from one provider resolution, but execution lacked an interface carrying it: `get_media_generator` resolved internally and returned only MediaGenerator, discarding results. Consumers retrieved them separately: image/video tasks opened another ConfigResolver session after obtaining generators, risking backend A with resolution B after configuration changes. Failed second video resolutions silently fell back to hardcoded provider/model pairs. Reference-video tasks read private `generator._video_backend`, manually split `project["video_backend"]` to reconstruct registry provider_id, and defended against capability/backend model mismatches (disabled custom-provider target models silently fall back in `load_custom_backend`, making intended-model capabilities wrong). Interfaces used `require_image_backend` / `needs_i2i` / `needs_audio` flags and resolved another lane regardless of declaration, so image-only projects' image tasks failed on missing video configuration.

Consolidate a deep module: `server/services/tasks/generation_context.py` exposes only `resolve_generation_context(project_name, payload, *, project, user_id, image=, video=, audio=)`, returning immutable `GenerationContext`. ① **Resolve once**: one ConfigResolver session resolves/constructs every declared lane, returning `generator` plus lane result values, without consumer re-resolution. ② **Named lane declarations**: supplying `ImageLaneRequest(capability=...)` / `VideoLaneRequest()` / `AudioLaneRequest()` declares lanes; tasks pay configuration/construction costs only for used lanes. Property access to undeclared lanes fails loudly, without Optional types. ③ **Use actual identity**: each lane resolves ProviderModel → constructs through `assemble_backend` (`docs/adr/0039`) → looks up resolution/capabilities by **canonical `provider_id` and actual backend `.model`**. Keys are `(provider_model.provider_id, backend.model)`, not `backend.name`: providers do not drift in assembly, and family aliases reusing Ark report family `backend.name` as `ark`; `backend.name` is a family name, not a registry key. Models alone drift through disabled-target custom-loader fallback, requiring actual `.model`. Structural elimination of intended/actual mismatch removes consumer defenses. Results expose both `provider_model` (canonical registry identity) and `backend_name` / `backend_model` (reported actual identity) string groups, without backend instances. ④ **Errors**: lane resolution/construction errors propagate unchanged, failing whole calls without partial results or silent cross-provider fallback; only capability-lookup failures admit empty values (`docs/adr/0002`). Preserve None resolution as omitted SDK parameters (`docs/adr/0019`); video additionally offers `resolution_or_fallback` for nonempty requirements. ⑤ **Audio carries narration voice/speed**: ConfigResolver retains logic, delegated within the same session without second audio sessions. ⑥ Remove public `resolution_resolver.py`: DB priority chains (project overrides > legacy > custom-provider defaults) join `ConfigResolver.resolve_resolution()`; pure lookup `get_provider_fallback` becomes public module-level `lib/config/resolver.py`.

**Explicitly rejected**: ① **Deepening MediaGenerator to carry resolution results**: generating and choosing providers are separate concerns; combine them through thin outer values instead of a grab bag. ② **Three injection Ports for ConfigResolver / ProjectManager / construction**: the first two are locally substitutable through real in-memory DB/tmp_path tests without mocks; only construction is an external seam, already adapted by `assemble_backend`. One-production-implementation Ports are imaginary seams. ③ **Partial success**: incomplete contexts after declared-lane failures disguise configuration errors. ④ **Atomic failure for capability lookup too**: metadata absence does not mean selected providers/models are uncallable and would regress `docs/adr/0002`'s no-worse semantics. ⑤ **Hardcoded resolution-failure fallbacks**: these existed only because second resolution could fail after construction. Single resolution removes that premise; retaining them silently runs unrelated providers and incurs costs/content despite explicit choices.

## Consequences

- **One consumer call supplies everything**: remove generator-plus-re-resolution/private-access/manual-split paths at generation_tasks' five sites (storyboard/character/design/grid/video), reference_video_tasks, and resume_executor. Remove dead reference-video capability-consistency defenses.
- **Behavior changes**: image tasks no longer need video configuration and vice versa; failed video resolution fails observably instead of silently substituting hardcoded models. Persist grid model metadata from actual backend `.model` (provider remains canonical `provider_id`), possibly differing from intended models during custom fallback.
- **Unchanged boundaries**: resolution remains execution-only (`docs/adr/0001`); payload > project > global precedence stays; `_backend_cache` remains server-execution responsibility ("Keep caches with callers" in `docs/adr/0039`), moving with the module and retaining invalidation entries for provider-change routes.
- **Consolidated tests**: consumer tests replace only `resolve_generation_context`, assembling fake contexts as frozen dataclasses. Module tests use real test DB + tmp_path + fake backends through interfaces without private-property assertions; retire multi-file resolve/backend monkeypatch assemblies.
- **cost_estimation is not a consumer**: estimates resolve without construction. Call `ConfigResolver.resolve_image_backend / resolve_video_backend` directly to remove duplicated priority resolution, preserving unknown display after failures.
- **Terminology recorded**: module/class docstrings in `server/services/tasks/generation_context.py` own `GenerationContext` and image/video/audio lane-result semantics; glossaries contain only product concepts, not internal types.
- `docs/adr/0086` supersedes video fallback resolution and empty-duration admission.
