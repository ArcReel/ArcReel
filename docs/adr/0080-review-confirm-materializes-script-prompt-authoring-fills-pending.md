# 脚本规划确定内容，内容确认生成正式脚本，编写只补视觉层

脚本规划产出结构化内容供创作者审阅。两次模型调用曾经用自由文本交接，让台词、画外音与原文在第二次解析中漂移。现在确认把规划整份转成正式脚本，服务端透传已确定的内容，提示词编写只补视觉层。无需等到生成视觉内容后才发现分集或口播有误。

正式脚本成为该集的内容来源，已确认的规划只供查阅。创作者和 Agent 在正式脚本上编辑正文。曾经按规划指纹增量合并的方案会静默撤销下游手工插入、删除和重排，也需要持续对账两份内容。

- 未确认的脚本规划可直接编辑，不另设平行的隔离草稿或 Agent 编辑副本。结构合法性守住落盘边界（人工编辑仍遵守 [ADR 0089](0089-single-speech-owner-per-video-unit-narration-delivery-per-project.md) 的发声准入），其余业务合规项在读取、编辑与确认时按本集规范集原文与当前项目事实实时计算，不落盘快照。
- 首次生成、界面保存与 Agent 增量编辑共享同一并发控制与版本基线，均允许保存结构合法但尚有确认阻断项的未确认规划；内容确认与覆盖已有规划的重生成均要求确认阻断项清零。盘上已有脚本规划时，重生成未全量通过则失败，保留原有规划、产物登记与确认状态不变。
- 确认替换已有脚本时须显式确认。旧分镜按结构移除处理，产物进入 [ADR 0107](0107-deletion-goes-to-trash-restore-only-adds.md) 定义的回收站。重做整集可以重跑规划再确认。规划重新生成但尚未确认时，正式脚本继续按其自身依据判断时效。
- 提示词编写读取正式脚本，默认只补标记为待编写的分镜或单元，完成后清除标记；显式点名允许重写已编辑的提示词，手工新增条目也可进入待编写，广告/短片的整集生成继续一步完成。参考生视频的提示词编写同样不设隔离草稿：逐单元按显式标识校验，通过项直接写回正式脚本并清除待编写标记，失败单元复用主编写路径对对应条目最多自动补跑一次；仍不通过或遇并发修改的单元保持正式脚本原有内容与待编写状态不变，并向调用方如实报告部分完成与失败明细。
- 需要给提示词编写读取的场景描述随规划进入正式脚本，原文锚点供人工核对。通过 Agent 改写原文锚点时，已有源文要求它仍是逐字子串。发声内容与参考生视频正文各见 [ADR 0089](0089-single-speech-owner-per-video-unit-narration-delivery-per-project.md) 和 [ADR 0064](0064-video-unit-body-is-the-only-truth.md)。

[v14→v15 迁移](../../lib/project/project_migrations/v14_to_v15_formal_script_truth.py) 移除历史条目指纹，为已确认但尚无正式脚本的集生成正式脚本，并标记待编写条目。脚本规划命名曾由 v9→v10 迁移统一，依据摘要中已有的旧 token 保持原值，因为只改 token 就会使已登记产物重新判旧。历史遗留的隔离草稿文件随项目迁移统一移入项目回收站并在迁移报告中说明。
