# Artifact lifecycles use the manifest as sole authority: backfilled artifacts are current; stale remains usable

> `docs/adr/0098` narrows "do not register targets whose current basis cannot be projected; read them as missing" and "backfill failures block entire projects": generation gaps no longer prevent projection. Backfill every available formal artifact unless its basis truly cannot be computed. Data-based whole-project rejection is limited to unreadable projects/scripts and unsafe archives; incomplete migrations still block under this ADR.

Users paid for every artifact (asset design images, script_plan intermediates, formal scripts, grids, storyboards, videos, narration audio, subtitles, presentations). The system must answer whether each exists and still matches current content. Directory scans/script paths answer only existence, mistaking files for matching content; persisted status fields require updating on every change, with omissions leaving lasting lies. Put answers in the **artifact manifest** (`lib/artifacts/artifact_manifest.py`, project-side `.arcreel_artifacts.json`): register identity, persisted paths, and **basis digests** (canonical JSON + sha256 of directly consumed formal content/upstream artifacts), plus video/audio content facts described below, **without status**. Compare registered and current projected bases on read to derive `current / stale / missing / blocked` (`ArtifactStatus`). Unpersisted status cannot become inaccurate through missed updates: changed content becomes stale on the next read.

## Decisions

- **Track only formal content and direct upstream artifacts.** Script bases use script_plan/formal project metadata; storyboards use entry bodies and referenced sheets/originals; videos use storyboards/unit bodies, and so forth. Visual bases (grids/storyboards/videos) exclude providers/credentials, models, pixel resolutions, seeds, audio switches, and renderer versions (`lib/artifacts/visual_artifact_provenance.py`): those express next-generation intent. Configuration changes must not stale a roomful of existing images and imply another paid generation round; apply them on explicit regeneration. Narration audio is different: provider/model/voice/rate determine who speaks/how fast, part of delivered content, joining narration text in bases (`lib/speech/narration_delivery.py`). Voice changes correctly stale old audio. The boundary is whether a value changes delivered content, not settings-versus-script location.
- **Register imported finished asset images by image content itself.** Description/style/original-derived asset bases and base-sheet/change-description-derived derivative bases apply only to images generated in this project. Uploaded asset/derivative images and library-applied images/derivatives are finished artifacts, regardless of external project generation or library upload origins. Only images matter to the project; descriptions are generation inputs, not freshness criteria. Library assets therefore carry no origin marker. Upload/application selects `source: manual_upload` versions in the same formal commit as image writes (batch asset application commits all version records/files/`project.json`/manifest registrations together, rolling everything back on any failure). If selected versions are manual uploads and managed snapshots match declared bytes, expected-basis planners use image-only `build_uploaded_asset_sheet_basis`, excluding descriptions/styles/base images/names; otherwise use generation inputs. Registration uses this same planner, never separate basis logic. Thus empty descriptions still claim imported images; later description/style/name edits never stale them, and uploaded/imported derivatives ignore base regeneration/description changes. Generating/selecting new versions, or external image replacement inconsistent with selected snapshots, restores generation-input freshness; restoring uploads restores image-only registration. Legacy images without upload records retain generation-input rules without retrospective classification. Version records thus enter expected bases: unreadable `versions.json` blocks asset freshness like typed media, without generated-input fallback that silently reclassifies finished images. Current-only archives retain selected upload snapshots, giving imports/backfill identical conclusions.
- **Cache content digests by file stat identity; values remain content hashes.** Expected bases hash assets/storyboards and other inputs (`lib/infra/content_digest.py`), repeatedly queried by claiming/requests/polling. Bounded process-local LRU caches use `(st_dev, st_ino, st_size, st_mtime_ns)`; reuse unchanged identities, rehash changed ones. Caching hashes rather than stat identities preserves freshness semantics: replacements rehash/stale; copies/imports/restores changing only mtime rehash once but identical bytes keep identical digests. Known accepted cost: deliberate replacement restoring both size/nanosecond mtime can return old digests. Recently written files (mtime within seconds of finishing reads) are not cached, avoiding repeated writes hidden by coarse timestamps. Caches never persist or create second authority; losing them costs only speed.
- **Write facts; derive conclusions on read.** Persist immutable-at-registration facts: bases and video/audio content fingerprints. Freshness is read-derived, never write-marked. Project writes can bypass interfaces (direct Agent script edits, manual replacements, imports/restores); write marking requires every writer's perfection, undoing flags if content reverts, and interruption-safe marking. Read derivation avoids these problems. Slow reads arise from implementation (per-item IO, duplicate evaluation, video rereads), not this principle.
- **Record video/audio content facts on write.** `episode-video` / `episode-audio` entries additionally store formal-file sha256 hexdigests, sizes, and nanosecond mtimes at registration (`ArtifactContentFacts`; `content_digest` / `content_size` / `content_mtime_ns`). Version records also store snapshot `content_digest`. Shared `observe_registered_artifact` gathers facts for paid generation, uploads, version restoration, narration delivery, and repair registration, reading the admitted file version through the same descriptor. Activation (migration and envelope-free self-proving archives) records descriptor facts when proving formal files equal selected snapshots. V17→v18 applies that proof to existing videos/audio in both entries/version records. Enveloped imports carry facts only if activation proves exactly envelope-fingerprinted bytes; otherwise omit facts and retain source-project stale status. Rekeying/compensation move/restore original entries with facts. Facts do not participate in entry equality: writer CAS, rollback decisions, and import validation compare only paths/bases. They do participate when deciding whether writes changed manifests.
- **Assess video/audio against registered facts, without reading snapshots.** Facts prove formal files are registered versions. Equal sizes/nanosecond mtimes accept directly without content reads; differences require full fingerprints, with mismatches stale. If registered mtime is not earlier than manifest mtime, same-timestamp writes may preserve stat values: treat as racy and fully compare, like git's index-relative checks. Entries without facts are stale. Validate snapshots only when actually used: restoration/pre-render compares version-record fingerprints and fails descriptively on mismatch. Render bases take unit snapshot fingerprints from version records, hashing only legacy versions lacking them. Accepted cost matches digest caches: deliberate same-size/restored-nanosecond-mtime replacement can evade detection.
- **Backfilled means current.** On schema introduction, register existing formal artifacts with migration-time projected bases. Shared registered/expected logic makes all completed backfills **current**. Authoritative indexes are `project.json`, script-entry `generated_assets`, asset definitions, controlled `grids/grid_*.json` (`lib/artifacts/artifact_planner.py`, exposed through `lib/artifacts/artifact_activation.py`); never scan/guess paths. No third legacy/unknown-provenance state or assumed staleness for old flows: upgrades must not mislead users into regenerating paid work. Missing files/unprojectable current bases (such as absent upstream artifacts) remain unregistered and read missing. Imports use the same entry but retain archived frozen bases, so stale imports truthfully reflect archived facts. Subtitles/presentations bind selected video versions at materialization, plus audio for `use_tts`. Later version changes make them temporarily inapplicable during export/import: preserve those fully self-proven against bound media, include them in full archives, and switching back restores applicability. Current-only archives exclude old snapshots/these entries. Other proof failures still fail exports/imports. Inactive projects may export archives: this read-only path admits even migration-blocked projects, omitting envelopes through schema gates (`server/services/project/project_archive.py`). Imports finish migrations then self-prove/backfill like upgrades. Deliberately retain this branch, sharing activation's current-schema criterion: previously active projects with outdated schemas likewise have ineffective manifests whose frozen bases are not archived, instead reprojecting on import. Archives keep no second reader for ineffective manifests. Removing compatibility would trap data by denying blocked-project backups. This differs from runtime `blocked`: here no entry can initially be registered; `blocked` means entries exist but runtime reading/basis computation fails.
- **Stale remains usable.** `stale` means older than current content, not unusable: view/render/export normally, block no steps, and infer no regeneration instruction. `usable = current ∪ stale`; generation without IDs fills only `missing`, with explicit user choice to redo stale. `blocked` (unreadable manifests, path blockers, unavailable bases) fails loudly, never missing: converting unreadability to absence turns faults into paid calls.
- **Task results and freshness are independent.** Batch requests exhaustively report `succeeded ∪ failed ∪ blocked` (`GenerationItemState`); artifacts independently report four states. Failed forced regeneration can leave current artifacts; missing artifacts do not imply failed prior tasks (perhaps never requested). Receipts carry both, preventing substitution of request failure for absent usable content.
- **Never merge four state axes.** Freshness (`ArtifactStatus`), queue/public task status (`GenerationTaskState`), admission (`BatchAdmissionDecision`, `docs/adr/0061`), and per-ID outcomes (`GenerationItemState`, `lib/generation/generation_result.py`) answer respectively usable content now, asynchronous-job progress, whether requests should happen, and actual item outcomes. Carry them alongside on receipts, never one status field: collapse needs translation elsewhere and misstates combinations, such as successful tasks with later externally deleted files, or current artifacts after failed regeneration.
- **`schema_version == 8` is the sole activation gate.** Effective manifests depend only on `project.json`'s `schema_version` matching `CURRENT_PROJECT_SCHEMA_VERSION` (`lib/project/project_schema.py`). Activation commits forward: complete read-only preflight under metadata locks, then whole-manifest writes; failed post-write preflight rechecks restore prior snapshots. Commit schema only afterward. Schema-write failure leaves new manifests with old schemas, hence inactive, equivalent to staying old; no second manifest rollback. Repair/retry converges through idempotent complete reprojection. Inactive projects have no fallback reader: `active_artifact_currency_resolver()` throws `ProjectMigrationError`, so callers cannot silently answer status. One verdict blocks generation, queue `enqueue_task()`, MCP, and REST writes (persisted migration failures ∪ outdated schema), exposing reasons unchanged for repair/retry. Entry declarations own blocking: REST `require_project_migration_ok`, Agent-declared migration policy wrappers; inner checks such as `ScriptBatchEditor` are fallbacks, never excuses to omit declarations. Rerunning migration chains does nothing to current schemas and is not reconciliation. Whole reprojection uses schema-preserving `activate_artifact_target_state(bump_schema=False)`, atomically replacing targets, returning `False` for unchanged entries, idempotent/reentrant. Ordinary content changes need only read-time assessment. Projects remain openable: read-only script/canvas reads bypass manifests. Each project has one generation answer and one presence/freshness answer: active manifests answer; inactive means unreadable, repair first.
- **Manifest locking is project-wide, cross-process, full-replacement.** One `.artifact_manifest.lock` per project uses portalocker exclusive/nonblocking polling and timeout errors, not indefinite waits. Shared cross-episode sheets require project rather than episode granularity. All read-modify-writes hold that lock and persist through temp files + fsync + atomic rename, always coherent snapshots. Readers need no manifest locks: descriptors see complete snapshots; each read validates root identity, rejects symlinks/junctions/FIFOs, and caches parsing only in-process. Resolvers read one snapshot per request, shared by admission/all comparisons; midrequest replacement changes no conclusions. Windows open-reader sharing conflicts can block replacement/empty-manifest deletion; writers retry briefly/boundedly then error. Scoped CAS preserves unrelated entries; full CAS likewise turns read/decision/write drift into explicit failure rather than overwrite. Activation/prepayment rechecks also need coarser `.project.json.lock`, always metadata ⊃ manifest, never reverse nesting. Timeouts apply only to manifest locks; metadata locks (`lib/artifacts/formal_write.py`) block indefinitely with queue semantics. Do not unify waits.

## Explicitly rejected

- **Directory scans/script paths for existence**: answer only file presence, not content matching; separate frontend/REST/Agent counts diverge after one storyboard deletion. This also holds for inactive projects: schema-branched file-presence readers retain the rejected approach.
- **Persisted entry statuses or write-marked downstream staleness**: every content write must update all downstream entries, omissions lie indefinitely, and updates need cross-file transactions. Bypasses, reversions, and interruptions are explained under "Write facts; derive conclusions on read." Read comparisons depend on one invariant, equal basis digests, at a projection cost per read. Expensive input hashing uses stat caches, costing changed files rather than scaling with read counts.
- **All generation settings in bases**: changing video models stales every video and implies repeat payment. Next-generation intent applies only next time, not retrospectively. Conversely, do not exclude every settings-page value: narration voice settings determine delivered sound. Draw the boundary by delivered content, not entry location.
- **Stale after backfill or unknown-provenance third states**: upgrades change no content; arbitrary staleness pushes paid regeneration, while third states add branches to every consumer.
- **Automatic stale regeneration**: old does not mean needs redoing. Queries must not charge, and users may knowingly accept old versions.
- **Pretending migration failures are normal**: do not swallow failures and use old readers. Persist blocking `migration verdict` ("Migration failure verdict" in `GLOSSARY.md`), expose reasons unchanged, reject generation, and keep projects open without pretending manifest authority applies. Outdated/unmigrated projects share that verdict even without persisted failures: schema checks derive not-yet-upgraded; recorded failures take priority only because they identify specific repair data.
- **Episode locks or incremental entry writes**: whole-target activation interrupted midwrite leaves half-active projects; cross-episode shared sheets defeat episode locks.

## Consequences

- **Manifest scale contract**: every write fully parses/serializes and renames whole files; reads reuse parsing by file identity in-process, completely rereading/reparsing changed files. Entry bound is approximately `资产数 + Σ_每集(2 + 宫格数 + 7 × 分镜条目数)`: at most storyboard/video/audio/two-subtitle/two-presentation identities per entry. Hundreds of episodes with tens of shots yield tens of thousands of entries and megabyte files, linearly increasing operations. **Known accepted cost**: no entry caps/LRU/TTL removal, which would make existence guesses again. Shrink only when canonical ownership disappears/moves (deleted entries, renamed resources), deleting empty sidecars. **Changed bases only stale entries, never orphan them; retain deliberately**. Real bottlenecks call for sharding/incrementally readable containers, not dropped entries.
- Backfill/migration failures block whole projects: existing content remains readable/viewable, generation unavailable. Explicit stoppage/repair replaces silent degradation, at the cost of one anomaly blocking all generation; exact reasons and retry entries requiring no manual JSON edits are mandatory.
- Lock-free reads neither wait nor fail behind long activation/batch-registration writes; manifest timeouts affect writers only. Reads create no lock files, preserving read-only queries.
- Correctness requires identical expected-projection/registration code; divergence makes entire artifact classes arbitrarily stale. New kinds must share basis constructors across both paths, never duplicate them.
- Product standardized sheets share all other sheets' lifecycle: registered artifacts, same four states, usable stale, no automatic regeneration (`docs/adr/0034`).
- `lib.artifacts.artifact_activation` is a permanent facade. Internal `artifact_planner` / `artifact_currency` / `artifact_input_claims` / `artifact_registration` are never exposed directly outside; external references use facade namespaces. Underlying `lib.artifacts.artifact_manifest` is outside this decomposition/exemption. Tests are intentional exceptions: re-export aliases cannot replace internal runtime references, so behavior patches target implementation modules. Exposing decomposition later requires revising this rule/migrating consumers first.
- Follow `GLOSSARY.md`'s "Artifacts and production status" section for artifact/manifest/freshness/backfill/production terminology, sharing this ADR's meaning without independent wording evolution. Unique mechanisms (four axes, fill-missing, independent task/freshness) stay here, not duplicated in glossary.

## User-provided artifacts (revision)

Extend finished-image registration to uploaded storyboards/videos: when selected uploads match artifact bytes, expected bases use upload bytes alone, excluding prompts/assets/style/upstream storyboards. Uploads become immediately current; later prompt/asset edits never stale them, and downstream use (videos using storyboards) does not question generation bases. Generated/selected new versions, externally replaced storyboards inconsistent with selected snapshots, or videos inconsistent with registered fingerprints return to generation-input assessment. Creators, not systems, judge upload/script consistency.

Retire both earlier behaviors: uploaded videos unregistered and claimed only through manual-upload version fallbacks; uploaded storyboards removed/missing with empty prompts or missing referenced sheets, blocking downstream as unregistered. Fill-missing batch generation therefore never pays to overwrite uploads.

## Storyboard/grid bases exclude asset names (revision)

The delivered-content boundary applies to names: reference images sent for storyboards, combined grids, and sliced storyboards identify by type as “图N”; body `@[名称]` renders as “图N”, so names are not model inputs. These bases therefore keep only reference types, roles, kinds, and fingerprints. Replace matching mentions with “图N”, preserving unmatched mentions because models see their names; retain nonasset identities such as previous storyboards (`without_asset_names` in `lib/artifacts/visual_artifact_provenance.py`). Renames preserve current status; changed sheets stale them. Reference-video declaration lines, storyboard-video dialogue, and sheet prompts do contain names, so their bases retain names and rightly stale on rename.

Replay grid/slice bases from grid-record frozen references; cascading renames therefore update reference names and moved paths. Asset merges moving images as derivatives under retained assets use the same rewrites. Merges into existing derivatives switch images, so records do not redirect and become stale normally. V18→v19 migrates existing projects: rewrite only previously current manifest registrations, plus frozen version bases through the same function, avoiding format-induced mass expiration.
