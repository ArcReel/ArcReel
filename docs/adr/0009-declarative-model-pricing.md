# Make billing pricing declarative in code: place pricing in `ModelInfo`, dispatch by `kind`, without runtime DB/UI price editing

Before this decision, ArcReel's `CostCalculator` (`lib/billing/cost_calculator.py`) stored per-provider/modality rates as **scattered class-attribute dicts** (more than ten, including `IMAGE_COST` / `VIDEO_COST` / `ARK_VIDEO_COST` / `GROK_TEXT_COST` / `OPENAI_IMAGE_TOKEN_COST`). `calculate_cost` manually routed through a long `if provider == X` chain to shape-specific functions, mixing USD/CNY inside functions. New built-in providers without explicit branches had videos **silently fall back to Veo rates**, charging incorrect prices. Provider promotions change prices; rates should be configurable rather than hardcoded.

Evaluation confirmed a key fact: **ArcReel generation costs are snapshots**. `finish_call` invokes `calculate_cost` only once at completion, freezing results in `ApiCall.cost_amount`; all usage/cost aggregation reads frozen values without recalculation. Thus "retain retired-model rates for historical billing" is unnecessary: historical records do not depend on rate tables. LiteLLM likewise indexes one data table by model name, holding metadata, context windows, and pricing (`input_cost_per_token` / per-image / per-second, etc.) together in entries, dispatching calculations by `mode`. Pricing and model metadata **stay together**.

Use **code-level declarative** billing, **without** runtime DB/UI price editing. Specifically: ① **put pricing in every `PROVIDER_REGISTRY` model entry** as `ModelInfo.pricing` (one truth per model, aligned with LiteLLM); ② place `Pricing` types and calculation **strategies in independent `lib/billing/pricing`**, selected by `kind` tags (`per_token` / `per_image_flat` / `per_image_by_resolution` / `per_image_openai_token` / `per_second_matrix` / `per_token_video` / …), separating calculation concerns from declarations; ③ dispatch `calculate_cost` **by `pricing.kind`**, not `if provider == X`; ④ mark retired models with `ModelInfo.hidden` (remove from UI dropdowns, retaining entries for retirement after enqueue but before finish), without historical-rate repositories; ⑤ **migrate every existing built-in provider** (Gemini/Ark/Grok/OpenAI/Vidu), pure refactoring without behavior changes, comparing old values through the full pytest suite. Runtime promotional-price changes without redeployment are a separate future epic if needed, not presumed here.

## Consequences

- **Thin, extensible `calculate_cost`**: replace `if provider == X` with `kind` dispatch. New built-in models add `ModelInfo.pricing` declarations and reuse existing `kind` strategies, **without editing `calculate_cost` logic or adding provider branches**, eliminating silent new-provider video pricing at Veo rates structurally.
- **`pricing=None` is an explicitly declared exception, not eliminated silent fallback**: Agent Plan packages (`ark-agent-plan`) publish no per-call rates, so registry entries intentionally omit `pricing`. For known models with None pricing, `lookup_pricing` uses generic Gemini defaults with debug logging (`lib/billing/pricing/lookup.py`). Unlike accidental routing of unknown models through missing provider branches to Veo, this exception is registered and observable.
- **Promotional price changes require declaration edits and redeployment**: a conscious tradeoff. Nontechnical runtime editing is unavailable, avoiding DB schemas/migrations/repositories/settings UI/trilingual i18n/validation. ArcReel is self-hosted, redeployment is normal, and costs serve estimates/internal accounting rather than external billing: precision needs "not wildly wrong," not "adjustable in real time."
- **No historical-rate database needed**: snapshots freeze past `cost_amount`; pricing need cover only **currently selectable** models. Retired models do not enter pricing data; `ModelInfo.hidden` covers rare retirement-after-enqueue/before-finish calculations without a historical-rate graveyard.
- **Custom-provider prices stay outside `ModelInfo`**: users enter dynamic prices in DB (`CustomProviderModel.price_input/output/currency`). `calculate_cost` retains an early `is_custom_provider` branch for parameterized calculation (callers query DB first and pass values), consistent with [ADR 0008]'s database-backed custom credentials/configuration outside static registries.
- **Pricing/capability declarations share location, with separate responsibilities**: data joins `ModelInfo` (single truth, visible promotional changes in one place), while `Pricing` **types/calculation strategies** remain in independent `lib/billing/pricing`. Declarative data and unit-testable logic are not coupled in one `cost_calculator` file.
- **Extend `ModelInfo` incrementally without redesign**: add only `pricing` and `hidden` to `ModelInfo`, **without** addressing existing small flaws such as duplication between `capabilities: list[str]` and `VideoCapability` enums (separate issues to prevent scope creep).
- **Add `kind` values for advanced tiered/cached pricing as needed**: initial `kind` values cover all current shapes without behavior changes. Qwen input-tier pricing initially uses the 0–128K base flat rate; tier modeling remains a future `per_token_tiered` kind extension, outside this pure refactor.
- **Complement ADR 0008**: 0008 prevents protocol shapes contaminating credentials; 0009 prevents scattered hardcoding contaminating billing data, with pricing shapes determined by `kind`, not provider. Both clarify runtime determination versus startup declaration. Future PRs introducing runtime DB/UI price editing or returning pricing to scattered dicts must first deprecate this ADR.
