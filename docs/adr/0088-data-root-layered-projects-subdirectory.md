# 数据根分层：项目收进 `projects/`，数据根内不再以前缀区分项目

数据根（`ARCREEL_DATA_DIR`，默认 `<仓库根>/projects`）起初只是项目目录，引入可配置数据根时直接把它当成了数据根：项目与数据库、全局资产库、用户记忆、锁与迁移标记平铺在同一层，靠 `.` / `_` 前缀声明「这不是项目」。放不进来的日志与 Vertex 凭证被推到代码目录和数据根的上一级；忘了加前缀的目录（日志、测试连接产物）先后被当成项目列出且删不掉；「什么是项目」在多处各自判定且口径不一。我们决定把数据根分层：项目收进 `<数据根>/projects/<项目名>/`，其余运行数据以无前缀的名字与之并列，代码目录只放代码与配置。

```
<数据根>/
├── projects/<项目名>/
├── global_assets/
├── users/<user_id>/memory/
├── arcreel.db
├── logs/
├── vertex_keys/
├── trial_runs/
└── runtime/        生成准入锁、迁移完成标记、迁移错误日志
```

随之确定的口径：

- **原地嵌套**：数据根仍是部署者已配置、已挂载、已备份的那个目录，升级不改环境变量与卷；默认开发布局因此是 `<仓库根>/projects/projects/`。
- **项目只有一处判定**：`projects/` 下名称合法且带 `project.json` 的目录才是项目，数据根其余条目一概不是。
- **持久化数据不存绝对路径**：数据库与任务载荷不再保存数据根或项目的绝对路径，一律由项目名、项目内相对路径或凭证 id 推导，以后再挪目录不必改库。
- **Agent 读访问对数据根默认拒绝**：内置读工具只放行当前项目与当前用户的记忆；Bash 沙箱拒绝 `projects/` 以外的全部顶层条目。新增的系统目录自动受保护，不再逐项维护敏感目录清单（`docs/adr/0026`）。
- **日志位置固定**：取消 `ARCREEL_LOG_DIR`，日志固定在 `<数据根>/logs/`；不需要文件日志时用 `ARCREEL_LOG_FILE_DISABLED`。
- **数据库默认文件在路径解析时改名**：新名缺失且旧名存在时连同 `-wal` / `-shm` 一并改名，应用、alembic 与脚本共用这一步；显式设置 `DATABASE_URL` 的部署不受影响。
- **启动时一次性迁移**：逐步幂等、崩溃后续跑，完成后启动期只剩一次标记检查；已有 Agent 会话的存储键随项目路径改写（`docs/adr/0029`）。**不支持降级**：旧版本会把 `projects/` 当成一个项目，升级前须备份数据根。

本 ADR 取代 `docs/adr/0074` 中「用户记忆落 `<数据根>/.arcreel/users/…`」与「数据根下 `_` 前缀目录表示跨项目共享素材库」两处；项目内部的 `.arcreel/` 不变。

## 明确不采用

- **维持平铺，只集中项目判定**：仍要求每个新系统目录记得加前缀；日志与凭证依旧无处安放，代码目录继续承载运行数据，而在安装目录只读的部署形态下它不可写。
- **换一个新的默认数据根（如 `<仓库根>/data/`）**：每个 Docker 与自定义部署都得改卷挂载，漏改即表现为「项目全部消失」。
- **系统状态收进数据根下的隐藏目录（如 `.arcreel/trial_runs/`）**：延续前缀约定，只是把同一个问题藏得更深。
- **保留 `_global_assets`、`.arcreel.db` 等现有名字**：分层后前缀已不承担区分作用，留着会让「前缀有含义」的旧约定继续被照搬。
