# SessionManager decomposition boundaries: dual AgentAccessPolicy projections, symmetric assembler I/O criteria, typed event streams, and SseChannel

SessionManager in `server/agent_runtime` (approximately 2,900 lines and nearly 100 methods) physically combines six unrelated responsibilities: access/sandbox rules, SDK-options assembly, subscription broadcasting, token/cost extraction, session lifecycle, and message serialization. Replay-boundary state machines leak into consumer AssistantService (decoding `_replay_done` / `_idle` / `_queue_overflow` sentinels); access-rule tests require monkeypatching private methods, while subscription broadcasting duplicates project-event services. Extract independent modules with small interfaces and deep implementations by responsibility, with these boundaries. **AgentAccessPolicy**: one class owns the rules for "what the agent may touch," projecting the same rules twice: compiling settings for kernel sandboxing and supplying per-read/write/command decisions to application hooks. It has zero I/O and pure construction from process-level root paths. Keep Windows fallback (Bash-prefix allowlists) inside the class through constructor parameter `sandbox_enabled`; Bash secret stripping also belongs here because wrapping and allowlist matching have mutually exclusive coupling that must stay local. Emit only pure decisions; SDK wrapping and permission-chain order remain thin session-management adapters (SDK is optional, and absence checks exist only there). Do not call it SandboxPolicy: the glossary reserves "agent sandbox" for kernel isolation, while this module also serves application hooks outside the sandbox. **Options assembler**: a dependency-holding class allowed I/O, responsible for credential injection (DB → SDK-subprocess env, transport rather than configuration legacy). Apply the same I/O criterion as AgentAccessPolicy: static rules mean zero I/O; assembly's purpose is collecting live data at session opening, so I/O is allowed. **Typed event stream**: SessionManager exposes one async context manager to AssistantService, yielding semantic events (deliver replay batch once → individual live messages → heartbeats → overflow terminates stream, termination signals reconnection), bringing atomic replay/subscription handoff into the seam. Reassess `docs/adr/0005`'s "do not introduce another typed event system" prohibition: it assumed an unchanged seam with consumers decoding sentinels. Redrawing the seam makes typed events the natural incorporation of sentinels. Keep 0005's core unchanged (CM shape, `is_disconnected` checks, `__aexit__` cleanup), revising sentinel-consumption wording alongside implementation. **SseChannel**: consolidate session/project subscription broadcasting, limited to subscription/unsubscription, broadcasting, idle heartbeats, and overflow handling (parameterized strategies: evict noncritical messages + overflow signal versus removing subscribers), with optional first/last-subscriber lifecycle hooks. Opening content (buffered replay / initial snapshots) stays outside; consumers guarantee atomicity under locks. Do not include deprecated database-polled task-stream endpoints. Extract token/cost and message serialization into pure-function modules. Session lifecycle, capacity eviction, and patrol are interdependent and share session tables/locks, so remain in SessionManager's core; leave SessionActor completely unchanged (`docs/adr/0028`). Apart from removing provider base_url environment-variable fallbacks, decomposition is purely structural, preserving behavioral semantics exactly.

## Explicitly rejected

- **A platform adapter for Windows fallback** (favored by architecture review): rejected. The two platforms produce asymmetric shapes: the kernel route emits startup configuration and leaves Bash alone at runtime; fallback emits runtime per-command decisions. Forcing one adapter interface creates abstractions with half their operations empty on each side, while genuinely shared path rules are identical and would require a third shared core after splitting. One boolean branch expresses platform differences more honestly than two half-empty adapters. Use this ruling for future adapter-splitting proposals.
- **AgentAccessPolicy as pure functions**: each function would receive 5+ root-path parameters, exploding signatures while callers still assemble them; complexity merely moves from the class to call sites.
- **Opening content inside SseChannel** (calling an "opening-content producer" on subscription): buffered replay and live snapshot scans share no implementation; parameterization is a false abstraction, adding forwarding without deepening the component.
- **Splitting streaming into two calls** (fetch replay list, then subscribe live): loses messages between calls. Seamless handoff under one lock motivates the single stream; closing that gap needs cross-call cursors or shared locks, complicating interfaces further.
- **Credential injection inside AgentAccessPolicy** (classified as "secret hygiene"): dependency shape is a better classification than ADR topic. Injection reads the DB; stripping has zero I/O. Combining them destroys the latter's pure-construction testability.

## Consequences

- AssistantService no longer sees sentinels; in-band sentinels become internal SseChannel mechanisms. Revise `docs/adr/0005` when typed streams land, describing current state without a patch-like supersession chain.
- Access-rule tests change from monkeypatching private methods/environment variables to constructor-fed allow/deny assertions. Preserve assertions exactly during migration, leaving redundant-test cleanup for a separate later change.
- Provider-secret environment containment (startup assertions, empty-value overrides, Bash stripping) is permanent: neither "transport" (SDK subprocesses authenticate only through env) nor "containment" (parent-process environments are external inputs) disappears with database-backed configuration. Do not remove it as technical debt.
- GLOSSARY.md includes AgentAccessPolicy, with SandboxPolicy in its _Avoid_ list.
