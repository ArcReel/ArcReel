# 媒体生成按提交与取件分别重试

向媒体供应商提交生成请求后，服务端可能已经创建任务并计费。如果响应丢失，重复提交就可能再次计费。相反，轮询和下载只取回已有任务的结果，遇到短暂故障即放弃可能丢掉已付费产物。因此重试分别控制在提交、轮询和取件各自的边界内，取件失败不会重新发起生成。

## 提交

共用的 HTTP 提交入口按传输阶段的证据分流。建连、连接池或代理握手失败时，可确认请求尚未送达，允许重试。本地协议或请求构造错误同样发生在送达前，直接原样返回并立即失败。读写阶段断连或超时等无法确认是否已受理的故障，以 `AmbiguousSubmitError` 终止，避免重复创建任务或计费。收到 HTTP 响应后，结合状态码和通道的业务错误分类判断，共用判断条件将 408、425、429 和 5xx 视为瞬态响应。

只有确定尚未受理的提交遇到请求体超限时，才按 [ADR 0012](0012-reference-compression-conservative-ceiling.md) 降低参考图上传档位。GET 或 HEAD 取件失败不触发降档。后端通过单向回调 `on_provider_resubmit_unsafe` 关闭降档重提窗口。可接续的后端在供应商任务号持久化后触发该回调。Grok 等把提交和等待合为一次不透明 SDK 调用的通道，则在进入调用前关闭窗口，因为调用开始后的异常无法证明供应商尚未受理。任务号的持久化和重启恢复见 [ADR 0007](0007-orphan-tasks-not-requeued-on-restart.md)。

## 取件

轮询、二次取件和下载在有限重试预算内处理 429、5xx 等瞬态故障。轮询和二次取件可将 404 视为资源尚未就绪，视频下载也可重试任务进入终态后短暂返回的 403。但对签发时即可取回的对象地址，403 和 404 立即失败。声明式端点在二次取件和产物下载阶段使用同一套预算规则。若供应商任务已成功但取件耗尽预算，支持接续的通道记录 `artifact_download_failed`，用户可通过「重试下载」重查原任务并重新取件。

「重试下载」按 `api_calls.task_id` 定位原调用。首次取件耗尽预算后，该调用可能已结算为 `failed`。接续取件再次耗尽时，则可能仍为 `pending`。两种情况下都会将该调用重新置为 `pending`，并清除旧的失败原文和结构化错误，确保后续重新结算成功时能正确呈现结果。调用与任务的关联和用量投影见 [ADR 0076](0076-usage-record-is-projection-of-provider-calls.md)。

实现入口见[媒体后端运行时](../../lib/backends/backend_runtime.py)与[声明式端点后端](../../lib/custom_provider/declarative_backend.py)。文本生成的重试边界见 [ADR 0047](0047-text-backend-retry-wraps-single-call-only.md)。
