# 视频请求事实只求值一次：读侧与执行侧同一次求值、只差身份来源

一次视频生成请求有一组互相牵连的执行事实：执行模型、下发的分辨率、可申请的秒数（时长联动约束收窄后的档位及每个被排除秒数的成因）、时长这一维是否由端点固定、音轨形态。报价、预检、整批准入、剧本规划、内容确认、界面展示、Agent 能力载荷与执行都要读这组事实；任何一处自行推算都会与其余各处分叉——预检要求确认的秒数与执行实际申请的秒数不同、规划阶段放行的时长在内容确认时被拒、报价按一个分辨率而扣费按另一个。

我们决定把这组事实收成「视频请求事实」，按「项目 × 路线 × 任务类型桶 × 身份来源」对每次请求求值一次：提交前的各读侧以当前配置解析出的执行模型为身份，执行侧以实际构造的调用通道为身份（`docs/adr/0049` ③），其余求值完全相同，各消费方直接读它的结果，不再各自组装或逐项转抄。执行模型解析、桶能力闸与时长联动约束的收窄规则本身不变，变的是「按一次请求组合出事实」只在这一处发生。

## 分辨率未设置即不下发，两条视频路线同口径

分辨率未设置时请求不携带该参数（`docs/adr/0019`），参考生视频路线（含降级为 i2v 的无参考图单元）与分镜路线一致；ArcReel 不维护按供应商的兜底分辨率。尺寸须承载比例的调用通道不在此列，仍按 `docs/adr/0011` 推导尺寸下发（`docs/adr/0019` 的边界不变）。时长联动约束按请求实际下发的分辨率收窄，未设分辨率即不施加分辨率约束（`docs/adr/0056`）。

报价与扣费同源：报价以请求实际下发的分辨率（含未设置）按扣费所用的同一计价规则求价。

参考生视频项目里无参考图单元落 i2v 桶，其执行模型可以与 r2v 桶不同；两个执行模型的分辨率各自设置（`docs/adr/0054` 的「按执行模型取键」对两个桶分别成立）。

## 单元定桶以可用参考图为准，i2v 桶不可用即「未知」

参考生视频单元按可用参考图定桶：有 → r2v，正文没有任何引用 → i2v（`docs/adr/0054`）；未登记引用的阻断照旧（`docs/adr/0073`）。每个单元的桶、可选档位与成因以服务端求值为准交给界面与 Agent，界面不以「名字已登记」自行判定；声明引用与可用参考图分裂时结构化阻断，不静默换桶。

i2v 桶解析不出（未配置可用模型、桶内模型已删除或停用、缺能力）时，无参考图单元的档位是「未知」并附原因与修复指引，任何读侧都不回退到 r2v 模型的档位。

## 时长由端点固定按桶判定

「时长由端点固定」随任务类型桶各自判定：参考生视频项目中 r2v 与 i2v 两桶的判定可以不同，界面、`use_tts` 可用性与执行都按单元实际落入的桶取值。剧本规划内部借固定篇幅当分镜依据；内容确认面板属于界面时长控件，按端点固定禁用并说明原因，不提供可选档位。

## 失败只带类型，由消费方按阶段处理

视频请求事实从不降级：解析失败给出带问题码、参数与修复指引的结构化失败。处理按阶段固定——读侧如实呈现「解析不出」并给出修复指引，内容确认因此被拦住；预检、整批准入与制作计划折成逐目标的阻断问题；分镜与参考生视频两条路线的执行都阻断并记录失败码。时长这一维在执行期不再「能力查询失败即空值放行」：走到执行说明入队前解析成功，执行期失败意味着配置在排队期间变了，应以失败码呈现，而不是交给供应商以付费失败暴露。时长联动约束把档位收成空集时一律严格处理：读侧如实呈现空集与成因，执行侧阻断。

问题码只增不改：已记录的失败码与其参数键名是对外契约。分镜路线的档位缺失、无效、收空用 `video_supported_durations_*` 一族，预检与执行同码；参考生视频路线沿用 `reference_*` 一族。

## 音轨事实由同一次求值派生

用户请求的音频开关取自配置，是求值的输入；计价口径的有无音轨、成片有无音轨、开关是否可控三项按任务类型桶派生，与请求的开关放在一起判定冲突；声音一致性档位的派生口径不变，仍由「模型有无音轨」×「项目生成模式」×「角色声音绑定方式」三维决定。执行与入队预检读同一次求值：分镜路线在执行期同样复查音频开关冲突，与参考生视频路线一致。

## 明确不采用

- **i2v 桶不可用时软回退到 r2v 档位**（不挡创作流）：执行期这类单元必然被阻断，回退只会让规划阶段放行一份执行不了的方案。
- **参考生视频路线下发按供应商的兜底分辨率**：该例外的成因已不存在，兜底值反而覆盖 ComfyUI workflow 的字面尺寸（`docs/adr/0082`）、在只接受特定档位的端点上失败，并使报价与扣费、约束与下发各取一值。
- **读侧与执行侧各自组装、只共享底层规则**：两份组装各自补缺省值，分叉在字段缺失时悄然发生。
- **界面保留「单元是否带参考图」的镜像判定**：它只看声明引用不看可用参考图，缺资产图的单元在界面按 r2v 取档、执行时落 i2v。

## Consequences

- 读侧与执行侧在同一份配置下给出相同的视频请求事实：桶内模型已删除、停用或缺能力时解析即失败（`docs/adr/0054`），执行侧不会被静默换成另一个模型，两个身份来源在同一份配置下必然一致；两侧事实不同只意味着配置在其间变了，此时以执行侧的实际身份为准。
- 能力查询与 Agent 能力载荷只有一个「无参考图单元档位」来源；设置页与创建向导的候选模型预览与已保存配置走同一道桶能力闸，候选失效时如实报出，不静默换成供应商默认模型。
- 参考生视频未设分辨率的项目改为不下发后，执行指纹随之改变：已选视频不再命中同档免费复用，已入队未提交的任务在执行时按当前口径重新投影；产物时效不受影响（`docs/adr/0062`），已跨过执行检查点的任务按检查点继续。
- `docs/adr/0049` 中 video lane 的兜底分辨率与「能力查询失败降级为空值放行」在时长这一维由本 ADR 取代；`docs/adr/0019` 对参考生视频路线不再有例外。
