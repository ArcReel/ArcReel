# 迁移与导入尽量保持原样：生成缺口只拦生成，依据总能投影，只有读不出才阻断整个项目

升级与归档导入时，补录曾用当前的生成输入审查存量产物：描述为空、引用的资产没有资产图、单位里台词与画外音混在一起，都会让依据投影不出来，产物于是不登记、读作 missing；各迁移步也各自决定哪些结构异常要拒整个项目。结果是业务上完全可用、用户已付过费的产物在升级后「消失」，过去正常流程产出的数据形态让整个项目被阻断，而迁移报告只在接口里、用户看不到。规则本身卡住了不影响业务的数据。

决定：

- **范围。** 迁移与导入只保证过去标准流程产出的数据能走通；用户手改造成的异常不专门防，但也不让它拖垮整个项目。
- **生成缺口只拦生成这个动作，依据总能投影。** 生成输入里缺的项在依据中记为缺席；输入完整时依据形态不变，已登记条目的摘要因此不受影响。补录时，文件本身可用的正式产物一律登记、判 current；之后补齐缺口（补写描述、生成缺的资产图）让依据变化，产物按常规判 stale。混合发声单位（`docs/adr/0089`）的存量视频同样照常补录，单位本身仍需重新规划。缺少合成时 TTS 设置的旧旁白音频不属于缺口：它的依据含合成时的发声参数，确实算不出（`docs/adr/0075`），仍不登记。
- **不删除、不丢弃用户内容。** 媒体文件读不出时原地保留、不登记；结构缺陷能按确定规则修复（补 id、重新编号）就修复，修不了就原样留在文件里，交给运行期已有的修复机制。
- **过去正常流程产出的旧形态由迁移规整，不拒绝。** 非规范的集绑定、新旧草稿名并存、归一后撞名的资产名等，按确定规则规整；规整有取舍时，另一份保留为备份。导入时剧本引用了未定义的角色、场景或道具，一律补占位。
- **因数据拒绝整个项目只限两类：** `project.json` 或剧本不是合法 JSON；导入包不安全（加密条目、路径越界、符号链接、`project.json` 缺失或多份）。迁移本身没能做完（磁盘空间不足、写入失败、迁移步自身的程序缺陷）不是对数据的裁决，照旧阻断：项目原样保留，排除故障后重试（`docs/adr/0022`）。
- **迁移报告只记迁移改变了什么、丢了什么：** 自动规整的取舍、补的占位、没能带入的产物（读不出的文件、依据算不出的旧旁白音频）。生成缺口不进报告，因为用户真去生成时会被拒并看到原因；需要重新规划的单位也不进报告，因为它已有持久状态。升级后报告非空时，项目给一次可关闭的提示；导入前报告非空时，弹出一次性确认，确认即导入，取消则什么都不写；报告为空时两者都不出现。

## 明确不采用

- **存量生成的资产图按图本身登记（与上传图同等）**：之后改描述永远不判 stale，丢掉了时效追踪，还多出一条按来源分叉的规则；依据总能投影已经让这些图正常登记。
- **补录后标 stale，或引入「待确认」状态**：`docs/adr/0062` 否决的理由仍然成立——缺口不等于「旧」，而每个读取状态的地方都得多一条分支。
- **报告逐条确认或逐条修改**：导入只需要一次知情同意；逐条操作会把迁移变成一段工作流。
- **报告列出全部生成缺口**：大多数升级会弹出一长串用户此刻无需处理的条目，真正改变了内容的条目反而被淹没。

## Consequences

- 收窄 `docs/adr/0062` 中两条规则的适用范围：「依据无法投影的目标不登记、读时报 missing」只剩依据确实算不出的情形；「补录失败把整个项目置于阻断态」只剩迁移没能做完的情形。取代 `docs/adr/0075` 中「投影失败的进迁移报告、由用户决定重生」；该 ADR 中旧旁白音频不补写、进迁移报告的规则仍然有效。`docs/adr/0062` 里「没有上传记录的存量资产图按生成输入投影、不做追溯判别」仍然有效：这些图照常按生成输入投影，只是缺口不再阻止投影。
- 执行器冻结的依据与期望依据必须继续出自同一个构造器；输入完整时两者逐字节一致，否则所有已登记产物都会判 stale。
- 已迁移的项目由下一个发行版自带的那一步迁移重跑补录：改规则前后各规划一次，只补录原先未补录、现在可以补录的产物，已登记条目不动。已经在未发版迁移步上跑过的开发实例不会重跑。
