# Editing timelines are named, multiple, current-following formal content, not artifacts

Finished videos and Jianying drafts always render from editing timelines. Episodes may have multiple timelines with stable IDs and editable display names. Create by mechanically using each current-script video unit in full, in script order with hard cuts, or by copying existing timelines; Agents/creators then edit them. Every edit appends an immutable revision recording author, change summary, and parent; writes declare their parent and reject nonlatest parents (optimistic concurrency). Rollback appends new revisions based on old ones. Export/render must specify existing timelines; episodes without timelines cannot export, without temporary read-time defaults.

**Edit clips reference video units, not pinned versions.** Always use current unit videos; choosing versions changes current, leaving one project-wide answer to "which version" shared by previews/editing/export, without second-state UI for timeline/current divergence. To avoid silent wrong trims after switching versions, clips also record which video version their in/out points target. When current differs, rendering ignores trims and uses full videos, reporting it to Agents on reads. Both rules require nonreused unit numbers: storyboard/video-unit IDs allocate only, never reuse, with per-episode high-water marks. Additions, splits, whole generation, confirmation conversion, and recycle-bin restoration all allocate beyond them, like episode IDs in `docs/adr/0096`. References to removed units never point to other content and always read as deleted; redo uses new numbers rather than version numbers to distinguish content.

**Timelines never automatically update with scripts.** Script changes are deliberate, usually contextualized in current Agent conversations: create new timelines or amend old ones. Reads report clips referencing deleted units and unused script units; rendering skips deleted references.

**Timelines are formal content, not artifacts.** Creative decisions are not paid-generated files and do not enter inventory freshness states. Rendered videos/Jianying drafts are artifacts owned by "episode + timeline + narration variant," with finished-video subtitle-burn choice additionally. Bases include only actually consumed content (timeline revision and referenced media; unnarrated variants exclude narration audio). Assess freshness on read under `docs/adr/0062`; stale remains usable without automatic rerendering.

**Move transitions from scripts to timelines.** Transitions describe adjacent episode visuals and belong to editing. Remove script `transition_to_next`, discarding existing non-hard-cut values without timeline migration. Retain script `segment_break` (scene boundary), which determines storyboard reference chains/grid grouping and is generation input, not editing. ArcReel owns transition vocabulary; each entry maps to both non-VIP Jianying presets and ffmpeg equivalents for shared output sources. Transitions never change total duration: clips adjoin, total duration sums trimmed clip durations, and windows center on cuts, half on each side. This matches Jianying's nonoverlapping same-track constraint and leaves narration/subtitle/BGM absolute positions unaffected.

## Explicitly rejected

- **Pinning clip versions with read-derived newer-version/divergence states**: protects trims precisely but creates current-versus-timeline answers for one unit, adding state for UI/Agents. One trim-basis-version field buys safety at lower cost.
- **Reusing numbers and distinguishing content by versions**: new content reuses numbers after old histories move to bins; new version numbering restarts at 1, matching old trim-basis versions. Old clips appear ready and silently apply old trims to new videos. Extra clip content fingerprints would add identity layers to every read path.
- **Read-time default timelines when absent**: produces Jianying drafts without timeline ownership and removes rendered-video ownership/freshness anchors.
- **Automatic unit-addition/deletion following**: needs exclusion lists distinguishing intentional omissions from new unused units; the system understands intent no better than conversation Agents.
- **Generic exchange formats such as OTIO as timeline models**: core subtitle/volume/transition vocabulary lacks native schemas and neither output has ready adapters; add export targets separately when needed.
- **Jianying-only stylized transitions with rendered-video dissolve fallback**: breaks shared source and makes Agent-visible effects differ from finished videos.
- **Blocking rendering/export for narration overflow**: local rendering costs nothing and Jianying drafts await human refinement; blocking only prevents creators repairing them there.
- **Automatically delaying overflowing narration or filling visuals during rendering**: makes outputs diverge from timelines, destroying sole truth.
- **Automatic BGM/native-audio ducking during narration**: commentary commonly uses fixed BGM levels; narration-linked changes sound uneven. Dynamic compression is inexpressible in Jianying drafts; narration-derived envelopes add noncreative-decision keyframes difficult to understand/refine.
- **Editing text, sentence breaks, or deleting subtitle entries on timelines**: subtitles would disagree with speech. Correct text in scripts and regenerate audio; sentence splitting/deletion are Jianying refinement.
- **Subtitle-style configuration at project/timeline/entry levels**: each setting adds mapping and Jianying test work. Styling is generative packaging outside editing; Jianying can restyle whole text tracks in bulk.

## Consequences

- Retain per-unit `SpeechPresentation` as clip material layers supplying visuals, narration, subtitle drafts, and measured duration, without transitions.
- Attach narration to only one clip per unit (first by default), starting at that clip and allowing extension across later clips, without overlap with subsequent narration or timeline-end overflow. Overflow is warning-only and never blocks rendering/export, affecting narrated variants only. Finished videos render timelines faithfully: overlapping narrations play together and over-end portions stop with videos. Jianying adds narration tracks as needed, separating conflicts without within-track overlap for refinement. Narrated subtitles follow narration; otherwise preserve source-media timing and show only portions within in/out points. Choose narration at rendering/export, not in timelines; only TTS projects may include it (`docs/adr/0089`). Finished rendering may omit burned subtitles, default on; Jianying always has subtitle tracks.
- Timeline subtitle text comes only from drafts: timelines neither edit/delete entries nor save text. Correct scripts and regenerate drafts under artifact lifecycles (`docs/adr/0062`); timelines then read new text without changes. Styles are fixed built-ins, not editing decisions; neither Agents nor creators change them. Base on existing Jianying styles, choosing size/position by frame shape; finished videos approximate without pixel-identical requirements. When subtitles overlap temporally (narration overflow or extension onto dialogue clips), libass collision handling moves later subtitles; Jianying adds nonoverlapping subtitle tracks as needed, moving each additional track upward a fixed distance. No separate overlap warning: narration-overflow/native-audio collision notices already cover causes. Reads preflight missing font glyphs and report warnings.
- BGM uses independent absolute-time tracks, one song at a time. All timeline volumes are static: native volume per clip, BGM volume/fades per BGM clip, written unchanged into render/export without ducking or derived envelopes. New clips without specified native volume default by speech ownership: lower whole voiceover-unit tracks as ambience beneath narration, retain original volume for dialogue/no-human-speech units. Normalize BGM against measured loudness at registration; default clip volumes/fades are fixed. Never rewrite existing volumes. Reads warn of possible native collisions when narration extends into dialogue or clips without lowered native volume. Like overflow, warnings affect narrated variants only; unnarrated videos/Jianying drafts mix no narration and cannot collide with it.
