# 剪辑时间线具名、可多条、跟随 current，是正式内容而不是产物

成片与剪映草稿一律从剪辑时间线渲染。一集可以有多条剪辑时间线，每条都有稳定 ID 与可改的显示名。新建时有两种来源：按当前脚本顺序、每个视频单元整段使用、全部硬切地机械生成，或复制已有的一条；此后由 Agent 或创作者在它上面剪辑。每次剪辑追加一个不可变修订，记作者、改动摘要和父修订；写入时声明基于哪个父修订，父修订已不是最新就拒绝写入（乐观并发）；回滚是基于旧修订追加新修订。导出与渲染必须指定一条已存在的剪辑时间线，没有剪辑时间线的集不能导出，也不在读取时投影出一条临时的时间线。

**剪辑片段引用视频单元，不钉视频版本。** 画面一律取视频单元的 current 视频版本，挑版本就是改 current。这样「这个视频单元用哪一版」在全项目只有一个答案，单元预览、剪辑与导出不会各说各话，界面也不必呈现「时间线用的版本与 current 不同」这类第二套状态。为了不让换版本后静默裁错画面，剪辑片段额外记下入出点是针对哪个视频版本裁的；current 已不是这一版时，渲染忽略这段裁切、整段使用，并在读取结果里告诉 Agent。整集重做后沿用同一 ID 的新内容一定是更大的版本号，同样落在这条规则里。

**剪辑时间线不随脚本变化自动更新。** 脚本变更是创作者的主动行为，上下文通常就在当前 Agent 会话里：要么新建一条剪辑时间线重剪，要么在旧的一条上补。读取剪辑时间线时报出引用了已删除视频单元的剪辑片段，以及脚本里有、这条时间线没用到的视频单元；渲染时跳过已删除的引用。

**剪辑时间线是正式内容，不是产物。** 它是创作决策，不是付费生成出来的文件，所以不进产物清单的时效四态。由它渲染出的成片与剪映草稿才是产物，归属于「集 + 剪辑时间线 + 旁白版本」，成片再加上是否烧入字幕；它们的生成依据只收录各自实际消费的内容（剪辑时间线修订与所引用的素材；不带旁白版本不含旁白配音），按 `docs/adr/0062` 的口径在读取时判定时效，stale 仍可用，不自动重新渲染。

**转场从脚本移入剪辑时间线。** 转场描述的是一集里两段画面怎么衔接，属于剪辑决策；脚本条目上的 `transition_to_next` 移除，现存的非硬切值直接丢弃，不迁移成剪辑时间线。`segment_break`（场景切换点）留在脚本里：它决定分镜图的参考图链和宫格分组，是生成输入，不是剪辑决策。转场用 ArcReel 自己的词表，每一项必须同时对应一个剪映非 VIP 预设与一个 ffmpeg 等效效果，保证成片与剪映草稿同源。转场不改变总时长：剪辑片段首尾相接，时间线总时长等于各剪辑片段裁切后时长之和，转场窗口以切点为中心、前后各占一半；这与剪映同轨片段不能重叠的约束一致，旁白、字幕与 BGM 的绝对位置也因此不受转场影响。

## 明确不采用

- **剪辑片段钉住视频版本，并在读取时派生「有更新版本」等偏离状态**：能精确保住裁切，但同一个视频单元会同时有「current」与「某条时间线用的版本」两个答案，界面和 Agent 都要多理解一层状态；用「裁切所依据的版本」一个字段换取安全，代价更小。
- **没有剪辑时间线时，按脚本读时投影一条默认时间线**：会产出不属于任何剪辑时间线的剪映草稿，成片的归属与时效也失去锚点。
- **剪辑时间线自动跟随脚本增删视频单元**：需要额外的弃用清单来区分「故意不用」与「新加的还没进来」，而系统并不比会话里的 Agent 更了解创作者的意图。
- **以 OTIO 等通用交换格式作为剪辑时间线的模型**：剪辑时间线的核心语义（字幕、音量、转场词表）在这些格式里没有原生 schema，两个输出端也都没有现成适配器；需要时作为导出目标另做。
- **允许只有剪映才有的风格化转场、成片退化为叠化**：两端不再同源，Agent 在剪辑时看到的效果与成片不一致。
- **旁白越界时阻断渲染与导出**：成片在本地渲染，不花钱，剪映草稿本来就是交给人精修的；阻断只会挡住创作者去剪映里修。
- **渲染时自动顺延越界的旁白，或自动补画面**：成片会偏离剪辑时间线，剪辑时间线就不再是唯一的真相源。
- **旁白响起时自动压低 BGM 与原声（ducking）**：解说类视频的 BGM 惯用固定音量，随旁白起落反而显得忽大忽小；动态压缩在剪映草稿里无法表达，按旁白区间派生的音量包络则会在剪映草稿里多出一套不属于剪辑决策的关键帧，精修时难以理解和修改。
- **在剪辑时间线上改字、断句或删条字幕**：字幕会与旁白配音、台词说的不再是同一句话；改字本来就该回脚本，配音随之重新生成。断句与删条属于精修，交给剪映。
- **开放字幕样式配置（项目级、剪辑时间线级或逐条）**：每开放一项，两端的映射与剪映实测就多一份；样式包装属于生成式包装，不在剪辑范围内，剪映里可以对整条文本轨批量改样式。

## Consequences

- 逐视频单元的呈现模型（`SpeechPresentation`）保留，作为剪辑片段的素材层，提供画面、旁白、字幕草稿与实测时长；它不再携带转场。
- 旁白只挂在该视频单元的一个剪辑片段上（默认第一个），从这个剪辑片段的起点播放，可以延伸到后续剪辑片段上，但不应与下一段旁白重叠，也不应超出时间线末尾。越界是警告级问题，不阻断渲染与导出，只影响带旁白版本：成片如实按剪辑时间线渲染，重叠处两段旁白同时响起，超出末尾的部分随成片结束截止；剪映草稿按需要增加旁白轨，把冲突的旁白分开放，保证每条轨内不重叠，交给剪映精修。字幕在带旁白版本里跟随旁白，否则按源素材时间保留、只显示落在入出点之内的部分。带不带旁白是渲染与导出时的选择，不写进剪辑时间线；只有 TTS 项目可以选带旁白（`docs/adr/0089`）。成片渲染时同样可以选择不烧入字幕，默认烧入；剪映草稿始终带字幕轨。
- 剪辑时间线上的字幕文字只来自字幕草稿：剪辑时间线不改字、不删条，也不保存字幕文字；纠错回脚本，字幕草稿按产物生命周期重新生成后（`docs/adr/0062`），剪辑时间线取到的就是新文字，自身无需修改。字幕样式固定内置，不属于剪辑决策，Agent 与创作者都不能改：以剪映现有样式为基线，按画幅取位置与字号，成片尽量贴近，不要求两端逐像素一致。字幕在时间上重叠时（旁白越界，或旁白延伸到有台词的片段上），成片交给 libass 的碰撞处理把后一条推开；剪映草稿按需要增加字幕轨，保证每条轨内不重叠，新增的轨道整体上移一个固定距离。重叠不单独报出，引起它的旁白越界与原声相撞提示已经覆盖。读取结果按字幕字体预检缺字，作为警告报出。
- BGM 以独立音轨放在剪辑时间线上，按绝对时间摆放，同一时刻只有一首。剪辑时间线上的音量一律是静态值：剪辑片段带原声音量，BGM 片段带音量与淡入淡出，渲染与导出原样写入，不做避让，也不派生音量包络。新建剪辑片段时未指定原声音量的，按发声归属取默认值：画外音单位整轨压低，作为旁白下的环境声垫底，台词与无人声单位保持原音量。BGM 登记时按实测响度折算到统一基准，BGM 片段的默认音量与淡入淡出取固定值。系统不改写已有片段的音量。旁白延伸到台词片段或原声未压低的片段上时，读取结果提示可能与原声相撞。
