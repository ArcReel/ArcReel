# 移除分镜的产物进项目回收站：不硬删，也不留为不可见文件

分镜从正式脚本消失只有一个出口：`lib/artifact_activation.py` 的 `prepare_episode_script_manifest_commit` 在正式写入事务内撤销该分镜名下的清单登记。提示词编写装配、机械转换、Agent `patch_episode_script` 的 remove 操作与参考生视频画布的「删除单元」全部经过它。撤登记之后文件原地保留：产物清单是唯一口径（`docs/adr/0062`），不在清单里的文件对系统不可见，用户既看不到也无法释放空间。当初「删条目不删文件」是因为删分镜是内容编辑的副作用，自动删文件会在一次编辑里销毁已付费产物；这条理由成立，但结论不该是「永远留着」。

决定：分镜被移除时，其名下文件进入**项目回收站**（术语见 `CONTEXT.md`「回收站」「回收件」）。

- **唯一挂接点**是上述清单提交的 `commit` 闭包，与撤登记同一个正式写入事务。不在各调用方分别处理，因此凡经这个口移除的分镜一视同仁，包括 PATCH 与删除单元。
- **回收范围**：分镜图、视频、旁白音频的当前文件，连同它们在 `versions/` 下的全部快照与 `versions.json` 里的记录片段；视频缩略图作为视频件的附件；尾帧图（用户上传的意图，不是产物，但不可再生）单独成件。字幕与演示物是从视频与音频派生的 JSON、不花钱，直接删除。磁盘上不存在的文件跳过，不建回收件。
- **回收件粒度**是（分镜 id，文件种类）：一件含全部版本与附件，下载给一个保留原相对路径的 zip 并附版本记录片段；删除与清空整件一起走。
- **落盘在项目私有区**的隐藏目录：索引 sidecar + 文件目录，与项目元数据锁同级写入。索引是权威：条目文件丢失则列表时剔除，索引外文件不列出、清空时随目录一并清掉。隐藏目录天然不进归档、不进 `DataValidator`，归档永远不带回收站。
- **失败即回滚**：任一文件移动或索引写入失败，整笔脚本提交回滚、不装配。回收站的承诺是「不再产生不可见文件」，尽力而为会让承诺失效。
- **仅 REST**：列出、下载、单删、清空，加总占用；不做 MCP / Agent 工具。
- **内容确认框**在有将被移除且有文件的分镜时列出它们，数据由 `GET script-review` 按清单过滤后给出，drama / narration 与 reference_video 两个变体都显示。
- 索引每件记原分镜 id、集号、种类、原相对路径、进入时间、大小、来源路径（提示词编写 / 机械转换 / PATCH）；不记触发者。
- 不提供恢复；存量已成孤儿的文件不补录。

## 明确不采用

- **移除即硬删**：删分镜是内容编辑的副作用，用户不一定意识到会销毁已付费产物；Lightroom 的「从磁盘删除」也要单独问一次。
- **维持现状（文件不删、清单不登记）**：文件对系统不可见，唯一的出路是用户手动进目录找，违背「产物是否存在一律问清单」的口径。
- **尽力而为、移动失败只记日志**：角色衍生清理这么做是因为它本来就是删除动作；回收站是保全动作，保全失败必须暴露。
- **给 Agent 开回收站工具**：回收站是用户释放空间的入口，不是创作动作；Agent 不需要也不应该清空用户的付费产物。
- **扫目录把存量孤儿补进回收站**：与 ADR 0062「不扫目录」正面冲突，且无从知道它们属于哪次移除；若要做另立议题。
- **归档可选带上回收站**：恢复不在范围内，导出回收站没有消费方；放在隐藏目录零改动即可满足不进归档。
- **按物理文件计件**：一条分镜的三个版本分镜图在列表里变成三行，与「删了一条分镜」这个动作不对应。

## Consequences

- 项目目录会多出一块只增不减的占用，且不自动过期；用户要自己去项目设置页清理。回收站总占用在设置页可见。
- 版本记录随分镜切走后，`versions.json` 里该资源的条目消失；同一分镜 id 日后重新生成从 v1 起，与它在回收站里的旧版本互不相干。
- 索引外文件只有清空能删。回收站目录是受控区，索引外文件只可能是崩溃残留，不为它做 UI。
- 正式写入事务需要为文件移动补偿：`formal_write_transaction` 目前只做字节快照回滚，文件移动的反向操作要由回收站模块自己在事务失败时执行。
- 手动放回：zip 内保留原相对路径，用户解压到项目目录再重投影清单即可让文件重新可见，这是「不提供恢复」下的人工出路。
- ADR 0041 与 0062 中「删掉的条目文件不删」的表述改为引用本 ADR。
