# 消息改写从历史用户消息处分叉

消息改写从指定用户消息发出前的状态开始。应用层会将该消息之前的 transcript 前缀连同子智能体历史复制到新会话中，交由 SDK 按新会话 ID 恢复，再发送改写后的消息。前缀内的消息 UUID 保持不变，由新会话 ID 提供独立的命名空间。分叉点仅限于主线用户消息，且排除存在未决问答或会切断工具调用与回执配对的位置。

SDK 原生分叉在决策时会丢弃子智能体历史并重分配消息身份。原地删改历史则会破坏 [事件日志](0048-session-event-log-single-ui-read-source.md) 的追加与续传语义。应用层分叉保留原会话和前缀身份，代价是由应用协调 transcript、元数据和恢复。

## 身份与发布

- 编辑锚点来自 UI 事件日志，切分使用 transcript 身份。活跃会话用映射解析提前分配的用户消息 UUID，历史条目可沿用同名 UUID。找不到有效锚点时明确失败。校验由 [事件日志服务](../../server/agent_runtime/event_log.py) 与 [前缀分叉服务](../../server/agent_runtime/session_branch.py) 承担。
- 发布分别写入新 transcript、新会话元数据以及原会话的替换指针。写入跨存储边界，失败由服务做补偿。条件更新防止两个分叉同时取代同一会话。
- 替换指针服务界面时间线的可见性，删除分支时可接续至其后继。分叉父会话和锚点独立记录，保持原有历史关系。改写只改变会话上下文，已发生的文件写入、任务和费用继续有效。
