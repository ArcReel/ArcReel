# Consolidate built-in backend construction into a declarative table, symmetric with but separate from custom endpoints

Before this decision, built-in backend construction (provider config + resolved model → constructor kwargs) duplicated imperative `if gemini / elif kling / else` in `_get_or_create_video_backend` / `_get_or_create_image_backend` / `_get_or_create_audio_backend` in `server/services/tasks/generation_tasks.py`, plus `lib/backends/text_backends/factory.py` (these functions now reside in `server/services/tasks/generation_context.py`, delegating to `lib/backends/backend_assembly` under this decision). Provider knowledge leaked into callers: gemini `aistudio|vertex`, Kling dual-secret JWT + `api_model_name`, base_url precedence, and dashscope/minimax OpenAI-compatible text. Two `PROVIDER_ID_TO_BACKEND` maps already drifted: text treated dashscope/minimax as `openai`, media did not. Custom providers already used a deep declarative `ENDPOINT_REGISTRY` in `lib/custom_provider/endpoints.py`, each `EndpointSpec` holding `build_backend`, with two-line `factory.py` forwarding. These parallel approaches are the shallow duplication to eliminate.

Raise built-ins to the same level through one "provider config + model → backend" seam: ① create `lib/backends/backend_assembly/` (in lib because the seam spans both families and lib cannot import server), exposing `assemble_backend(provider_id, media_type, model_id, ...)`, internally dispatching by `is_custom_provider` to family adapters; ② create built-in `(provider_id, media_type) → ProviderSpec` tables with build closures, matching custom `EndpointSpec`; ③ split **async loading** (DB/config → `LoadedConfig`: credential overlay + `PROVIDER_REGISTRY` metadata + shared rate_limiter) from **sync construction** (pure closures assembling backends from envelopes), making the synchronous deep core testable without DB; ④ leave custom `ENDPOINT_REGISTRY` unchanged, move `_create_custom_backend` DB loading from server to lib, and consolidate text factory's inline duplicate.

**Explicitly rejected**: ① **One table for both families**: fundamentally different credentials (custom fixed `api_key`+`base_url`, `docs/adr/0008`; built-in multi-secret typed columns, `docs/adr/0037`), while `EndpointSpec` holds frontend catalog fields (video caps, request paths, display names) unnecessary for built-ins. Merging loses types or adds `Any`. Share `assemble_backend`, not table structures: one door, two symmetric rooms. ② **Unified `BackendRequest` input value objects** flattening both shapes to force single-argument entry: no second consumer, only signature-aligning glue. The deletion test shows removing it would not recreate complexity in callers already branching at `is_custom_provider`; it also forces deliberately separate 0008/0037 credentials together. Built-in builders accept `LoadedConfig`, custom builders `CustomProvider`. ③ **Pure declarative data specs for built-in construction** (credential mapping + base_url enums instead of closures): this seam differs from protocol expression. Declarative endpoints (`docs/adr/0067`) express HTTP requests/responses; here loading/assembly builds constructor kwargs with gemini modes, Kling secrets, and `api_model_name`. Pure data overconfigures roughly 11 providers and still needs closure escape hatches. Closures match custom `EndpointSpec` and `docs/adr/0009`'s `kind` pricing dispatch. ④ **Default-if-absent simple providers** (generic closures when no specs): silently turns mistyped `provider_id` into backends. Explicitly register every simple provider row sharing builders, failing loudly with complete visible tables at one-row cost.

## Consequences

- **New built-ins shrink from four files/five sites to one row**: simple providers add `ProviderSpec`; exceptional ones add a row + build closure, symmetric with custom `EndpointSpec`. Do not touch `generation_context.py`'s three `_get_or_create_*` methods or text factories.
- **Merge duplicate `PROVIDER_ID_TO_BACKEND`** into `ProviderSpec`'s registry field (each `(provider, media)` row declares its registry backend), structurally eliminating drift.
- **Test construction without DB**: build `LoadedConfig` + model_id and assert constructor parameters (Kling secrets, gemini `backend_type`, dashscope text base_url derivation, Kling `api_model_name`), without DB/resolver mocks; async loading uses substitutable in-memory DB tests. Validate built-in tables in two tiers: callable `build`, unique `(provider, media)`, and similar internal consistency fail fast at import (like equally lightweight `endpoints.py::_validate_video_caps_declarations`). Checking `registry` names against media registries requires importing all `lib.{image,video,text}_backends`, so do it in unit tests rather than making lightweight CLI/migration imports load all backends.
- **Keep caches with callers**: `_backend_cache` is server-execution performance, not seam responsibility. Stateless pure construction aids concurrency/tests.
- **Scope**: only backend-instance construction, not task execution, queue scheduling, billing, or lifecycles. `provider_job_id` persistence (`docs/adr/0007`), queues (`docs/adr/0010`), and pricing (`docs/adr/0009`) remain outside.
- **Orthogonal to future plugin markets**: third-party sharing/installation is a separate custom-side `ENDPOINT_REGISTRY` epic (`docs/adr/0008` permits plugin `api_key`+`base_url` only unless built-in-style declarations support multiple fields). This ADR consolidates **built-ins**; family isolation preserves clean extension slots without expanding current scope.
- **Change gate**: subsequent table merging, unified `BackendRequest`, or returning built-in construction to scattered imperative branches requires deprecating this ADR first.
