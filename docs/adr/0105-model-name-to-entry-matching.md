# 模型名对应条目只做名字归一化，日期快照靠模型别名；对应不上的供应商模型不关联条目，模型事实在运行时回落

自定义供应商的模型发现只返回模型 ID，Agent 凭证上也只有模型名，两者都要对应到模型条目才能取到价格与模型事实。中转站的命名五花八门：加命名空间前缀、用点号写版本、改大小写，甚至另起名字，所以对应不上的情况很常见。我们决定只在客户端做不改变模型身份的名字归一化，带日期的快照是否属于同一个模型交给目录数据里的模型别名表达；对应不上的模型照常可用，只是没有条目，模型事实在运行时按名字回落，不把猜测写进任何数据。

## 规则

- 模型名与条目的官方模型名、模型别名比较，比较前做三步归一化：忽略大小写；去掉最后一个 `/` 及之前的命名空间；点号视同连字符。精确命中优先于归一化命中。不去掉日期后缀，也不去掉 `:free`、`-thinking`、`-preview` 这类后缀。
- 自定义供应商的「获取模型」、自定义供应商按 ID 手动添加、Agent 凭证的档位匹配，共用这一条规则。内置供应商按其清单中的 API 模型名精确匹配（见 `docs/adr/0099`）。
- 一个模型名命中多个条目时（两栖模型），按名字推断的媒体类型取其中一条，用户可以改关联。
- 模型别名只随出厂快照与官方同步下发，用户不编辑。用户确定的对应关系记在自定义供应商下供应商模型的条目引用上，或 Agent 凭证的绑定上，不修改条目，因此不会关闭条目的官方同步。
- 自定义供应商的模型发现为每个模型给出默认调用端点。对应上条目的模型，媒体类型取条目，在这个媒体类型内按名字族选端点，选不到时取该媒体类型在当前模型发现协议下的默认端点；对应不上的模型，按名字同时推断媒体类型与端点。获取时可以逐个修改。
- 对应不上的模型可以添加，成为不关联条目的供应商模型，媒体类型取其调用端点，费用记为未定价。它的模型事实在运行时回落：可选时长取按名字推断的时长预设，其余维度不加约束，超出范围时由上游拒绝（见 `docs/adr/0018`）。回落结果不写入能力覆盖或其他字段；用户自己设置的能力覆盖照常优先。
- 官方同步带来的条目或模型别名能命中不关联条目的供应商模型时，自动关联上。已关联条目的供应商模型不受影响，包括用户手动关联的。
- 调用通道按名字族认定通道能力时，名字取供应商模型所关联条目的官方模型名与模型别名；没有关联条目时取 API 模型名（见 `docs/adr/0104`）。

## Considered Options

- **在客户端去掉日期后缀**：能多命中一些中转站上的快照名。但同名不同日期的快照可能价格不同，例如 `gpt-4o-2024-05-13` 与 `gpt-4o`，去掉后缀会把费用静默算成另一个价格。哪些快照与主名是同一个模型，属于数据事实，由目录数据仓库生成模型别名表达。
- **只做精确匹配**：规则最简单，但中转站普遍带命名空间前缀或用点号写版本，命中率太低，大部分模型都要用户手动关联。
- **命中多个条目时让用户逐个选择**：目前只有一个两栖模型会命中多个条目，为它设计候选选择不划算，添加后改关联即可。
- **默认端点参考同一供应商同一媒体类型最常用的端点**：中转站可能同时以 `ark-seedance` 转发 Seedance、以 `kling-video` 转发可灵，按媒体类型统计会把后者带到错误的端点上。改为参考同一模型厂商的已有模型，又会成为用户看不出缘由的隐式规则，不如逐个修改直观。
- **添加时把按名字推断的时长写进能力覆盖**：用户会看到一组自己没设过的覆盖值；日后关联到条目时，也分不清哪些值是推断的、哪些是用户改过的。
- **为对应不上的模型自动新建用户条目**：条目的身份需要模型厂商，对应不上时并不知道；每添加一个这样的模型，目录里就多一个用户条目。
- **允许用户给条目补模型别名**：在官方条目上补别名会关闭它的官方同步；用户的对应关系已经有地方记录。

## Consequences

- 命中率取决于目录数据仓库生成的模型别名，包括价格相同的日期快照名与中转站的常见命名（见 `docs/adr/0103`）。
- 中转站给已知模型改了名时，用户关联一次条目，价格、模型事实与通道能力就都按这个模型取得。
