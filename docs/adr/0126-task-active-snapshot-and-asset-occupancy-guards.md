# 任务活跃快照与项目资产并发占用边界

任务活跃占用与最近任务分页分离。最近任务分页仅服务历史展示、常规失败通知与单资源最新结果，不作为任务仍在运行的权威依据。活跃任务通过独立快照端点单次查询返回当前可见范围内全部处于 `queued` 或 `running` 状态的生成任务，不走 `OFFSET` 翻页以免任务动态完成导致跳漏；触发安全上限时显式返回 `truncated` 标志，前端据此保持保守而不解除既有占用或卸下乐观标记。需读取终态结果的业务（音色试听、资产图批次、提示词编写空操作监听与乐观提交交接期）经按 ID 批量查询端点显式跟踪，响应将不存在或超出可见范围的任务归入 `missing_ids`，供消费方明确结束等待；不做全量消失任务的隐式补查，也不跨浏览器刷新持久化批次汇总通知。前端任务 store 以单行表保存每个任务的最新行，按服务端高精度 `updated_at`（同时间戳按 `queued < running < terminal` 裁决）合并，既防乱序旧快照覆盖新终态，也兼容「重试下载」把失败任务原地改回 `running` 的路径，见 [ADR 0123](0123-provider-submission-and-retrieval-retry-boundaries.md)。项目事件流断线重连后经既有单飞入口补拉同步，见 [ADR 0122](0122-active-project-snapshot-refresh-has-one-entry.md)。

长文本队列任务的运行期进展采用进程内轻量内存态表达，不写入数据库任务表，进程重启后允许丢失。鉴于 `GenerationWorker` 与 FastAPI 固定同进程运行，Worker 仅维护三个真实可观测的运行态：`waiting`（等待模型响应）、`receiving`（正在接收模型生成内容，附已接收正文字符数；仅收到思考增量且正文为空时展示思考状态）与 `retrying`（明确可重试错误触发的第 N/M 次重试），严禁伪造完成百分比、预计剩余时间或假业务阶段。运行态切换与节流后的接收增量经项目事件流上的独立轻量 `task_progress` 事件推送（携带任务内单调递增序号 `seq`，不走普通任务变更分支、不触发全量任务刷新），前端在独立映射中按 `seq` 单调合并，仅对当前 `running` 任务生效并在终态立即清除，避免被 `updated_at` 相同的历史页或旧快照覆盖。活跃任务快照端点返回活跃行时附带当前内存进展，用于页面刷新或 SSE 断线重连后的即时补齐；未订阅项目 SSE 的跨项目全局用量浮窗沿用既有快照刷新。该机制仅覆盖经 Worker 队列执行的文本任务，不覆盖同步等待返回的 HTTP 短接口。

前端入队动作承担网络往返期的乐观占用标记边界（见[生成入队动作](../../frontend/src/actions/generation.ts)与[出片入队动作](../../frontend/src/actions/render.ts)）。调用方在发出请求前已确定目标资源或脚本文件身份时，先为本次提交分配独立标记，把在途占用提前反映给所有订阅者；并发提交各自持有独立标记，单次失败只回滚自身。请求发出、响应中任务 ID 提取与标记兑现置于同一异常保护范围内：请求失败或解包抛错时回滚全部预打标记；响应未返回任务 ID 时立即释放标记，防止无对应任务行的标记滞留；返回多个任务 ID 的标记按各任务 ID 逐个交接。对于目标集合由服务端筛选的批量入口（如整集旁白、分镜路线的分镜图与视频批次 `enqueueStoryboardBatch`、资产图批次），调用方不在请求前预先标记候选资源，而是在响应返回已入队资源与任务 ID 的对应关系后逐项补标并认领，未入队或被跳过的项不打标；参考生视频批次 `enqueueReferenceVideoBatch` 则按调用方是否指定 `unit_ids` 区分：已给出 `unit_ids` 时在请求前逐项预标，准入后按 `task_ids_by_unit` 交接并释放未获任务 ID 或未准入的标记，未给 `unit_ids` 时既不预标也不在响应后逐项补标；同一动作也可同时使用脚本文件级预打标与响应后的资源级补标（如多宫格分镜生成）。成片渲染与剪映草稿导出走本地 `render` 车道，不占用可编辑项目资源槽，不打资源乐观占用标记。前端乐观标记仅作为界面占用提示，并发准入与实际去重仍由服务端裁决。

项目资产的生成入队与写操作共享按 `(project_name, asset_type, NFC 归一化本体名)` 计算的准入锁临界区。角色衍生锁键归属所属角色本体，以串行协调本体与衍生操作；资产合并等双资产操作按确定性字典序依次取锁，避免死锁。所有资产入队路径（Web 路由、批量提交与 Agent 工具）在锁内重新确认宿主存在并入队；全部受保护资产写边界（全局资产库双向同步、手动上传、供应商素材导入、版本恢复、资产及衍生的删除、资产重命名、资产合并、参考音频变更，以及触及资产图或参考音频字段的通用更新）在同一锁内先复核活跃任务冲突，再执行读写，避免查完空闲后并发入队的窗口。资产写冲突查询面向同一项目文件的全部写者，不按 `user_id` 过滤，并对资产名及衍生两段统一执行 NFC 归一化。

前后端共用四维资产忙碌矩阵：`image` 覆盖资产本体生成与 `image_edit`（角色额外含其全部衍生）；`derivative_image` 覆盖单条衍生自身与所属角色本体，不阻塞同一角色的兄弟衍生；`voice` 仅覆盖角色音色试听；`whole_asset` 取 `image` 与 `voice` 并集，用于资产删除、资产重命名、资产合并及全局资产库覆盖回项目等整资产操作。角色资产图与音色试听分槽并行，未确认的音色试听仅写独立预览音频，不阻塞项目资产导出全局资产库。所有 `dry_run` 预览及仅修改描述或资产别名的更新豁免占用校验。相关决定见 [ADR 0006](0006-cancel-only-queued-tasks.md)、[ADR 0057](0057-asset-name-as-identity-cascade-rename.md) 与 [ADR 0072](0072-character-derivative-sub-identity.md)。
