# Agent project-JSON edits use in-process MCP; deny raw Write/Edit/Bash

Agents previously wrote `scripts/*.json` and `project.json` directly through `Write`/`Edit` or Bash `echo>`/`sed`/`python -c`, guarded only by PreToolUse **JSON syntax** hooks. Structural errors (out-of-range `duration_seconds`, missing `image_prompt`, inconsistent `ReferenceVideoUnit` shots↔duration) persisted, bypassing `_write_script_unlocked` (ADR-0002) and invalidating its single guard. Route all Agent project-JSON writes through in-process MCP, **forbidding** raw byte writes outside tools so structural validation has one actual enforcement point.

Tools (all in-process MCP `arcreel`, inside server processes, outside agent sandboxes):

- `get_episode_script` + `patch_episode_script`: read bodies/canonical JSON `sha256-v1` revisions, then submit `{script, base_revision, operations[]}`. Ordered `update` / `insert` / `remove` / `split` discriminated operations locate `segment_id` / `scene_id` / `unit_id` / `shot_id` across modes. Under project locks, recheck revisions, apply whole batches to in-memory candidates, then preflight structure, project references, applicable Artifact Manifest bases, and SpeechComposition. Any failure returns stable `code`, `operation_index`, unit/field locations, and `next_action`, with zero writes.
- `insert` / `split` perform structural projection through `patch_episode_script` within the same batch transaction. **Stable IDs never reorder**; allocate beyond episode high-water marks without reuse (`docs/adr/0090`): narration/drama segments/scenes use `E{集}S{序号}`, reference units `E{集}U{序号}`; legacy split children may have `_{子序号}`. Split first parts retain IDs and `generated_assets` / `end_frame_image`; other new identities clear assets.
- `patch_project`: add/update `project.json` by table/name, **replacing** deleted `add_assets.py`; `analyze-assets` calls this tool, eliminating fragile single-line CLI JSON.
- `generate_episode_script`: whole-episode generation **writes through `_write_script_unlocked`**, replacing `ScriptGenerator`'s raw `json.dump`.

Two-layer enforcement:

- **Bash subprocesses (Linux/macOS, kernel-level)**: `sandbox.filesystem.denyWrite` covers `scripts/` and `project.json`. [Claude Code OS-level enforcement](https://code.claude.com/docs/en/sandboxing#os-level-enforcement) specifies Seatbelt/bwrap enforcement for **every sandbox subprocess, including Bash children**, closing `echo>`/`sed`/`python -c` bypasses. Choose `denyWrite`, documented alongside `denyRead` in `filesystem` passthrough, rather than relying on undocumented SDK translation of Edit allow/deny into Bash filesystem profiles.
- **Built-in Write/Edit (all platforms)**: these use permissions, not sandboxes; `_check_write_access` rejects `scripts/*.json` + `project.json`, sharing the same paths as denyWrite for double enforcement.
- Funnel all script writes through `_write_script_unlocked`. Outer deep `ScriptBatchEditor` performs OCC/candidate preflight in one project/script critical section and compensatably commits script, project episode index, and applicable episode-script Manifest entries. Later failures restore script/project bytes before unlock; Manifest hooks restore old entries. Underlying writes retain ADR-0002 no-worse compatibility, but batches require full candidate structure/reference preflight; only unchanged legacy speech blockers may leave unrelated edits unblocked.

## Consequences

- In-process MCP executes in servers, **outside agent sandboxes**, so filesystem denials do not block legitimate tools. After removing `add_assets.py`, **no legitimate sandbox Bash writes `scripts/*.json`/`project.json`** (`split_episode` writes `source/`, compose writes videos); kernel denial causes no collateral damage.
- **Unsandboxed fallback** (Windows or failed Linux bwrap probing): use `_check_write_access` Write/Edit denial plus existing `_WINDOWS_BASH_PREFIX_WHITELIST` (`python .claude/skills/`, ffmpeg, ffprobe; arbitrary `echo>`/`sed`/`python -c` already excluded). Verified post-`add_assets.py` removal: allowed `python .claude/skills/` scripts never write `scripts/*.json`/`project.json` (split writes `source/`, compose videos, peek reads), requiring no extra fallback defenses.
- **Kernel denyWrite validation**: `denyWrite` shares `denyRead`'s `filesystem` passthrough (already protecting `.env` in production). SDK documents kernel enforcement on Bash children; unit tests in `server/agent_runtime/agent_access_policy.py` cover compiled dual-denial configuration/predicates. Actual kernel denial relies on SDK promises, without live smoke tests: enabled-sandbox validation should reject Bash `echo > scripts/x.json` while MCP writes succeed.
- **Editing never deletes existing media or rewrites `generated_assets`**. Prompt changes retain media until explicit regeneration; remove only removes script references, retaining files. Same-ID split anchors retain assets; new IDs clear them. Manifest freshness derives from read-time basis comparison, never persisted stale script flags.
- **Register only formal direct inputs for structured bases**: narration/drama, including reference_video, use canonical script_plan for episode-script bases when present, without registration otherwise. Ad lacks canonical plans; never construct self-referential bases from edited scripts themselves.
- Tool **return text** is agent-facing/i18n-exempt; **display names** are user-facing, registered in `ARCREEL_MCP_TOOL_IDS` with trilingual `tool_name_<id>` (zh/en/vi).
- Implements ADR-0002's Agent raw-write consolidation. Reference structures operate on top-level `video_units`; `duration_seconds` is independent orchestration, not member-shot sums. Validation/editing/metadata share `script_editor.resolve_items`.

## Limit no-worse semantics to their boundaries (post-#604 root-cause iteration)

PR #608 implemented tools atop ADR-0002, but repeated reviews found `「不更坏」从一个具体策略悄悄泛化成了「宽容氛围」`: a specific no-worse strategy became generalized tolerance. Helpers, reads, cross-episode synchronization, and allowlists adopted dirty-data degradation outside write chokepoints, producing silent no-ops/overwrites. Fix boundaries explicitly:

- **No-worse exists only at two chokepoints**: `_guard_no_worse` in script writer `_write_script_unlocked` (structure through `_select_model` + Pydantic ValidationError); error-set diffs inside `upsert_assets`' `_mutate` (project.json through `DataValidator.validate_project_payload` errors). All other helpers/callers **must not** invent local dirty-data policies.
- **Fail loudly everywhere outside**: `resolve_items` raises `ScriptEditError` for present nonlist arrays (already); `batch_update_scene_assets` raises `KeyError` on missing IDs (this PR); `_write_script_unlocked` metadata treats `duration_seconds=None` as absent rather than crashing; `get_storyboard_items` uses `resolve_items` to align dirty-data errors instead of generic TypeError from `list(None)`.
- **Degradation is explicit caller choice**: narrow `versions.py::_sync_storyboard_metadata` from `except Exception` to `except ScriptEditError` + episode-bearing warnings + continue, making cross-episode degradation observable; unexpected exceptions propagate as router 5xx. `_resolve_items_or_warn` already warns on dirty data; missing keys return `[]` silently because empty drafts are valid initial states. **No zero-signal success**: every degradation needs warnings.
- **Explicit feedback replaces allowlist silent drops**: `upsert_assets` returns diagnostics (added / merged / dropped_fields / dropped_legacy); `patch_project` tells Agents excluded reference_image/sheet_field fields were ignored and historical type/importance fields deprecated, preventing repeated attempts. `analyze-assets` prompts strictly skip existing assets, filtering before patch_project, removing contradictory "do not overwrite"/"may revise" wording.
- **Editing routes by actual shape**: forensic `lib/script/script_skeleton.resolve_script_kind` uses top-level `video_units` / `segments` / `scenes` / `shots` presence plus `content_mode`, ignoring declared generation routes. Editors answer actual script shape; route-based editing would make mismatched legacy episodes unreachable through every MCP tool, leaving unexplained missing-ID errors. Generation instead follows project routes and gates Agent enqueue/validation mismatches (`docs/adr/0045`, `docs/adr/0055`), so these episodes remain readable/editable/archive-exportable (Jianying canonical content_mode skeletons cannot obtain completed clips), only unavailable to Agent generation.
- **Tool boundaries**: `patch_episode_script`'s `_set_nested` **permits absent leaf writes** (Agents can fill LLM-omitted optional `video_prompt.note`, without remove/insert whole-episode regeneration), but absent intermediate parents fail loudly against typos. `split` preserves anchor `parts[0]`'s `generated_assets`, matching `insert` anchor semantics so using split as insert no longer loses generated assets.

Cross-cutting principle: **enumerate the decision matrix before fail-loud changes** (read/write × missing/dirty keys × validate/no-validate), deciding every cell. Do not push structure-layer before/after no-worse logic into helpers without before/after concepts (metadata, lookup, exception handling); dirty-data degradation there is explicit caller responsibility, never helper defaults.
