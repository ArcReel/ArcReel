> "Dialogue and voiceover may interleave within one scene" is superseded by `docs/adr/0089`: they cannot coexist; mixtures block generation, and voiceovers use narration dubbing or post-production dubbing. "Finished-video subtitles estimate duration by speech rate and allow gaps" is also superseded by `docs/adr/0089`: sentence-split subtitle drafts are sequenced proportionally by reading units inside outer bounds, without speech-rate timing. This ADR's ordered utterances as sole spoken-content truth, `source_text`, and one-way spoken-volume duration constraints remain valid.

# Drama spoken content becomes ordered utterances, replacing separate dialogue/voiceover fields

Unify drama spoken content (character dialogue + voiceovers) into one **scene-level ordered discriminated-union list**, `scene.utterances: list[Utterance]`, each `Utterance{kind: "dialogue"|"voiceover", speaker: str|None, text: str}`. Insertion order is temporal order (dialogue/voiceover sequence within scenes); `kind` routes downstream (dialogue enters video YAML for provider lip-sync audio, voiceover stays outside video prompts for subtitles/future TTS; the distinction is attribution to a specific speaking character, with voiceover only unattributed narration/commentary). Utterances hold the sole spoken-content truth (`dialogue` is not nested in `video_prompt`). This unified sequence underpins three consumers: finished subtitles derive from it, scene spoken-volume duration constraints estimate from it, and structured script_plan output targets it. Multiple unordered fields leave subtitles without one source, lose cross-type order, decouple speaking volume/duration, and force novel narration into visuals with distortion. Accompanying decisions: permit novel-source voiceover sparingly (prompts supply contextual creative judgment, not rules/category allowlists or a fallback characterization; screenplays extract verbatim); scene-level `source_text` (verbatim excerpts like narration `novel_text`, but traceability anchors only, never read aloud) supports human review, single-scene regeneration, and distortion diagnosis; derive `subtitle_spans` for Jianying from utterances (speech-rate-estimated durations, sequential placement, gaps allowed, no forced scene filling); impose **one-way duration constraints** (dialogue pushes durations up, never down): save-time estimates above duration warn without blocking; generation-time script_plan guidance asks models to select tiers no shorter than estimated speech, leaving duration visually driven without mechanical rewriting.

## Considered Options

- **Retaining 0036's two fields and adding cross-type ordering (indexes/order references)**: smaller changes and unchanged video YAML, but speech remains split, LLMs must maintain consistency across structures, and subtitle/duration/structured consumers each combine two sources; ordering is bolted on, not sole truth.
- **Implicit discrimination by speaker presence (speaker=None means voiceover)**: saves a field, but null-based semantics are obscure and easily confused with empty strings; LLM structured output is unstable without explicit enums. Use explicit `kind`, matching existing `ReferenceResource.type` / `AdUnitReference.type` discrimination.
- **Always-empty voiceovers for novels**: preserves drama's "perform rather than narrate" purity, but unperformable narrative passages in drama projects can only be distorted into visuals. Sparse permission with contextual LLM judgment better fits reality.

## Consequences

- `lib/script/script_models.py`: `DramaScene` spoken content is `utterances` (`Utterance{kind, speaker, text}`, validating `kind ⇄ speaker`: dialogue⇒nonempty speaker, voiceover⇒speaker None), plus scene-level `source_text`. Generic-extra speakers (`老人甲`) keep source labels without entering characters_in_scene or mechanical checks. Retain `VideoPrompt.dialogue` only if narration / ad consume it: otherwise remove it from shared models; if consumed, use a dialogue-free drama variant.
- Existing data uses read-time migration (`model_validator(before)`, like `LEGACY_DROPPED_FIELDS`): merge old `video_prompt.dialogue` + `voiceover` into `utterances` and strip old fields (so `extra="forbid"` + "no worse" guards do not error). Old data lacks interleaving information and mixed scenes are rare; merge deterministic best-effort (dialogue first, voiceover afterward), without claiming reconstruction.
- `lib/project/data_validator.py`: validate utterance structure, `kind ⇄ speaker`, and `source_text`; add **warning** for "estimated speaking duration > duration × tolerance" (following ad-duration drift's warn-only policy). Speech rate has a configurable single truth (language-dependent with project overrides), shared with subtitles instead of hardcoded.
- Spoken-volume duration is a **one-way constraint with symmetric direction**. Both consumers use one speech-rate source (`lib/speech/speech_rate.py`; precedence: project override > `source_language` default > global default, layered only there, without consumers independently reading project.json). Save time uses a **one-way upper-bound warning** (above; `lib/project/data_validator.py` warns beyond tolerance without blocking/rewriting). Generation uses **one-way lower-bound soft guidance** (`lib/prompts/prompt_builders_script.py` drama script_plan duration prompts request tiers **not below** each scene's estimated utterance duration; above maximum tier, choose maximum and rely on save warnings). Both only push duration up, never down: visuals/gaps can exceed the minimum, no mechanical logic rewrites model-selected duration, preserving "visually driven, gaps allowed."
- `server/services/presentation/jianying_draft_service.py`: register drama as a subtitle mode, deriving `subtitle_spans` from utterances (reusing existing span rendering and single-subtitle fallback). `_SUBTITLE_TEXT_FIELDS`' single-field model does not fit drama; use an utterance→spans builder.
- For script_plan / prompt_authoring production of utterances (structured script_plan, passthrough prompt_authoring, Web review gates), see ADR 0041.
