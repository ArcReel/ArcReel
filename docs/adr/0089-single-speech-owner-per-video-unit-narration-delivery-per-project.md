# 一次视频生成只有一个发声归属，画外音不进视频模型；旁白交付方式是项目配置，不影响视频生成

一次视频生成的内容单位（说书片段、剧集场景、广告镜头或视频单元）按其发声条目机械派生出唯一的发声归属：只有台词、只有画外音，或无人声。台词（对白、内心独白、角色的画外解说）由视频模型的原生人声承载；画外音整段不进视频提示词，由独立的旁白配音或外部后期配音交付。同一单位里台词与画外音并存是阻断生成的违约：人工编辑把单位改成这样时拒绝保存，机器产出或迁移而来的这类单位落盘时标记需要重新规划或进入待修复草稿；无论来源，它们在改好之前都不能生成，下游也不自动切分、移动或改写发声内容。发声归属不落盘，每次都从正文或发声条目重算（`lib/speech/speech_composition/`）。

**一个单位对应一次视频请求，声音归属必须在请求之前定下来。** 视频模型只能「演」人物说的话——把画外音写进提示词，模型要么让画面里的人物对口型念出来，要么随机生成一段不属于任何人的人声，两者都无法事后剥离。而台词与画外音混在一个单位里时，没有一种交付方式能同时满足两者：交给视频模型会演错画外音，交给 TTS 会丢掉角色的原生声。把混合挡在规划阶段，是唯一不需要后期修补的位置。

**旁白交付方式是必填的项目配置。** 取值为「TTS 配音」或「后期配音」，在创建项目的向导里选择，默认后期配音，之后可以随时在项目设置里修改。选 TTS 时，项目必须指定 TTS 模型，音色与语速同样写进项目：创建时以全局默认值预填，此后全局默认的变化不影响这个项目。TTS 项目由 ArcReel 为含画外音的单位生成旁白配音；后期配音项目里，ArcReel 不为画外音产生任何声音，画外音文字随字幕草稿交付，由创作者在交付后自行配音。

**旁白交付方式不影响视频生成。** 两种项目都按编排时长申请视频，编排时长在写剧本时由画外音文字按项目语速估算，这已经是画面与旁白的对齐点。视频的申请时长、准入、报价与生成后检查都不读交付方式，两种项目生成出来的视频相同。旁白配音不是生成视频的前置条件：它属于剪辑阶段，在 Agent 首轮自动剪辑的第一步按「缺失补齐」生成，创作者也可以随时手动生成；项目选了 TTS 即视为同意这笔调用，不另外确认。旁白实测比画面长时，由剪辑时间线处理：旁白可以延伸到后续剪辑片段上（`docs/adr/0090`）。

**交付物按旁白版本区分。** TTS 项目的成片与剪映草稿可以出「带旁白」与「不带旁白」两个版本，两者并存、互不覆盖，默认带旁白；后期配音项目只有不带旁白一个版本。产物身份里的变体沿用 `use_tts` / `post_production`。

## 明确不采用

- **把画外音交给视频模型念**：模型会把画外音演成画面人物的台词或无主人声，且与原生音轨混在一起无法分离。
- **下游自动切分台词与画外音混在一起的单位**：切分点、时长分配与画面归属都是创作判断，机器切出来的两段往往都不成立；阻断并指明位置，让规划层或作者处理。
- **每次生成请求各自选择交付方式**：同一项目会混出按两种方式生成的素材；每个入口都得再问一次、再传一次，漏传一处就静默退回默认值；批量准入还得额外约束「同一批只能一种方式」。交付方式本质上是项目的制作决策，不是单次请求的选项。
- **项目只存默认值、请求仍可覆盖**：保留了按请求选择的全部问题，只是少问一次。
- **以旁白配音的实测时长作为视频申请时长的下限**：TTS 被迫成为视频的前置步骤，跨档要重新确认费用，时长固定的视频模型无法用于 TTS 项目，视频生成也因此随交付方式分叉。编排时长已按语速对齐，残余的长短差在剪辑时处理成本更低。
- **TTS 设置继承全局默认**：旁白配音的生成依据包含供应商、模型、音色与语速，改一次全局默认就会让所有项目的旁白配音变 stale。
- **截断或变速播放已生成的旁白配音来塞进画面**：会破坏配音本身；需要更短的旁白时重新生成，或在剪辑时间线上调整画面。

## Consequences

- 供应商原生音轨保持原样：不静音、不压低、不做人声分离；带旁白版本把旁白配音作为独立音轨叠加在其上，不带旁白版本不添加旁白音轨。没有语音识别时，系统只保证规划与请求不主动把两者混在一起，不保证供应商实际生成的波形里没有意外的人物声。
- 字幕是机械草稿：台词以实际视频时长为外边界，画外音在带旁白版本里以实际配音时长、在不带旁白版本里以实际视频时长为外边界，多条文本按规范化长度顺排，不宣称逐句对齐。
- 修改交付方式不让任何已有产物变 stale：交付方式不进视频的生成依据，字幕、呈现、成片与剪映草稿按旁白版本各占一个产物身份。从后期配音改为 TTS 后，比旁白短的画面由剪辑时间线的检查报出，不自动重新生成视频；从 TTS 改为后期配音后，已有旁白配音保留。画外音文字变化只让依赖它的配音、字幕与呈现失效，不让视频失效（`docs/adr/0062`、`docs/adr/0064`）。
- 工作流里没有独立的交付方式选择步骤；TTS 项目的旁白配音出现在剪辑阶段。
- 存量项目迁移时，产物清单里已有旁白配音产物、且能解析出 TTS 模型的项目判为 TTS 项目，并把当时解析出的模型、音色与语速写进项目；其余判为后期配音项目。
- TTS 的生成基数是 TTS 项目里每个含画外音的单位一段（`docs/adr/0010`）；`docs/adr/0040` 中同一场景可交错台词与画外音的前提不再成立。
