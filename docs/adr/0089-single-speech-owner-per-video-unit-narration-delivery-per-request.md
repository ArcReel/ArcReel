# 一次视频生成只有一个发声归属，画外音不进视频模型、交付方式按请求选择

一次视频生成的内容单位（说书片段、剧集场景、广告镜头或视频单元）按其发声条目机械派生出唯一的发声归属：只有台词、只有画外音，或无人声。台词（对白、内心独白、角色的画外解说）由视频模型的原生人声承载；画外音整段不进视频提示词，由独立的旁白配音或外部后期配音交付。同一单位里台词与画外音并存是阻断生成的违约：机器产出的这类单位落盘时标记需要重新规划或进入待修复草稿，人工编辑直接拒绝保存，下游不自动切分、移动或改写发声内容。发声归属不落盘，每次都从正文或发声条目重算（`lib/speech/speech_composition/`）。

**一个单位对应一次视频请求，声音归属必须在请求之前定下来。** 视频模型只能「演」人物说的话——把画外音写进提示词，模型要么让画面里的人物对口型念出来，要么随机生成一段不属于任何人的人声，两者都无法事后剥离。而台词与画外音混在一个单位里时，没有一种交付方式能同时满足两者：交给视频模型会演错画外音，交给 TTS 会丢掉角色的原生声。把混合挡在规划阶段，是唯一不需要后期修补的位置。

画外音的**旁白交付方式**——「使用当前 TTS」或「后期配音」——是每次视频生成请求的参数，不写进剧本、项目设置或任何确认状态（`lib/speech/narration_delivery.py`）。未配置 TTS 时只能选后期配音，视频照常可以生成。选「使用当前 TTS」时，该单位必须已有 current 且可测时长的旁白配音；它的实际时长是视频申请时长的下限，跨档需要重新确认时长与费用，超过供应商最大档则阻断、回到规划层。选「后期配音」时按编排时长申请视频，不叠加旁白音轨，画外音文字随机械字幕草稿导出，供外部配音使用。

## 明确不采用

- **把画外音交给视频模型念**：模型会把画外音演成画面人物的台词或无主人声，且与原生音轨混在一起无法分离。
- **下游自动切分台词与画外音混在一起的单位**：切分点、时长分配与画面归属都是创作判断，机器切出来的两段往往都不成立；阻断并指明位置，让规划层或作者处理。
- **把交付方式存为项目设置或剧本字段**：同一项目常常先用 TTS 试看、定稿后再交专业配音；存下来就会出现「设置是 TTS、手上的产物却是后期版本」的状态分叉，且每次切换都要让一批产物失效。
- **未配置 TTS 即禁止生成含旁白的视频**：后期配音本就不依赖 TTS，把 TTS 当前置条件会让不用内置配音的用户卡在门外。
- **截断、加速 TTS 或把余量挪到相邻单位来适配时长档位**：改变语速与截断都会破坏已试听确认的配音，跨单位挪用则破坏「一个单位一段产物」的边界。

## Consequences

- 供应商原生音轨保持原样：不静音、不压低、不做人声分离；选 TTS 时旁白配音作为独立音轨叠加在其上，后期配音方式不添加旁白音轨。没有语音识别时，系统只保证规划与请求不主动把两者混在一起，不保证供应商实际生成的波形里没有意外的人物声。
- 字幕是机械草稿：台词以实际视频时长为外边界，画外音在选 TTS 时以实际配音时长、在后期配音时以实际视频时长为外边界，多条文本按规范化长度顺排，不宣称逐句对齐。
- 批量请求对全部目标使用同一交付方式，准入全有或全无（`docs/adr/0061`）。
- 旁白配音、字幕与呈现的产物时效各自比较当前内容与交付方式：画外音文字变化只让依赖它的配音、字幕与呈现失效，不让视频失效（`docs/adr/0062`、`docs/adr/0064`）。
- `docs/adr/0010` 的 TTS 生成基数从「每个说书片段一段」扩展为「每个含画外音的单位一段」；`docs/adr/0040` 中同一场景可交错台词与画外音的前提不再成立。
