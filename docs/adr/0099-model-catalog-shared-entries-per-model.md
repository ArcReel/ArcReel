# 模型目录共享模型事实，供应商模型记录渠道差异

内置供应商、自定义供应商和 Agent 共用模型条目。条目按模型厂商和官方模型名标识，描述模型事实与参考价目表。供应商模型记录发送的 API 模型名、调用端点及适用的条目绑定与能力覆盖。渠道价差通过倍率表达，避免为同一模型维护多份事实和价格。参考费用在调用时计算并冻结，历史账目无需保留旧费率才能读取。见 [ADR 0100](0100-price-table-meters-and-dimensions.md) 和 [ADR 0104](0104-capability-sources-split-by-dimension.md)。

两栖模型在目录中以媒体类型区分条目。可灵 v3 Omni 的图片和视频都发 `kling-v3-omni`，内部键仍分别使用 `kling-v3-omni-image` 和 `kling-v3-omni`，以保留已有项目和费用记录的身份。映射见 [目录查询](../../lib/catalog/query.py)，用户负责的模型与条目怎样对应见 [ADR 0105](0105-model-name-to-entry-matching.md)。

## 数据所有权

- 目录在出厂快照和官方同步中取较新的数据。用户编辑或创建条目时保存整条副本，该条目由用户维护；恢复官方数据时丢弃副本。用整条副本是为了让同步停止后的数据归属可预测。后来发现同身份的官方条目，用户可确认改用官方数据。
- 官方收录的供应商模型随官方数据，用户只管理启用状态。内置供应商下用户添加的模型和自定义供应商的模型由用户负责。官方后来收录同一 API 模型名和媒体类型时接管这条内置供应商模型，保留启用状态。
- 内置供应商表示官方渠道，地址覆盖用于透明转发。中转站用自定义供应商。内置供应商获取模型列表供补充收录，账号或地区返回的列表不作为可调用性的判据。

## 推荐模型与生成用模型

官方数据的 `defaults` 是推荐值。它只在内置供应商首次配置时填补空的全局默认设置、旧版升级固化，或用户主动接受推荐时写入设置。此后项目和全局配置决定执行模型。它们皆为空时才用合格的自定义供应商默认模型；没有候选时提示用户配置。自动应用每次同步带来的推荐会在用户不知情时改变价格和画面风格。因此推荐变化只提示，已处理的推荐在同一供应商和媒体类型再次变化前无需重复处理。

0.36 及更早版本仍会从官方数据自动解析内置默认模型。升级以原应用版本及其当时可见的目录、凭证和停用状态还原实际选择，将结果持久化供默认设置固化、旧项目迁移及重试复用。缺少可信快照或无法还原时要求用户选定模型；固化未完成时也不通过自定义供应商兜底。能够确定旧版原本已使用自定义默认的媒体类型继续按该设置解析。归档导入缺少原实例上下文，使用目标实例的当前推荐补齐旧归档。支持的版本、失败处理与项目字段约束见 [升级前推荐解析](../../lib/config/pre_upgrade_recommendations.py)、[默认模型固化](../../lib/config/recommended_models.py)及 [v19→v20 迁移](../../lib/project/project_migrations/v19_to_v20_bare_provider_models.py)。修改推荐对仍在运行的旧版本有影响，发布规则见 [ADR 0103](0103-catalog-data-repo-built-from-third-party-sources.md)。
