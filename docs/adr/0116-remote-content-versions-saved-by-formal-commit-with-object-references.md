# 远端内容版本经正式提交保存，正式对象按内容摘要命名并以引用记录归属

[ADR 0109](0109-content-version-identity-on-version-records.md) 规定内容版本的身份、摘要与持久定位记在版本记录上，远端主存储到来时在记录上增加远端定位。决定如下。

**持久定位**：远端内容版本的版本记录增加 `storage` 字段，记下写入时的对象存储连接 ID、桶与对象 key。没有这个字段的记录照旧按本地定位解释。读取只按记下的连接与桶取对象：连接已删除或已指向另一个桶时明确拒绝，不按新桶重新解释旧定位。签名 URL 只交给需要取图的一方，不进入定位。

**正式提交**：`lib/material/formal_objects.py` 的 `formal_commit` 是正式提交入口，调用方在其中执行既有的正式写入编排。入口按全局设置 `material_storage_target` 选择这次新写入的图片内容版本保存在本地还是对象存储；缺省本地，普通 UI 与 API 暂不开放修改。远端保存发生在版本管理器写版本记录之前，即 `_persist_snapshot` 这一个接缝。对象写入并经 HEAD 确认后才返回定位；失败时版本管理器与调用方照旧回滚，旧版本、产物清单与正式文件不变。只有图片资源写进对象存储，视频与音频照旧保存在本地。选择或恢复已有版本仍使用记录原有的定位，不算新增。

**对象与归属**：正式对象的 key 是 `arcreel-materials/sha256/<前两位>/<摘要><后缀>`，与中转副本的 `arcreel-relay/` 前缀分开。同一连接里同字节的内容版本共用一个对象。`object_storage_formal_object` 在上传前登记对象。`object_storage_formal_object_ref` 记录两类引用：进行中的提交占用（`pending`），以及版本历史中的内容版本使用（`active`）。

- 对象只要还有任何引用就不删除。
- 提交结束后（无论成败）按项目版本历史结算：被内容版本使用的占用转为 `active`，其余撤下。
- 失败补偿只删除本次提交新建、结算后没有任何引用的对象，复用的对象一律不删。
- 删除失败保留原因，由维护循环退避重试。
- 进程在提交中途退出时，下次启动补做结算。

**工作文件**：远端内容版本在版本快照位置与选中时的正式文件位置都有本地工作文件，既有读取方因此不用区分存储位置。工作文件只是缓存。

- 读取方经 `lib/material/work_files.py` 的 `ensure_work_file` 或 `ensure_content_version_file` 取回。预览、缩略图与版本切换已经接入：公开文件路由与版本还原在读取前取回缺失的工作文件。
- 取回时按摘要校验，同一文件的并发取回只下载一次。安装在版本锁内复核记录未变、文件仍不在，不会盖住并发提交写下的新文件。
- `hold_work_file` 登记使用中的文件，清理跳过它们。
- 清理入口有两个：对象存储路由的 `POST /api/v1/object-storage/work-cache/cleanup`，以及后台每小时一次、只清理闲置 24 小时以上文件的维护循环。两者都只删除远端已确认保存、且本地内容与摘要一致的文件，不删除任何对象。

**连接保护**：连接上还有正式对象（上传未确认、已保存或等待删除）时，不能更换桶、Endpoint、区域，也不能删除连接；可以只更新访问密钥。

**供应商入库**：内容版本已作为正式对象保存在当前连接的桶里时，入库直接为这个对象签发地址，不写中转副本。对象 key 由摘要决定，地址固定指向这个内容版本；中转清理只按中转副本记录进行，不会删除它。

## Considered Options

- **按提交随机命名对象，每个对象只归一个内容版本**：失败补偿简单，但同字节的跨项目应用、全局资产库只能重复上传，后续任务也无从表达共享对象的归属。
- **在提交外先上传，再把对象交给版本记录**：上传不占版本锁，但图片生成、编辑、导入与上传各有自己的提交路径，每条都要在提交前另做一步。远端保存放在 `_persist_snapshot` 这一个接缝，所有路径进入 `formal_commit` 即可。
- **另建与项目目录无关的内容寻址缓存目录**：既有读取方都按项目内路径读文件。工作文件放在原位置，迁移读取方时只需在读取前确保文件在场。
- **连接变更时允许改桶、旧定位按新连接解释**：会把旧对象静默指向新桶。
- **按对象前缀扫描删除**：会作用于不在记录中的对象，补偿与清理只按登记的定位进行。

## Consequences

- 对象上传在版本锁内进行，同一项目的其他版本写入在上传期间等待。部署是单个 uvicorn 进程（见 [ADR 0007](0007-orphan-tasks-not-requeued-on-restart.md)、[ADR 0083](0083-generation-queue-stays-in-house-for-now.md)），对象级的串行用进程内锁实现。
- 后续生命周期改变内容版本对对象的使用时，经 `reconcile_project_references` 按版本历史重算项目的引用，或经 `add_reference` 为另一个项目的内容版本登记引用。这些操作包括版本删除、回收站、归档导入与跨项目应用。对象失去全部引用后是否删除，由该操作按自己的保留规则决定；本决定只让失败补偿删除对象。
- 既有直接读取正式文件或版本快照的消费方暂未迁移，包括参考图装配、产物清单与时效判定、归档导出与图片编辑。远端内容版本的工作文件被清理后，它们须先经工作文件入口取回，由各自的后续任务迁移。

范围与验收见 [Spec #3559](https://github.com/ArcReel/ArcReel/issues/3559)。
