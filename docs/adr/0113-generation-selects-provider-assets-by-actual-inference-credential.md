# 生成按实际推理凭证选用供应商素材，适用的关联不可用时失败而不回退

参考生视频提交前，编排层为每张参考图决定发送图片内容还是 `asset://` 素材引用。范围由调用通道报出的推理凭证决定：内置方舟视频通道报出生效凭证记录的 ID、API Key 与 Base URL，自定义供应商报出自己的 ID、API Key 与 Base URL，再交给 `resolve_bound_scope` 按绑定摘要核对。编排层不按供应商名称、域名或配置重新推断凭证；凭证不来自凭证记录（只在供应商配置里填写 API Key）时，通道不报出凭证，按没有绑定处理。参考图按实际发出的字节对应到内容版本：摘要须等于资源当前选中版本的摘要，否则视为没有适用的关联。上传与导入建立的关联按同一规则选用。

是否接受素材引用由通道按模型与槽位声明（`provider_asset_roles`）。官方文档只给出 Seedance 2.0 / 2.5 在参考图槽位使用素材 ID 的契约，所以只声明这一个槽位。模型取供应商模型所对应的条目：内置供应商取清单所引的条目，自定义供应商与内置供应商下用户添加的模型先看条目绑定，再按名字现查（见 `docs/adr/0105`）。通道按条目的官方模型名与模型别名认定这两代，内置与自定义入口共用同一判定。对应不上条目时不声明，不回落到按 API 模型名认定：`docs/adr/0104` 的通道事实回落只开放保守能力，而按名字认定素材引用是乐观推断，中转站给任意模型起含 Seedance 字样的名字就会发出 `asset://`。中转站改了名的模型，由用户绑定条目来启用。首帧、尾帧、Seedance 1.x 与 Seedream 照常发送图片内容；以后有官方契约时再逐个声明，不改变生成路线，也不新增帧槽位。素材引用原位替换图片内容，图片数量、顺序与提示词编号不变；被替换的槽位不读取、不压缩，也不计入请求体预算。

选定的关联或入库任务尚未可用（等待上传、提交中、供应商处理中、结果待确认）或已失败时，这张图片算作有适用的关联但不可用，生成在写入执行检查点之前失败，不向供应商提交请求，已暂存的媒体随失败清理。不采用回退到普通图片：用户把图片入库，往往正是因为普通图片会被供应商拒绝，静默回退只会换来一次计费或审核失败，而且用户无从知道素材没有生效。没有素材 ID 的关联同样不可用，不能按没有关联处理。

供应商以输入图片未通过审核拒绝请求时，失败原因给出供应商错误码，并提示把资产图上传到素材库；不自动上传、不重试、不切换供应商。方舟的错误不带图片下标，只有请求里只有一张参考图且没有首帧、尾帧时才点名这张图片，其余情况不猜测。

## 后果

执行检查点升到 schema v5，新增 `provider_asset_references`，记录哪张暂存参考图以哪个内容版本的哪个素材引用发出；它进入请求摘要与版本元数据，不进入产物时效依据。同样的内容以素材引用或图片内容发出，免费复用与时效判定的结果相同。v4 及更早的检查点按没有素材引用续跑。

接收任务、批量预览与报价共用的请求投影同样核对关联：读侧以当前配置装配的调用通道求素材库范围，执行侧以实际调用通道求范围，按同一规则选择，适用的关联不可用时报同一个问题码与参数（`provider_asset_link_processing`、`provider_asset_link_failed`），这一单元不给出预估费用。执行时暂存参考图之后再按实发字节核对一次，关联在提交之后才变得不可用的，在写入检查点之前失败。核对只产生阻断问题，不改变投影的请求事实，也不进入产物时效依据。限流路由只需要定桶结论，不核对。范围与验收见 [Spec #3559](https://github.com/ArcReel/ArcReel/issues/3559)。
