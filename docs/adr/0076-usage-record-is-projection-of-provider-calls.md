# 使用记录投影任务状态和已发生的调用

生成任务表达的是调度意图，调用记录表达的是真实发生的供应商交互。前端展示的使用记录从任务中读取进行中状态，从调用记录中读取用量与费用。一条任务可以关联多笔调用，而在排队阶段就被取消的未执行任务则无需生成调用记录。将两者分开存储，能避免把调度的一对多关系强行压成一笔账。

内嵌 Agent 的客户端能看到一轮的逐请求用量，记录按轮及模型汇总，价目表仍对每次请求独立求值。见 [ADR 0102](0102-agent-cost-computed-per-request-from-tokens.md)。

## 取消、失败与成功结算的分界

单次生成调用经 [记账账本](../../lib/billing/ledger.py) 的 `Ledger.record` 进入 `pending` 状态，协程取消或异常失败落在不同阶段时遵循不同结算口径：

- 开账写入阶段或调用块内部遇到取消时，先等待已发起的 `pending` 行落库（若在开账中取消），再尝试按 `cancelled` 与零费用结算，落库后发布刷新事件并继续传播取消。
- 正常退出调用块、已声明成功并进入成功结算写入时，供应商结果与费用事实已经产生；此时遇到取消不改判为零费用取消，而是等待受保护的成功写入落库、发布成功刷新事件后再传播取消，保留实际计量结果。若成功写入抛出普通异常，则改走失败分支尝试结算为 `failed` 并向上抛出。
- 调用块以异常失败退出时，若本次调用链上已有已完成的供应商物理请求并返回了计量（例如文本原生请求已收到 HTTP 200 后，后续结构化降级或截断失败），账本保留这些已确认的逐次请求计量并按价目表结算费用；尚未产生已知用量的失败调用仍按零费用结算。

刷新事件仅在调用关联了非空项目名时发布，发布失败只记日志，不推翻已落库的调用记录。上述规则只约束 ArcReel 本地参考账本的记录状态，不推断供应商是否退款。
