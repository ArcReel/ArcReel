# 下级智能体叫「子智能体」，取代 ADR-0063 定的「子任务」

`docs/adr/0063` 把「智能体/子任务」列入与 Spec #1840 一致的产品名清单。本 ADR 只推翻其中的「子任务」一项，改为**子智能体**；0063 的其余决定（一次性全量改写、机器标识入标题、陈述类条目删除、不保留兼容别名）全部继续有效。

「子任务」在这个仓库里同时指两件不相干的东西：智能体派出的下级智能体，以及一个生成任务级联出的下级生成任务（`TaskRepository` 取消父任务时要一并中止的那些 running 行）。两者都会出现在界面与日志里——前者在对话时间线的卡片上，后者在任务队列的取消路径上——用户看到同一个词，指的却是两个层级完全不同的东西。任务树那一侧没法改名：它就是任务的子任务，换任何词都更绕。所以改的是智能体这一侧。

「子智能体」还有一个「子任务」没有的好处：它自带「这是一个会自己思考的执行体」的含义。用户看到一张卡片在转圈，「子智能体正在分析素材」解释了为什么它需要时间，「子任务正在分析素材」读起来像是一个进度条。

## Consequences

- `CONTEXT.md` 的「子智能体（subagent）」条目把「子任务」列入 `_Avoid_`，并注明该词在生成任务树里另有所指——拦截的是智能体语境下的误用，不是任务树那一侧的正当用法。
- 界面文案（`frontend/src/i18n/{zh,en,vi}/dashboard.ts`）、内嵌智能体的配置源（`agent_runtime_profile/`）与交回给智能体的运行时消息统一改口；生成任务树相关的代码注释保持「子任务」不动。
