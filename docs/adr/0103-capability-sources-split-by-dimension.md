# 模型能力按维度只有一个来源：模型事实记在条目上，通道事实由代码声明，渠道限制记在供应商模型上

模型目录把模型的能力随官方同步下发，但有一部分能力不是模型本身的事实，而取决于调用通道怎样打包请求，并且会随执行子路径分叉：同一个视频模型走图生视频和参考生视频时，音轨形态可能不同；可灵在 pro 档才放开尾帧。我们按维度划分来源，每个维度只有一个来源，两侧不互相比较。

- **模型事实记在模型条目上，随官方同步下发**：文本是否接受图片输入、是否支持结构化输出、最大输出 token；图片是否支持文生图与图生图；视频的可选时长、分辨率，以及时长与分辨率、参考图之间的联动约束。
- **通道事实由内置调用通道或调用端点在代码中声明**：视频的输入模式（文生视频、首帧、尾帧）、参考图与参考音频上限、提示词长度上限、音轨形态，以及图片调用端点实现了文生图还是图生图。

## 规则

- 能力按模型声明。供应商一级没有自己的能力声明，供应商支持哪些媒体类型和能力，由其下的供应商模型聚合得出。
- 图片的文生图与图生图两侧都有，含义不同：模型条目说模型接不接受，通道声明说这条通道实现了没有。生效能力取两者都满足的部分，任务类型桶的候选和执行时的校验都用这一个结果。
- 调用通道不另带时长或分辨率检查。时长原样透传，超出上游范围时由上游拒绝（见 `docs/adr/0018`）。
- 调用通道遇到不认识的模型时，先按名字族匹配同一代的能力；匹配不到时统一回落为只支持文生视频与首帧，不开尾帧，参考图与参考音频上限为 0。
- 渠道与模型条目、通道声明不一致时，用供应商模型上的能力覆盖表达，不修改模型条目；只有模型本身的事实有误时才修改条目。能力覆盖两类维度都可以覆盖，每个维度整体替换，优先级最高。
- 只有用户负责的供应商模型带能力覆盖，即自定义供应商的供应商模型，以及内置供应商下用户添加的供应商模型。官方收录的供应商模型不带能力覆盖（见 `docs/adr/0098`）。
- ComfyUI 端点的能力只从节点绑定推导，不接受能力覆盖（见 `docs/adr/0082`）。

## Considered Options

- **输入模式等通道事实也记在模型条目上**：新一代模型不必发版就能用上全部能力。但条目表达不了按执行子路径的分叉；第三方数据源也没有这类数据，等于人工维护一份与调用通道代码强耦合的数据。
- **不认识的模型乐观回落到同一供应商最新一代的能力**：用户不必手动打开就能用参考图，但新一代改了请求参数时，提交会被上游拒绝。保守回落仍能走图生视频这条主路线，时长和分辨率也来自条目，不受回落影响。
- **官方数据给供应商模型下发能力覆盖**：可以表达官方渠道之间的差异，也能让老版本实例抢先用上新一代模型的全部能力。但目前同一模型在不同内置供应商下的能力完全一致，没有用例；日后需要时只是新增字段。
- **在官方收录的供应商模型上叠加一层用户能力覆盖，不影响同步**：可以照顾把内置供应商接到中转站的用户。但内置供应商代表官方渠道，中转站应该用自定义供应商（见 `docs/adr/0098`）。

## Consequences

- 新一代视频模型在调用通道支持之前，即使已列入内置供应商清单，也只有保守能力。目录数据仓库宜在调用通道支持之后再列入。
- 自定义供应商的供应商模型不再单独存可选时长，可选时长来自引用的条目，渠道限制写进能力覆盖。按模型名推断时长的预设只在新建模型条目时用于预填。
