# Expose session/project SSE streams as async context managers; consumers poll is_disconnected on idle wakeups to ensure cleanup

Session (`SessionManager`) and project-event (`ProjectEventService`) real-time delivery previously exposed raw `asyncio.Queue` interfaces: consumers each called `subscribe`, handwrote `while queue.get()` loops, and used `finally: unsubscribe`. Omitting `finally` leaked subscribers. Consolidate this as **async context managers** `stream_messages()` / `stream_events()`, make `subscribe/unsubscribe` private, and hide subscription, queue consumption, and exit deregistration behind the seam. Historical replay remains outside: session streams use a first-event barrier marking atomic subscription establishment, after which consumers query stored history themselves (see Consequences). However, **an async generator alone cannot ensure cleanup**: `async for ... break` **never** automatically closes an async generator (an absolute language-level conclusion); the event loop runs its `finally` after garbage collection. Whether `finally` runs promptly on client disconnection depends on how runtime **terminates/cancels** the generator chain; prompt cleanup is neither guaranteed nor necessarily deferred to GC. FastAPI native SSE `fastapi.sse` (source analysis based on the then-locked 0.136.1, whose comments cite PEP-789 as motivation; this decision does not depend on that version's exact cancellation timing, because uncertain cancellation injection is precisely why we do not rely on it, so later upgrades do not overturn the conclusion) uses structured-concurrency cleanup: it hands the endpoint generator to a task group on a request-level `AsyncExitStack`, calling `cancel_scope.cancel()` on disconnection instead of throwing `GeneratorExit` into the generator. According to its source, cancellation propagates down to nested generators' `finally` only when the generator is **waiting for the next item** (the `__anext__` chain). If paused at its own `yield` (the consumer is not reading or buffers are full, common on disconnect), cancellation hits send and **cannot reach** nested `finally`, returning cleanup to GC. Therefore: (1) use **async context managers**, not bare generators, with cleanup in `__aexit__`; (2) consumer loops periodically wake on idle signals (session-stream heartbeats/project-stream `_idle` sentinels) and **actively detect disconnection and break normally** using `await request.is_disconnected()`, deterministically triggering `__aexit__` without relying on cancellation injection hitting the right point. `project_events.py` already polls `is_disconnected`; this decision aligns session SSE with it.

## Consequences

- Consume `stream_messages()`/`stream_events()` with `async with`, never directly as bare generators through `async for`. Every new SSE consumer uses the CM form; flag bare `async for some_stream()` as a cleanup risk in review.
- Event shapes are **per-stream, not global**: session streams (`SessionManager.stream_messages`) yield semantic events. First comes a subscription barrier (`SubscriptionReady`, marking atomic subscription establishment without gaps in subsequent broadcasts; history replay stays outside the seam, with consumers such as `AssistantService` querying stored entries via `event_log.list_entries` after the barrier, filtering duplicate delivery between subscription and database reads by identity through a seq threshold), then individual live messages (`LiveMessage`) and heartbeats (`Heartbeat`). Subscription-queue overflow is expressed as **stream termination**, signaling reconnection; the overflow sentinel stays inside subscription/broadcast component SseChannel (`server/sse_channel.py`), invisible to consumers. Project-event streams (`ProjectEventService.stream_events`) retain raw message dicts + `_idle` sentinels (consumers dispatch through `msg.get("type")`), using "snapshot as first event" instead of a replay boundary. Queue overflow removes the subscriber and ends its stream; clients realign through initial snapshots after reconnection (see the last item). Consumers must handle the shape of the particular stream they consume. For session-stream seam boundaries (typed events absorb sentinels), see `docs/adr/0046`.
- Idle wakeups make SSE paths periodically check `is_disconnected`, maintaining liveness and cleanup boundaries through session-stream `Heartbeat` or project-stream `_idle`.
- Do not rely solely on FastAPI/anyio cancellation injection or GC for prompt client-disconnection cleanup. Consumers' `is_disconnected` checks own timeliness; CM `__aexit__` owns "deregister regardless of exit cause." Both are required: CM without checks still drifts to GC for parked-at-send disconnections; checks without CM can still miss deregistration on exception paths.
- On overflow, `ProjectEventService` must terminate the removed subscriber's stream: streams sending only idle heartbeats do not trigger client reconnection, silently losing subsequent one-time events such as autonomous-turn recovery notifications.
