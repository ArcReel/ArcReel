# 费用归属以记账 key 为强证据，ID 前缀仅作兜底弱线索

费用聚合需要把每笔实付（成本快照）归属到集与剧本条目。归属对象是 image / video / audio 三类记账——它们记账时冻结了所属剧本条目的 ID；text 类调用不写这个 key，不参与归属，其支出由用量统计侧按供应商与调用类型单独汇总。

记账 key 是冻结在调用记录 `segment_id` 列上的资源 ID，有两种形态：

- **剧本条目 ID**（主形态）：取值随骨架而异（`segments` 的 `segment_id`、`scenes` 的 `scene_id`、`shots` 的 `shot_id`、`video_units` 的 `unit_id`），规范格式统一为 `E{episode}S{n}` / `E{episode}U{n}`
- **宫格图 ID**（`grid_{12 位十六进制}`）：宫格生视频路径下一张宫格图承载多个分镜，记账落在宫格上。它按剧本条目 `generated_assets.grid_id` 反查认领，再按该宫格覆盖的条目数均摊；不带 `E{episode}` 前缀，因此不适用下面的前缀兜底

这些 ID 既不保证全局唯一，也不保证与所在集一致——剧本可编辑、可整体替换，ad 模式下 unit 重建会复用编号。我们决定：归属的强证据就是这个冻结的 key。估算聚合先把同一 (记账 key, 费用类型) 下的全部成本快照按币种汇总成一份金额（不同币种各自分列，不折算合并），再按「一次估算内每个 (记账 key, 费用类型) 只认领一次」整份消费——去重防的是同一笔钱被多个剧本条目重复计入，不是丢弃其中的调用记录；无法被当前剧本认领的历史记账不丢弃，经 ID 前缀解析集号摊回对应集、解析失败（含宫格 ID 等无前缀 key）则归入项目级，统一以「未归属（unassigned）」单列呈现。

放弃的替代方案是为剧本条目引入全局唯一身份（schema 级改造）：它能根治 ID 复用错配，但需要迁移全部存量记账与剧本数据，与收益不成比例。因此 ID 不唯一、不保证与所在集一致是**已知且接受的限制**——基于「校验 ID 唯一性/前缀一致性再归属」的改进建议不成立，会把真实支出误判为未归属（或反之）；审查中反复出现的此类意见应引用本 ADR 驳回。
