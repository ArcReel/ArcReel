# Cost attribution uses ledger keys as strong evidence; ID prefixes are only weak fallback clues

Cost aggregation must attribute each actual payment (cost snapshot) to an episode and script entry. Attribution covers image / video / audio calls **that write a ledger key** (see the key allowlist in `media_generator.segment_id_for`). Three spending categories are excluded: text calls write no key and are separately aggregated by provider and call type by usage statistics; asset-image keys (character/scene/prop/product) are empty, so output paths split them into project-level asset-type details, with unsplittable ones placed in project-level "unassigned"; historical video / audio ledger keys from before the `segment_id` column was backfilled are also empty, offering no episode-attribution clue, and go directly into project-level "unassigned."

The ledger key is a resource ID frozen in the call record's `segment_id` column, with three forms:

- **Script-entry ID** (the primary form): values vary by skeleton (`segment_id` in `segments`, `scene_id` in `scenes`, `shot_id` in `shots`, `unit_id` in `video_units`). Canonical formats are `E{episode}S{n}` / `E{episode}U{n}`; child entries created by insertion and splitting in existing data have a `_{子序号}` suffix (such as `E1S01_1`) and are also valid keys. All three content modes on the reference route attribute costs directly to self-contained `video_units` entries
- **Grid-image ID** (`grid_{12 位十六进制}`): on the grid-to-video path, one grid image carries multiple storyboard images and receives the ledger entry. Claim it through a reverse lookup of script-entry `generated_assets.grid_id`, then split equally by the number of entries covered by that grid. It has no `E{episode}` prefix, so the prefix fallback below does not apply

These IDs guarantee neither global uniqueness nor consistency with the containing episode: scripts can be edited or entirely replaced. Before `docs/adr/0090`, rebuilding units could reuse numbers, and existing ledger entries can still point to reused numbers. Decision: this frozen key is the strong attribution evidence. Estimate aggregation first sums all cost snapshots under the same (ledger key, cost type) by currency into one amount (separate columns for different currencies, without conversion or merging), then consumes the whole amount under the rule "each (ledger key, cost type) is claimed only once within an estimate." Deduplication prevents counting the same money repeatedly for multiple script entries, rather than dropping any call records. Historical ledger amounts unclaimable by the current script are retained and shown separately as "unassigned": the project-level unassigned bucket is the complete aggregation bucket, receiving every unclaimed amount. Amounts whose ID prefix yields an episode number that still exists in `project.json` are additionally displayed in that episode's unassigned bucket (unparseable keys, prefixless keys such as grid IDs, and deleted episodes have only the project-level copy). The episode-level copy is an episode view of the same money, not additional spending. Read the project-level bucket when calculating project totals; never add episode-level buckets again.

The rejected alternative is globally unique identity for script entries (a schema-level redesign): it would eliminate ID-reuse mismatches at their root but require migrating all existing ledger and script data, disproportionate to the benefit. Nonunique IDs and lack of consistency with the containing episode are therefore **known, accepted limitations**. Suggestions to "validate ID uniqueness/prefix consistency before attribution" are invalid, since they would misclassify actual spending as unassigned (or vice versa); recurring review comments of this kind should be rejected by citing this ADR.
