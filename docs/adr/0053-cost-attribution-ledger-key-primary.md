# 费用归属以记账 key 为强证据，ID 前缀仅作兜底弱线索

费用聚合需要把每笔实付（成本快照）归属到集与剧本条目。参与归属的是**写了记账 key 的** image / video / audio 调用（key 白名单见 `media_generator.segment_id_for`）。三类支出不在其内：text 调用不写 key，由用量统计侧按供应商与调用类型单独汇总；资产图（角色/场景/道具/产品）的 key 为空，按产物路径拆成项目级的资产类型明细、拆不出的并入项目级「未归属」；`segment_id` 列回填之前的历史 video / audio 记账 key 同样为空，无集归属线索，直接并入项目级「未归属」。

记账 key 是冻结在调用记录 `segment_id` 列上的资源 ID，有三种形态：

- **剧本条目 ID**（主形态）：取值随骨架而异（`segments` 的 `segment_id`、`scenes` 的 `scene_id`、`shots` 的 `shot_id`、`video_units` 的 `unit_id`），规范格式为 `E{episode}S{n}` / `E{episode}U{n}`，插入与拆分产生的子条目带 `_{子序号}` 后缀（如 `E1S01_1`），同为合法 key
- **派生 unit ID**：ad 参考生视频的 unit 不是剧本条目，由 `derive_ad_reference_units` 按镜头分组现推（格式同 `E{episode}U{n}`）。记账落在 unit 上，认领后按其成员镜头均摊
- **宫格图 ID**（`grid_{12 位十六进制}`）：宫格生视频路径下一张宫格图承载多个分镜，记账落在宫格上。它按剧本条目 `generated_assets.grid_id` 反查认领，再按该宫格覆盖的条目数均摊；不带 `E{episode}` 前缀，因此不适用下面的前缀兜底

这些 ID 既不保证全局唯一，也不保证与所在集一致——剧本可编辑、可整体替换，ad 模式下 unit 重建会复用编号。我们决定：归属的强证据就是这个冻结的 key。估算聚合先把同一 (记账 key, 费用类型) 下的全部成本快照按币种汇总成一份金额（不同币种各自分列，不折算合并），再按「一次估算内每个 (记账 key, 费用类型) 只认领一次」整份消费——去重防的是同一笔钱被多个剧本条目重复计入，不是丢弃其中的调用记录；无法被当前剧本认领的历史记账不丢弃，统一以「未归属（unassigned）」单列呈现：项目级的未归属是全量汇总桶，收下每一笔未认领金额；其中能由 ID 前缀解析出集号、且该集仍在 `project.json` 中的，另在对应集的未归属里展示一份（解析失败的、宫格 ID 等无前缀 key、以及集已被删除的，就只有项目级这一份）。集级那份是同一笔钱的按集视图，不是新增支出——求项目合计时读项目级桶即可，不得再叠加集级桶。

放弃的替代方案是为剧本条目引入全局唯一身份（schema 级改造）：它能根治 ID 复用错配，但需要迁移全部存量记账与剧本数据，与收益不成比例。因此 ID 不唯一、不保证与所在集一致是**已知且接受的限制**——基于「校验 ID 唯一性/前缀一致性再归属」的改进建议不成立，会把真实支出误判为未归属（或反之）；审查中反复出现的此类意见应引用本 ADR 驳回。
