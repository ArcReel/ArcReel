# Key script-skeleton registries by skeleton kind; centralize axis interactions in declared/forensic resolvers

`SCRIPT_SHAPES` used content_mode alone as key, covered only three skeletons, and had only 4 consumers. About 19 other files handwrote `== "narration"/"drama"` branches, sometimes degrading to "not narration means scenes." Skeleton knowledge was duplicated in data_validator's four-way chain and script_editor discrimination. Consequences already occurred: `project_events` snapshots' binary fallback always returned empty entries for ad (`shots`) and reference_video (`video_units`), preventing storyboard-level events. Missing reference_video registry coverage forced consumer-specific video_units exceptions, with omissions silently dropping entries: structural cause, not individual carelessness.

Centralize skeleton knowledge in dependency-free leaf `lib/script/script_skeleton.py`; every consumer dispatches through it.

- **Key the table by skeleton kind**, four values `segments / scenes / shots / video_units` (see "Skeleton" in `GLOSSARY.md`). Keys are entry-array keys, leaving rows as `Skeleton(id_field, chars_field)`. `chars_field` may be `None`: video_units has no per-entry character list (characters are `references` entries with `type == "character"`). Declare absence honestly; consumers receiving `None` must explicitly derive or declare inapplicability, without fake names yielding empty `get()` results.
- **Neither content_mode nor generation_mode enters the registry**. Centralize interactions in two functions: **declared resolution** `(content_mode, generation_mode) → kind` for consumers holding project configuration, always taking generation_mode from project routes (`docs/adr/0055`); **forensic resolution** `script dict → kind` (migrated from `script_editor.resolve_kind`) for consumers holding script data, retaining its shape-first tolerance ladder. It answers actual shape irrespective of declarations, keeping mismatched legacy scripts editable/archive-exportable. Input contract: potentially incomplete script dicts use forensic resolution; declared resolution accepts only validated project-level mode pairs. These real, mutually exclusive needs cannot substitute: per-episode artifact scoring must follow declarations without leftover foreign arrays changing project routes, opposite editing's data-first requirement.
- **Agent enqueue tools and data validation additionally pass a route gate**, a third entry point, not third resolver. `ensure_route_skeleton(script, content_mode, generation_mode)` first obtains required skeletons through declared resolution, then admits/rejects based on presence of the route's array. Cross-family mismatches (storyboard `segments`/`scenes`/`shots` ⟷ reference `video_units`) raise `SkeletonRouteMismatchError` with structural conclusions/re-splitting guidance; within-family shape differences and leftover foreign arrays pass honestly. Return depends on route: reference routes only ask whether `video_units` exists, returning it regardless of residual storyboard arrays (matching estimates: routes determine paths, shapes do not vote); storyboard routes return forensic answers. Neither resolver alone suffices for generation: declarations alone can falsely report all generated against absent arrays; forensic-only lets history override selected routes. The gate guards only generation, not viewing/editing/project archives (Jianying draft export separately takes clips from canonical script-content_mode skeletons; see `docs/adr/0055`).
- **Declared resolution fails loudly**: unknown/missing content_mode raises `ValueError` at call time; remove `script_shape()`'s historical drama fallback. `project.json` already requires/validates content_mode; existing defaults disagree (script_shape/data_validator choose drama, text_generation/resolve_kind ultimately narration), so silent defaults hide damage and change another consumer's behavior. Table consistency (four complete rows, valid fields) fails fast at import, like `docs/adr/0039`.
- **Narrow table**: no validation hooks/edit allowlists/other behavior. Admission requires skeleton structural facts without upward dependencies. Keep four data_validator functions, replacing only homemade axis interactions with declared resolution; editing allowlists await script_editor dual-implementation consolidation.
- **Test shape**: central matrix (table consistency, every declared combination including reference_video → video_units for all three content modes, every forensic ladder step, fail-loud) plus one exhaustive table-key-parameterized assertion per skeleton-dispatching consumer. A fifth skeleton fails every unhandled consumer's tests instead of repeating silent ad omission.

## Explicitly rejected

- **Composite `(content_mode, generation_mode)` registry keys**: both determine canonical skeletons, but belong only in compact declared-resolver mappings. Key structure tables by resulting kind without duplicating `id_field` / `chars_field` across six combinations.
- **ASSET_SPECS-style wide tables carrying behavior**: those work for homogeneous CRUD-factory consumers; skeleton consumers are heterogeneous (validation/export/billing/events). Four validators have differing signatures (shots needs products, scenes language); forcing uniformity creates false abstractions and reverse-couples server behavior into lib leaves.
- **Tiered "missing defaults to narration"**: roughly half historically defaults to drama; choosing either silently changes other code. Fail explicitly instead.
- **Regex interception tests (CI bans binary-fallback ternaries)**: rejected after review; enforce `docs/adr/0033` prohibitions through exhaustive assertions/review.

## Consequences

- Fix `project_events` snapshots alongside consolidation, without separate temporary PRs, restoring storyboard events to ad/reference_video. Derive video_units snapshot `characters` by filtering character-type `references`.
- Removing `script_shape()` fallback changes behavior; individually verify inputs from all 4 existing consumers.
- Classify approximately 45 literal content_mode dispatches: skeleton/structure (migrate to tables/resolvers), content/behavior (script_plan paths, prompt selection: legitimate content_mode dispatch, retain), axis-interaction business rules (such as skipping storyboard estimates for reference routes, retain). Classification inventories, PR splits, and keeping/removing scattered dispatch tests belong to PRD.
- Status is accepted: implemented in `lib/script/script_skeleton.py` (`SKELETONS` narrow table + declared `resolve_declared_kind` + forensic `resolve_script_kind` + gate `ensure_route_skeleton`); implemented names appear in `GLOSSARY.md`'s "Skeleton" entry. Future composite keys, registry behavior, or restored silent fallbacks require deprecating this ADR first.
