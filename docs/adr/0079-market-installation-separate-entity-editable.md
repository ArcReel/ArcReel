# 安装记录是独立实体，已安装端点可原地编辑、不锁定

从市场安装一个调用端点，落地的是一行普通的自定义调用端点，加上一条「它来自哪个市场源的哪个条目」的绑定。我们决定**这条绑定作为独立实体 `market_installation` 存放，与端点 1:1，记市场源规范键（字符串，不是外键）、slug、安装时的版本与定义摘要**（摘要 = 解析后的定义经 `lib/content_digest.py` 的 `prefixed_canonical_json_digest` 得到的带 `sha256-v1:` 前缀的规范化 JSON sha256，安装写入与本地修改判定用同一个函数，空白与键序差异不算修改，前缀让日后换算法时能分辨旧行），不放在 `custom_endpoint` 表上：该表的不变式是「除 `definition` 外的列都是由定义派生的只读镜像」（`docs/adr/0067`），而安装记录不是镜像，是有独立生命周期的事实；规范键用字符串而非外键，是让删除市场源不抹掉已安装端点的来源；键由地址归一化得到：`owner/repo`、`owner/repo@ref`、`https://github.com/owner/repo[/tree/ref]` 三种写法归一为 `github:owner/repo@ref`（缺省 ref 为 `HEAD`）；以 `arcreel-market.json` 结尾的任意 `https://` 直链（含 raw 地址）归一为 `url:<索引地址>`，直链不反推成 `github:` 键——同一仓库用两种写法添加就是两个市场源，这是可接受的边界。同一写法删了再加得到同一个键，既有安装记录自动重新对上，不会出现一源两条记录。「已安装」严格按安装记录判定：本地存在同作者、同名的定义（用户此前手工导入的文件）不算已安装，安装时走导入对话框的三选——覆盖那份既有定义（安装记录挂到它）、另建一行新端点（安装记录挂到新行）、或取消。**覆盖只对没有安装记录的端点开放**：同作者、同名的端点若已持有另一来源的安装记录（典型是官方源与其 fork 各收录了同一份定义），在三选里只展示「已从 X 安装」、不可选，用户只能另建新行或取消；不做安装记录的跨来源转移，与「不提供解除跟随」同一条线。无论哪条路，一个市场条目在本地至多一条安装记录：唯一约束一条落在端点 id（1:1），一条落在（市场源规范键, slug）。

**已安装端点可原地编辑，不锁定。** 内置调用端点的模式是只读 + 「复制为我的」（副本不跟随上游）；市场端点不沿用它：改一个请求头就得复制再重挂模型行，摩擦太大。代价是本地修改会被更新覆盖，用「本地修改」状态承接——安装记录里的定义摘要与当前定义不一致即标已修改，更新确认页明确警告并提供先导出。状态因此是两个正交的轴：市场轴（最新 / 可更新 / 市场中不可用）与本地轴（是否已修改）。**不提供解除安装记录的动作**（讨论过的「停止跟随市场」不做）：已安装端点只有更新、删除或带着徽标继续用三条路，将来有需求再加一个动作即可。可更新只看安装记录里的版本与索引版本字符串是否相等，不看本地定义的 `meta.version`，用户改版本号不影响判定；更新走与安装同一张确认页并原地覆盖，键与模型行不动。版本字符串是唯一的更新信号：同版本改了定义内容不会被判可更新，这是有意的——刷新只读索引、不逐条抓定义，索引也不放载荷摘要（`docs/adr/0078`）；官方仓靠投稿审查要求内容变更必升版本，第三方源由用户自担。

## 对此前导入决议的修订

分享文件格式定稿时曾定「导入后不记 provenance（文件名、来源 URL）」：定义 `meta` 里的作者与名称是仅有的、能跨实例指认同一份定义的信息，版本只说明新旧。本 ADR 修订为：**安装来源要记，但记在端点定义之外**——定义本体仍是协议唯一真相、导出字节不变，安装记录只是旁边的一条事实。从本地文件导入维持不记来源。

## Consequences

- 安装是服务端单事务接口（抓定义、比对索引一致性、校验、建或覆盖端点、写安装记录），不由前端四步编排——安装记录的唯一约束与「记录里的摘要 = 落库的定义」只有单事务能保证。
- 卸载就是删除端点，安装记录级联删除，被模型行引用时沿用 409 与引用清单。
- 将来提示词 / 风格模板进入市场时，各自再加一个可空外键列或另起安装记录表，不复用端点的这一张。
