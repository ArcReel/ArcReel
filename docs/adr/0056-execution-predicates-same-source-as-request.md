# 执行期判据与真实执行路径同源

判断供应商执行行为的代码（计费口径、成片是否有声、校验放行）曾读 ArcReel 侧配置的中间字段做推断——如按配置的分辨率或质量档推断供应商会不会产音——而供应商只按请求体里的字段行事。配置与请求构造之间隔着归一、回退、截断、口径叠加等变换，推断在每个变换点都可能失真，产生「请求人声但成片无声、仍按有声价出账」一类表里不一的缺陷。决定：**执行期判据一律取自会真正发给供应商的字段，与请求构造同源**——判断某段行为是否发生，读它的真实输入；需要同一变换时调用同一函数，不在判据处另算一遍。

## 明确不采用

- **按 ArcReel 侧中间字段推断供应商行为**：中间字段到请求字段的变换（能力回退、计费口径叠加、静默截断）对判据不可见，边界场景必然分叉。
- **在判据处复制请求构造逻辑**：两份逻辑没有共同真相源，改一处漏一处；判据应复用构造路径的产出或其同一变换函数。
- **用计费口径字段兼任请求口径判据**（反之亦然）：两种口径各自叠加了不同规则（如恒按含音出账的供应商特例），互相兼任会在特例供应商上恒真或恒假；两口径并列透出、各自取用。

## Consequences

- 能力、计费、校验类判定的取值路径须可追溯到请求体字段，或与请求构造共用同一变换函数；review 时对「读配置推断执行行为」的写法按本原则质疑。本原则约束的是决定实际执行行为（计费、校验放行）的判据；入队前的候选收窄或预检（如时长档位预检、UI 候选过滤）允许按项目配置近似解析，前提是调用方明确知道结果是近似值、实际执行按供应商真实输入重新判定。
- 声明层同构：视频能力真相源按字段归 backend 声明（`VideoCapabilities`）、与请求构造同源（见 `docs/adr/0054`），是本原则在静态声明侧的对应；图片等其余能力字段的声明层真相源另见 `AGENTS.md`「供应商能力数据」。
