# 分集源文采用唯一规范路径，补零别名在迁移边界一次性归一化

每集原文在磁盘上只有唯一规范路径 `source/episode_N.txt`（`N` 为无前导零的正整数）。写盘与状态读取早已统一到该路径，但历史上读侧与部分清理入口仍兼容 `episode_01.txt` 等补零别名，导致同集多文件并存时按文件名排序读到旧稿，手工调整边界、丢弃或重规划替换旧集后也可能残留补零旧文件。

不在各业务入口继续维护补零别名兼容分支，而是在项目结构迁移 v21→v22（[v21_to_v22_episode_source_names.py](../../lib/project/project_migrations/v21_to_v22_episode_source_names.py)）建立一次性归一化边界，遵循 [ADR 0125](0125-episode-planning-reset-preserves-unproven-files.md) 的文件级可重建证明与用户数据保护原则：

- 规范文件已存在时保持不动；同集号的非规范别名仅在常规文件且字节与账本唯一可读 `source_range` 切片一致、或与规范文件字节完全一致时清理，其余另存为永久保留副本（`source/<别名>.kept.v21-<时间戳>`）并写入迁移报告。
- 规范文件不存在时，仅当账本登记了该正整数集且原文来源非 `none`、且未曾留底过同集 v21 冲突副本时，才在无歧义情形（单一常规别名、多份同字节常规别名、或有常规别名命中 `source_range` 切片）下将文件改名落位为 `source/episode_N.txt`；冲突且无法证明归属的别名、符号链接、无原文集或未登记孤儿别名以及 `episode_0.txt` 一律另存为保留副本。
- 迁移按「先落位规范文件、再留底冲突副本、最后清理可重建别名」的顺序逐集执行并最后提交 `schema_version = 22`，异常回滚且中断重跑收敛到同一终态；归档导入旧 ZIP 经同一迁移链归一化。

迁移完成后，正常业务的读取、手工切分、重规划、重置与删集均只识别 `source/episode_N.txt`。整本源文上传仍保留对 `episode_[0-9]+.txt` 名称的占用校验，避免新项目重新引入歧义文件名。
