# 拆耦已登记与未登记模型的输出上限，结构化截断明确报错

把文本输出上限当作省钱预算曾把正常的大批次结构化结果切断；反过来，对目录中未登记输出上限的自定义或中转模型一律硬传统一安全上限（64000）并据此推导大规划批次，既会触发小输出模型 400 拒收，也会让分集规划一次请求过多集数而截断。

文本生成将「请求输出上限」与「规划批次估算预算」拆耦，并由 [文本生成器](../../lib/backends/text_generator.py) 统一收口（业务调用点默认不硬传 64000，仅在有意收窄时传入更低值）：

- **已登记模型**：请求输出上限与规划批次推导均采用 `min(模型登记最大输出长度, 64000)`。
- **未登记模型**：协议允许省略 `max_tokens` 时请求不传该参数，由上游按模型自身上限执行；必传该参数的协议（如 Anthropic Messages）发送保守默认值 `16384`。分集规划等需按输出上限估算批次大小的调用，统一按保守预算 `8192` token 推导小批次，方案见 [ADR 0032](0032-episode-planning-server-side-batched.md)。模型事实与渠道覆盖的边界见 [ADR 0104](0104-capability-sources-split-by-dimension.md)。

结构化响应触顶时返回 `TextOutputTruncatedError`，指出当前模型并引导换用输出能力更高的模型或在自定义模型页登记准确的最大输出长度。重发相同请求仍会触顶，截断错误直接结束结构校验重试（分集规划的同窗缩半批重试见 [ADR 0032](0032-episode-planning-server-side-batched.md)）。自由文本截断默认只记录告警并返回部分结果，调用方要求完整结果（`require_complete=True`）时也抛出 `TextOutputTruncatedError`。
