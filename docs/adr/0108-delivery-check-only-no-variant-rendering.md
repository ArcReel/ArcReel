# 平台交付检查只报告，不阻断渲染，也不渲染多平台变体

成片最终要发到抖音、TikTok、YouTube 这类平台，每个平台有自己的上传规格（画幅、时长、编码、文件大小、响度）与播放页 UI 遮挡（顶部状态栏、底部标题区、右侧操作列）。渲染只产出一份文件，交付合规性由一次只读的检查给出：`lib/delivery/platforms.py` 的 `PLATFORMS` 是交付规格的单一数据源（v1 六个平台：douyin、tiktok、youtube、bilibili、x、instagram），`check_delivery` 用 P0 的媒体探测加 P1 的实测响度逐项校核，输出 PASS/WARN/FAIL 行（字段、期望、实测、文案键与参数，前端按 locale 渲染）。

渲染任务按项目画幅推导默认平台（横屏 → youtube，竖屏与方屏 → douyin），对渲染出的文件检查一次，结果挂在 `FinalCutRender.delivery` 上并写进工具摘要；成片状态接口带可选 `platform` 查询参数按需重查。烧入字幕的版式用默认平台的安全区收缩行宽、水平居中并抬高底边距；没有安全区可套时回退 `lib/subtitle_style/baseline.py` 的默认版式。

## 规则

- 交付检查只报告：不阻断渲染、不改渲染参数、不重渲，也不为每个平台渲染变体；FAIL 行只是结论，处置（改时间线、换平台、人工裁时长）留给编辑与 Agent。
- 检查输入是交付文件的实测值（P0 探测 + P1 响度重测），不是渲染参数：文件探测不出时该次检查没有结果（`delivery` 为 null），不让渲染失败。
- 默认平台只由画幅决定；用户按 `platform` 参数请求其他平台时按该平台规格重查，未知平台是请求错误（422）。
- 响度与真峰行按平台目标（v1 统一 −14 LUFS ± 2、−1.0 dBTP）判 WARN 而非 FAIL：平台侧自身归一/限幅会兜底，偏差影响的是听感预期，不是能不能上传。
- 安全区数值是 v1 标定值：平台公开规格加竖屏播放页布局估算，各平台条目注明来源与标定日期；修订时只改表，不改检查逻辑。
- 平台规格表是单一数据源：新增平台等于表里加一行加三语文案，不改检查与版式代码。

## Considered Options

- **按平台渲染多变体**：每个目标平台一份文件（裁时长、重编码、不同字幕版式）会把渲染耗时与磁盘乘以平台数，且项目画幅已经选定主方向；逐平台的取舍是编辑决定，不该由渲染器替它做。
- **FAIL 阻断渲染**：检查项里有依赖上传者档位的项（如 X 免费档 140 秒），误判会挡下合法渲染；渲染链路本来就不以平台合规为验收条件。
- **把安全区做进 `lib/subtitle_style/baseline.py`**：基线是剪映样式到画布的换算，对没有 UI 遮挡的场合（剪映草稿、直接下载）仍要用默认版式；平台安全区是交付侧概念，只在套了平台规格时生效。

## Consequences

- 工具摘要与前端成片面板多一段交付结论（一行结论加非通过行明细）；Agent 可据此建议，但不能强制合规。
- 成片状态接口在文件存在时会多一次媒体探测与响度实测（按需重查路径），响应时间随文件时长增加。
- 检查行的文案键进 `lib/i18n` 与前端 i18n 的三语文案集，新增平台与新增行要同步三语。
- 安全区数字尚未对照真实播放页截图标定；P3 的逐帧对照（contact sheet）可以人工核对后再修订表中数值与标定日期。
