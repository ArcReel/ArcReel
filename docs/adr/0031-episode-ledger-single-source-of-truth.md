# 分集以 project.json 账本为单一真相源，物理集文件降级为同锁派生物

旧拆分流程以物理文件本身为真相（`episode_N.txt` 存在即已拆、`_remaining.txt` 滚动覆盖作进度指针），没有任何"第 N 集对应原文哪一段"的显式记录——下游选错文件无从对账，后续集靠 Glob 推断集数易错，`_remaining.txt` 损坏即不可恢复。决定把分集真相源并入 project.json `episodes[]`：条目记录集原文来源，切自整本源文的集带原文素材范围（source_range，narration 为精确切分点、drama 为软素材范围）、钩子（hook）与 drama 分集大纲；条目带消费状态字段（ledger_status，planned/consumed/stale 三态，咨询性——能否重造派生文件或续接规划不看该字段，而看 source_range 结构是否完整、引用的源文件是否存在、范围是否在界内、指纹是否与已记录一致）；条目的先后即播出顺序（见 `docs/adr/0096`）。顶层增加 planning_cursor 标记下一批规划起点、source_fingerprints 按候选源文件相对路径记录 `normalize_source_text` 输出文本的 SHA-256 指纹，用于检测规划中途源文件被外部替换。切出集的物理 `episode_N.txt` 降级为派生物，由规划与手工切分在同一把项目锁内随账本一并重写并清理账本之外的残留文件，不一致窗口为零；`_remaining.txt` 废除。存量项目沿 ADR 0022 启动迁移只盖版本章，不按内容反推原文范围：旧拆分流程切出的集仍是切自整本源文的集，只是没有原文范围，照常消费；分集规划遇到它们拒绝执行，要重新规划须从第 1 集起。

## 集原文的三种来源

一集的集原文有三种来源：由分集规划从整本源文切出的一段范围（记 `source_range`）；该集自带的一份原文（创作者逐集上传或直接填写，集文件即该集的源文）；或者没有原文（手写脚本）。三种是并列的正常形态：

- 集文件是派生物还是源文，由账本条目记录的来源决定，不按 `source/` 目录里有没有整本原文整体推断——同一项目可以既有整本源文，又有自带原文或没有原文的集。
- 自带原文或没有原文的集不占用整本源文，也不挡分集规划：分集规划只消费整本源文，读取起点取规划游标。
- 切出集的原文范围互不重叠、按源文位置排列；删除中间的切出集后，它那段原文成为未切分的原文，切出集之间因此可以有空段。
- 重置分集规划只把切出集退回未规划状态，重新规划只替换切出集；另外两种集留在账本里，范围内夹有它们也照常执行。重置不改变它们之间的相对顺序；重新规划采纳时它们的落位见 `docs/adr/0032`。
- 自带原文的集可以编辑其原文；切出集的集文件仍是派生物，修改走账本重派生，手工编辑或重命名 `episode_N.txt` 不被支持。
- 逐集原文以显式登记进入账本：创作者上传时选择「整本源文」或「逐集原文」，后者可以分多次追加，按上传顺序排到播出顺序末尾，文件名不决定集的位置。

## Considered Options

- 维持物理文件真相源、仅包装更可靠的单一工具：对账依据依旧缺失，"不同集生成了相同内容"类事故无从检测。
- 独立账本文件或 DB 表：集的概念裂成两处需要对账；DB 与"项目级数据一贯在文件系统"的分层相悖，导出/迁移/备份路径全部复杂化。
- 不派生物理文件、下游按范围直读源文：三个预处理 subagent 与 Web 端展示全要改造，爆炸半径过大。
- 消费时按需派生：永不陈旧，但"agent 记得先调派生工具"把可靠性又押回流程遵循。
- 按内容反推存量集的原文范围：派生文件与源文的差异只可能来自人工编辑，近似锚定会让账本失真。

## Consequences

- 新 session 接续 = 读账本，废除 Glob 推断集数与 `_remaining.txt` 进度指针。
- 失效是标记（stale）而非删除：原文范围被改动、或在重新规划中被替换下来的集，旧产物保留，重做沿现有覆盖/版本机制替换，贵重媒体产物不因规划调整丢失。
- source_range 绑定的是规划当下的原文内容，原文被替换后会让坐标失真而无从察觉；source_fingerprints 把这条隐含前提显式化为可机械校验的证据，规划提交与部分重置的前置校验均比对，不一致即拒绝，出路是从第 1 集起的重新规划。
