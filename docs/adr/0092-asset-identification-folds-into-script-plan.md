# 资产识别并入逐集脚本规划：全书资产提取与资产清单闸门退役

原流程在分集之前由一个子智能体通读整本源文，一次性登记全部角色、场景与道具，并以源文修订号判定这份资产清单是否现行；清单不现行，分集规划及其下游全部停住。这让长篇源文要整本进入一个上下文，源文改动一个字节就让整份清单过期，Web 要提供一键提取就得另写一个读全书的服务，而逐集自带原文、无源文的自由创作都与它不相适配。脚本对资产的依赖却是真实的：脚本规划的产出只允许引用已登记的资产，引用未登记的名字即成待修复草稿。

决定把资产识别放进**逐集的 AI 规划脚本**：规划一集时以已登记资产（名字与描述）为上下文，本集出场的资产已登记即直接引用；未登记的作为「本集新增资产」随规划一并产出（含视觉描述）；已登记角色在本集以另一套外观出现时，产出「新增衍生」，只写相对本体的变化（判据同 `docs/adr/0072`）。规划从不修改已登记资产的描述。内容确认时，创作者对每个新增项选择：采用（可改名、改描述）、归到已有资产、归为已有角色的新衍生，或不登记；确认即与正式脚本一并登记，引用随所选处理改写。规划校验从「引用须已登记」放宽为「引用须已登记或在本次新增项中」。

全书资产提取随之退役：资产清单的完成标记、制作状态中的资产清单一步、对应的建议动作、提交提取结果的 Agent 工具与读全书的提取子智能体一并移除。分集规划不依赖资产；AI 规划脚本的准入只剩「本集有集原文」（`docs/adr/0091`）。

## Considered Options

- **维持分集前的全书提取**：跨集命名一次定死，但承担上述全部代价，且清单过期会挡住与资产无关的操作。
- **并入分集规划**：分集规划本就分批读源文，可顺带识别；但只覆盖整本源文，自带原文的集不经过分集规划，仍需第二条识别路径。
- **逐集识别之外保留全书提取作可选操作**：两条路径长期并存，重复与冲突要各自处理；「先把主要角色建出来」的需求已由手工新建资产、资产库导入与 Agent 登记满足。

## Consequences

- 同一人物在不同集被起不同名字的风险，靠带入已登记资产表对齐，并由内容确认时的「归到已有资产」兜住；创作者改名后再出现的旧名同样在此归并。
- 角色首次出场时写下的描述可能不全，后续集不会自动补充，只能由创作者修改；外观变化走衍生，不改本体。
- 没有集原文的集（手写脚本）不经规划，资产照旧手工登记。
- 存量项目已登记的资产照常使用；遗留的资产清单完成标记不再参与任何判定。
