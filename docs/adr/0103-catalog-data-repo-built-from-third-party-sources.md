# 模型目录由公开仓库构建和发布，实例独立同步

各上游的格式与覆盖面不同。由 [ArcReel 目录数据仓库](https://github.com/ArcReel/arcreel-catalog) 接入第三方模型元数据，叠加人工维护的结果，再用应用共用的 [目录格式与校验器](../../packages/arcreel-catalog-core/README.md) 校验和发布。媒体模型清单由人工维护，文本清单可按上游映射和过滤规则生成。实例只消费 ArcReel 格式的数据，旧版遇到无法认识的价格规则时按未定价处理，整份校验或解析失败则继续用上一份可用数据。

官方同步复用 GitHub raw 代理配置，请求无需实例身份，也不经过官方服务。实例自动整批应用较新数据，用户已接管的条目保留。上游删除的条目在已取得它的实例中仍保留最后一版，供存量配置和计价引用。内置供应商的官方清单随数据更新，条目与清单归属见 [ADR 0099](0099-model-catalog-shared-entries-per-model.md)。实现入口见 [官方同步](../../lib/catalog/official_sync.py)。

## 端点发布与应用版本

请求协议随应用代码发布，某个供应商模型挂哪个端点随目录数据发布。构建必须为官方模型声明端点，并按端点清单验证媒体类型及供应商归属。最低应用版本取挂接端点的起始版本、人工标记和多端点供应商开始读端点声明的版本所要求的最高值。基线模型经过核对后可豁免最后一项，避免给旧版本已能正确调用的模型虚设门槛。应用与目录构建共用端点清单中的媒体类型、可选端点与默认端点。CI 校验清单与内置装配及自定义端点注册表一致。清单与版本推导见 [端点清单](../../packages/arcreel-catalog-core/src/arcreel_catalog_core/endpoints.py)。

新端点的起始版本取合入时记录版本的下一个补丁号，以覆盖最终发的是补丁版或次版本的两种情况。为已发布端点扩展合法取值可原地扩展，无需抬高端点的起始版本。旧实例按已安装的实现处理新增值，包括在本地拒绝映射不到的枚举值，或把值交给上游。

目录以 ArcReel 最新发布版本判断哪些模型可发布。高于它的门槛本轮暂缓，否则用户会看到尚无法下载的版本要求。暂缓的是推荐模型时，沿用上次仍合格的推荐或留空，其余目录照常发布。读取最新发布版本或目录构建失败时保留上次数据。应用发布会触发新一轮目录构建，镜像发布可以独立完成，避免被外部数据源故障拖住。实例低于一条数据的最低版本时，模型仍可显示升级要求，不能被启用、选为运行候选或用于自动推荐填充。

## 生命周期与旧版推荐

生命周期属于模型厂商和模型条目，对各供应商统一生效。关停按 UTC 日期判断，关停当天即已下线。官方清单在退役后继续发布 90 天以提供关停与后继提示，纠正收录错误可直接删除。后继按原模型定位与实际替代性推荐，优先核对模型厂商的迁移目标，但不限于厂商点名，没有合适替代时留空；它与内置供应商的推荐模型独立，避免把能力口径不同的主力推荐强行当作旧模型的整型号替代，单个供应商是否提供该后继由其官方清单决定。项目和设置的模型引用继续保留，用户选择是否切换后继，避免静默改变生成结果及费用。

0.36 及更早版本仍以官方推荐参与运行时选择。改变已发布的推荐，或为原先没有推荐的媒体类型新增推荐，需要考虑这些仍在运行的实例会随同步改变生成用模型；发布处理参见 [ADR 0099](0099-model-catalog-shared-entries-per-model.md)。按目录校验规则处理已退役推荐仍沿用既有退役换模语义。
