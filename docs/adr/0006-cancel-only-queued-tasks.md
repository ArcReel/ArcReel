# 用户只能取消排队中的生成任务

生成任务被 worker 认领后，供应商调用按原路径完成。终止本地等待不会取消供应商的生成或费用，却可能丢失用户已付费的产物。此前曾允许取消执行中的任务，但为此引入了额外的过渡状态以及贯穿各写入路径的撤销协议，最终已撤回该方案。

- 取消单个任务时，若任务已开始执行，接口直接返回冲突。批次取消和项目级全部取消只影响排队成员；依赖被取消任务的下游排队任务按依赖关系级联取消。
- 服务关停优先等待在途任务。执行被进程级原因打断时，终态可以是 `cancelled`，来源记为 `interrupted`。用户取消记为 `user`，级联取消记为 `cascade`。重启后的在途任务另按 [ADR 0007](0007-orphan-tasks-not-requeued-on-restart.md) 处理。
- 升级迁移把旧 `cancelling` 记录收敛为 `cancelled`，同时处理仍在排队的下游。现行状态转移以 [任务仓储](../../lib/db/repositories/task_repo.py) 为准。

重新开放执行中取消，前提是供应商能提供可依赖的取消与费用语义。
