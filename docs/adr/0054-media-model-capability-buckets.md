# Configure image/video models through capability buckets: one default plus optional overrides

> `docs/adr/0104` supersedes "custom-provider audio shapes cannot have model-level overrides": user-owned provider models can replace audio shape as a whole dimension like other channel facts. Without overrides, custom-provider audio still follows "no signal, no tightening."

Some video models support only partial capabilities (i2v only, no reference slots); one video-model setting cannot express this, delaying wrong-model failures until reference-video execution. Unify image/video configuration as **one default model + optional capability buckets**: image t2i / i2i, video i2v / r2v. Resolve project-first like text tiers (`docs/adr/0051`): project bucket > project default > global bucket > global default > automatic inference; empty buckets fall back to defaults. Code fixes call-site mappings: images follow actual execution request shape (`docs/adr/0001`); video first follows **immutable project generation routes** (`lib/config/resolver.video_bucket_for_generation_mode`, predicate `project_manager.is_reference_video_project`), without script route information and identically across three content modes (`docs/adr/0055`). Storyboard routes, including grids, use i2v. Reference routes then follow actually usable shot references: present → r2v; **reference-free degraded shots → i2v**. Reference quotes, Web/Agent preflight, rate limiting, and execution first hydrate current assets through `lib/script/reference_video/request_projection.py`; declared/actual divergence returns declared→hydrated results and structured blockers, never silently switching buckets/models. This consolidates image-slot configuration without changing `docs/adr/0015` endpoint separation/runtime gating.

## Explicitly rejected

- **t2v buckets**: their sole call site is reference-route empty-reference fallback, already served by i2v configuration/resolution gates. A third text-only bucket needlessly expands settings. Fallback changes the success question from r2v accepting empty references to i2v accepting text-only requests, without guaranteeing execution: i2v checks only `first_frame`; image-only Vidu `viduq3-pro-fast` / `viduq1-classic` / `vidu2.0` are outside `/text2video` allowlists and still fail explicitly on empty references. This narrow image-only residual is much smaller than mainstream r2v models rejecting empties (DashScope R2V, MiniMax S2V `video_reference_images_required`), resolvable by reconfiguring i2v.
- **Models configured by generation route**: routes describe source paths, not capabilities, missing the original partial-support problem; route changes would directly expand settings.
- **Mandatory buckets without defaults**: full-capability models are common; forcing all buckets burdens most users and gives flat dropdowns no hierarchy. Defaults with optional detail constrain configuration surface.
- **Silent model substitution on capability failure**: users unknowingly pay for unselected models. Return structured resolution errors directing corresponding bucket configuration, following text-vision precedent.
- **Write-side reference blocking/cascading cleanup**: dangling buckets from edited overrides, deleted models/providers, endpoint changes, or upgraded registry judgments all fail at resolution. Write interception reverse-scans distributed project.json files, expensive and race-prone; cascades silently change settings. Both routes reproject current configuration before submission; submitted tasks resume only through execution checkpoints without silent substitution.

## Consequences

- Preserve existing capability declarations without copies. Both buckets read backend `VideoCapabilities`: i2v `first_frame` (grids remain first-frame-driven), r2v `max_reference_images > 0`; custom providers combine endpoint judgments ⊕ model `capability_overrides`. Built-in video dimensions live only in backends, not registry `ModelInfo` capability/reference bits: one token cannot distinguish image/reference paths (such as reference-only `happyhorse-1.0-r2v`). Bucket dropdowns prefilter candidates; defaults do not promise capabilities and remain unfiltered.
- Audio-track presence/control likewise belongs to backend `VideoCapabilities`, **declared per bucket**: `audio_track` describes i2v, `reference_route_audio_track` r2v (omission means identical routes), accessed through `audio_track_for_route(capability)`. One model's paths may differ: Kling v3-omni multi-image-subject R2V lacks native `sound`, necessarily silent, while its image path is controllable. Disabled UI switches, admission rejecting audio-off for always-audio models, and voice-consistency derivation share declarations, truthfully showing absent reference-path switches instead of allowing ignored controls. Undeclared models default to `controllable` (no signal, no tightening), without falsely claiming unknown switches ineffective.
- Custom-provider audio does not join this derivation: always assume audio present/controllable without model overrides. UI lacks custom per-model audio catalogs (outside `/providers`); server-only inference would contradict preflight/UI. User-entered upstream names are unverifiable; mistaken always-audio classifications block valid settings. User declarations also lack execution counterparts: protocol backends either send switches or not; declarations cannot change that.
- All readers (`video_capabilities`, agent tools, estimates, duration/resolution narrowing) and execution resolve the same bucket/function. Project reads (`video_capabilities`, storyboard document previews) use routes without episode/script context or content-mode branches because units do not yet exist or are irrelevant. Reference shot reads (estimates, limiter projections, Web/Agent preflight) share execution request projections: read current project/script/unit, expand/validate assets, then choose buckets/providers/models/duration tiers. Projections are advisory, not executable snapshots, issuing no tokens/fingerprints; workers must reproject latest state. WebUI individual storyboard-video endpoints still use project routes, directly rejecting reference projects with reference-flow guidance (`docs/adr/0055`).
- Neither route locks provider/model on enqueue. Task `provider_id` is claim/rate-limit advisory; execution ignores old payload video-identity keys. Payloads hold task locations/user options, not frozen requests, so queued edits to projects/scripts/assets apply at worker start. Only nonreused videos actually approaching provider submission cross execution checkpoints: atomically persist actual provider/versioned full execution facts in dedicated task columns immediately before submit, without rewriting payloads. Polling/restart resume read checkpoints only, never recomputing current scripts/references/provider/model; current projects supply only credentials/construction. Explicitly fail if resolved identities/custom endpoints disagree with checkpoints. Agent `resume=true` re-enqueueing unfinished shots is separate, resolving fresh identities from current settings.
- Empty image buckets mean default-layer fallback, never automatic-inference-only; migrations exhaustively handle existing key combinations.
- Frontend model-based capability/configuration keys (`model_settings` resolutions, panels) use **executing models**: active buckets or fully resolved defaults. Video resolves project-route buckets first, shared with backend semantics and consistent across project episodes. One image exception: `executingImageModel` uses T2I execution identity for resolution keys; I2I executes independently. With different models, I2I finds no own `model_settings` key and falls back to provider resolution defaults. Defaults themselves are keys only when actually executing.
- Text tiers/image buckets/video buckets share UI: persistent main default dropdown + collapsible capability detail, unresolved placeholders showing fully effective models and covered call sites (zh / en / vi together). Creation exposes defaults only.
- Evaluate video execution models/capabilities once per request through "video request facts." If reference projects' i2v buckets are unavailable, reference-free units have unknown tiers, without r2v fallback; see `docs/adr/0086`.
