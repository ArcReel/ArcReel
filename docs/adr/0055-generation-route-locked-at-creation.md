# 生成路线创建时锁定，宫格降为分镜路线内的装配选项

`generation_mode` 是项目的**生成路线**，二值必填：`storyboard`（分镜图生视频）与 `reference_video`（参考生视频）。路线在创建项目时二选一、创建后不可更改——不可变性由结构保证而非校验规则：项目 PATCH 模型、集级 PATCH 模型、agent 项目设置白名单中都不存在路线字段，没有任何写入面可以改它。宫格不是路线，由独立的项目级布尔 `grid_storyboard` 表达（默认 false，仅分镜路线有意义，ad 内容模式恒拒），随时可切。

**区分路线的判据是喂给视频模型的输入契约**：分镜路线的输入是单张分镜图（i2v，首帧驱动），参考路线的输入是资产参考图集合（r2v，参考图槽位驱动）。宫格改变的是分镜图**从哪里、以什么方式被生产出来**——多个场景合成一张 N 格大图一次生成、再切割成各场景的起始分镜图——切割后仍是单张图走 i2v，输入契约与逐张分镜完全相同，故它是分镜路线内部的装配选项，不是第三条路线。业界事实支撑见 `docs/research/storyboard-to-video-industry-survey.md`：无任何主流模型的公开 API 原生接受「一整张多格分镜板图」一次输出多镜头连续视频；跨厂商术语一致的独立范式只有 r2v 与首尾帧两种，前者即本文的参考路线，后者是 i2v 内的关键帧子模式。各家名为 storyboard 的产品功能各自是什么形态、证据到哪一级，以该调研文档为准。

路线锁定使剧集与剧本都不再承载路线信息，整个项目由单一字段定轴：剧本骨架（`docs/adr/0045` 的规范解析）、视频能力归桶与声音一致性档位（`docs/adr/0054`）、时长联动约束、费用估算、生成入队一律读项目 `generation_mode`，读侧不需要剧集上下文——时长联动约束里的参考图档位是例外，路线只决定这条约束适不适用，具体收窄按该单元实际是否带参考图（`uses_reference_images`）判定；估算与执行同读项目路线，不存在「估算按一条路、执行按另一条路」的分歧空间——例外是 WebUI 的逐条生成端点：该路径按剧本实际骨架取条目、不读项目路线，入队预检与执行一律按 i2v 归桶——除骨架与路线失配的存量剧本外，`ad` + 参考路线这类骨架合法（`shots` 恒定，见 `docs/adr/0033`）的项目在该入口上同样是执行按 i2v、查询与估算按 r2v。存量项目由项目迁移框架的 v4→v5 迁移器一次性重编码（`lib/project_migrations/v4_to_v5_generation_route.py`）：三值 `grid` 展开为 `storyboard` + `grid_storyboard=true`、字段缺失补写显式 `storyboard`、剔除全部集级路线覆盖字段，剧本文件不动。骨架与项目路线跨族的存量剧本由智能体的生成入队工具与数据校验经路线闸门 `ensure_route_skeleton` 显式拒绝并给重拆指引；WebUI 的逐条生成端点按剧本实际骨架定位条目、不经闸门；查看、编辑与项目归档导出同样不受影响，剪映草稿导出按剧本 content_mode 的规范骨架取片段，失配剧本取不到已完成片段。

## 明确不采用

- **集级路线覆盖**：让某集单独走另一条路径，等于把「项目按一条路径生成」降格为逐集属性，能力查询、费用估算、时长约束全部要携带剧集上下文才能回答，且用户在项目级看到的口径与某集实际执行的口径可以长期不一致。跨集混排的需求由「另建一个项目」表达。
- **剧本携带路线戳**：路线写进剧本 JSON 会产生第二个真相源——剧本戳与项目字段可分歧，失配时任何一方赢都是错的（按戳走等于用历史数据否决用户当前配置，按项目走等于静默换掉这份剧本实际能生成的路径）。路线是项目属性，剧本只承载内容与结构；存量剧本残留的戳字段作未知字段忽略，重生成即消失。
- **读时映射（兼容分支）**：把三值旧值在读取时映射为「路线 + 宫格开关」，可以省掉一次迁移，但代价是每个读点都要重复这条映射、且写侧仍能写回旧值，映射永远删不掉。改以一次性迁移完成重编码，读侧不再有旧三值的映射分支，路线本身也无默认回退（缺失即由迁移补写显式值）。能力解析对表外与非字符串路线值统一落 i2v 桶（`lib/config/resolver.video_bucket_for_generation_mode`），是对手工改坏的 project.json 与无项目上下文查询的脏数据防御，不是旧值的兼容映射。
- **宫格作为第三条路线**：见上文判据——它不改变模型输入契约。把装配方式与生成路线并列在同一个选择器里，会让「分镜图怎么画」的优化项被读成不可逆的立项决策，也会让每处按路线分派的代码多出一个与另一支行为完全相同的分支。
- **宫格开关进 agent 白名单**：agent 被要求改装配时指引用户去设置页，被要求改路线时告知不可更改。装配开关决定后续分镜图能否按宫格批量生产（宫格入口与费用估算读 `grid_storyboard_enabled`；逐条分镜生成入口不检查它，单张重出照旧），属用户的显式设置动作，不经对话旁路。

## Consequences

- 创建请求的 `generation_mode` 必填、无默认值，缺失即 422——不存在「没选就悄悄锁进某条路线」的路径。`grid_storyboard` 可随创建写入；ad 项目对 `grid_storyboard=true` 在创建、PATCH、数据校验三处一致拒绝。
- 前端向导以两张卡片承载路线二选一（无预选、必选），分镜卡内嵌宫格开关，并在向导上明示「生成方式创建后不可更改」；设置页只读展示路线，宫格开关随时可切且只影响后续生成，已有内容不动。
- 存量集级覆盖产生的失配剧本（如分镜路线项目下的 `video_units` 骨架）经智能体入队生成时得到结构结论与重拆指引，不静默降档；这些剧本仍可查看、编辑、归档导出，WebUI 逐条生成与剪映草稿导出的边界见上文。
- 「首尾帧作为独立范式」是调研的附带观察（`docs/research/storyboard-to-video-industry-survey.md` 四.3）：ArcReel 的尾帧目前是 i2v 路径上的可选过渡控制手段，是否值得升格为独立建模不在本 ADR 范围。
