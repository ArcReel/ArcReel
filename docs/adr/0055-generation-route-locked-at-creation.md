# Lock generation routes at creation; grids become an assembly option within storyboard routes

`generation_mode` is the project's required two-valued **generation route**: `storyboard` (storyboard-image-to-video) or `reference_video` (reference-to-video). Choose one at creation, immutable afterward through structure rather than validation: project PATCH models, episode PATCH models, and agent project-settings allowlists contain no route field, leaving no write surface. Grid is not a route; independent project boolean `grid_storyboard` (default false, meaningful only on storyboard routes and always rejected for ad) can change anytime.

**Routes differ by the input contract fed to video models**: storyboard inputs are single storyboard images (i2v, first-frame driven); reference inputs are asset-reference sets (r2v, reference-slot driven). Grids change **where and how storyboard images are produced**: combine several scenes into one N-cell image, generate once, then slice initial storyboards per scene. Each sliced image still uses i2v with the same contract as individual storyboards, making grids internal assembly, not a third route. Industry support: no mainstream model's public API natively accepts "one complete multi-cell storyboard board" and outputs continuous multi-shot video in one call. Cross-vendor consistent paradigms are only r2v and first/last frames: the former is this reference route; the latter remains i2v by input contract (adding last-frame constraints beyond first frames), classified here as an i2v keyframe submode. Vendor storyboard features (Sora storyboard editor, Flow Scenebuilder, Runway Multi-Shot Recipe, etc.) are product/orchestration capabilities: organizing shots, invoking underlying generation per shot, then concatenating, without changing model API input contracts.

Locked routes remove route information from episodes/scripts; one project field sets the axis. Script-skeleton canonical resolution (`docs/adr/0045`), video-capability buckets and voice-consistency tiers (`docs/adr/0054`), coupled duration constraints, cost estimation, and enqueueing all read project `generation_mode`, without episode context. Reference-image tiers in coupled duration constraints are an exception: routes determine applicability, but actual narrowing follows whether the unit carries references (`uses_reference_images`). Estimation/execution share project routes, leaving no route divergence. WebUI individual-video endpoints likewise use project routes: reject reference-route projects at submission and direct them to reference-to-video flows, with `video_units` for all three content modes; storyboard preflight/execution use the same project-derived bucket. Existing projects are re-encoded once by v4→v5 (`lib/project/project_migrations/v4_to_v5_generation_route.py`): old `grid` becomes `storyboard` + `grid_storyboard=true`; missing fields get explicit `storyboard`; remove every episode route override without modifying scripts. Agent enqueue tools and data validation explicitly reject cross-family skeleton/project-route mismatches through `ensure_route_skeleton`, directing re-splitting. WebUI individual endpoints guard only routes (directly rejecting reference routes), locating entries by actual skeletons on storyboard routes without skeleton gates. Viewing, editing, and project-archive export remain unaffected; Jianying draft export selects clips by project route and cannot obtain completed clips from mismatched scripts.

## Explicitly rejected

- **Episode route overrides**: another route for one episode demotes "project generates through one route" to episode properties. Capability lookup, cost estimation, and duration constraints would require episode context, while project-level display could indefinitely disagree with episode execution. Express mixed-route episodes through separate projects.
- **Route stamps in scripts**: script JSON routes create a second truth. Any winner on disagreement is wrong: script stamps let historical data override current configuration; project fields silently switch what the script can actually generate. Routes belong to projects; scripts hold content/structure only. Ignore leftover stamps as unknown fields until regeneration removes them.
- **Read-time mappings (compatibility branches)**: mapping old three-valued modes to "route + grid switch" avoids migration but repeats at every read point while writes can still emit old values, preventing removal. Re-encode once through migration; read sides retain no old-mode mapping or route default fallback. Migration supplies explicit missing values in existing projects; HTTP creation requires one of two values and rejects absence. Retain one data-layer write default: `ProjectManager.create_project_metadata` uses `setdefault` to supply `storyboard` for callers bypassing routes (tests/internal scripts), ensuring newly persisted projects contain both explicit fields rather than incomplete project.json. This is a creation-shape fallback, not read-time compatibility. Capability resolution sends unknown/non-string routes to i2v (`lib/config/resolver.video_bucket_for_generation_mode`), defending against manually damaged project.json and dirty no-project-context queries, not mapping old values.
- **Grid as a third route**: it changes no model input contract. Placing assembly beside routes in one selector makes "how to draw storyboards" optimization look like an irreversible project decision and adds an identical-behavior branch everywhere routes dispatch.
- **Grid switch in the agent allowlist**: agents asked to change assembly direct users to settings; asked to change routes, explain immutability. Assembly switches govern future grid-batch storyboard production (grid entry points/estimates read `grid_storyboard_enabled`; individual storyboard generation does not check it, preserving single-image regeneration). This is an explicit user setting, without conversational bypass.

## Consequences

- Creation requires `generation_mode` without default; missing means 422, leaving no silent route lock-in. Creation may include `grid_storyboard`; ad rejects `grid_storyboard=true` consistently in creation, PATCH, and data validation.
- The frontend wizard uses two mandatory route cards without preselection, embedding the grid switch in storyboard and explicitly stating "generation method cannot change after creation." Settings display routes read-only; grid switches change anytime, affecting only future generation without changing existing content.
- Existing override-induced mismatches (such as `video_units` under storyboard projects) receive structural conclusions and re-splitting guidance through Agent enqueueing without silent downgrade. They remain viewable/editable/archive-exportable; WebUI individual-generation and Jianying-export boundaries are described above.
- First/last frames have independent industry names but remain i2v under input-contract criteria. ArcReel last frames are currently optional transition controls on i2v paths; separate first-class modeling is outside this ADR.
