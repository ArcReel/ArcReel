# Split script pipelines into script_plan content / prompt_authoring visuals, with a blocking review gate between them

> `docs/adr/0080` supersedes this ADR's persistent script-plan foundation, per-entry incremental authoring, and fingerprints; content/visual separation, passthrough, and content confirmation remain valid.

Drama/narration used two stages: script_plan (normalize) arranged source into Markdown scene/segment tables with speech (dialogue/voiceover/`novel_text`) embedded in free-text scene-description columns; prompt_authoring (generate-script) reparsed structured fields. Verbatim/source content thus crossed two LLM "structure → free text → structure" gates: screenplay fidelity loss, novel drift, occasional measured narration `novel_text` expansion (>10% only warned). Web also could not see/edit intermediate plans before authoring. Separate responsibilities: **script_plan = content** (scene/segment boundaries, characters/scenes/props, drama `utterances` + `source_text`, narration structured `novel_text`); **prompt_authoring = visuals** (image_prompt / video_prompt). **Pass through already determined speech/source without re-identification**; free-text columns now carry only visual-adaptation content, whose loss is tolerable. Add a **blocking Web review gate**: display structured intermediates for manual/agent edits and require explicit confirmation before expensive visual authoring. Drama, narration, and reference_video share it (narration keeps `novel_text` without `utterances`; reference_video script_plan splits video_units into units → shots narrative text + duration + references, structured JSON serving as sole foundation for ReferenceVideoScript authoring). All three render/edit structured plans on Web and release authoring only after confirmation.

## Considered Options

- **Structured screenplay plans only, leaving novel creation to prompt_authoring**: smaller changes, but asymmetric source outputs, retained source_kind re-identification, and unfixed novel/narration drift. Apply universally, unifying both sources and removing double transcription structurally.
- **Unchanged pipelines with after-the-fact `source_text` distortion detection**: detection is not prevention; verbatim fidelity favors prevention, and Web invisibility remains.
- **Observational gates with automatic authoring**: users can still miss review windows. Blocking until confirmation enables actual review/editing and catches errors before expensive visuals.

## Consequences

- Change script_plan tools (`normalize_drama_script`, etc.) from Markdown-only to structured output; review intermediates remain, rendered from structures rather than free-text originals.
- All script_plan content is generated/persisted through server normalize/split text pipelines (models resolved by `docs/adr/0051` tiers). Subagents orchestrate tools without generating content in their own contexts.
- Reference-video authoring prompts (`lib/prompts/prompt_builders_reference.py`) assemble from structured units without free-text parsing; Web previews/editors render structures.
- Prompt_authoring (generate-script) uses confirmed structures exclusively: preserve plan boundaries and nonvisual `characters_in_scene` / `scenes` / `props`, `utterances` / `source_text` / `novel_text`, generating/overwriting only `image_prompt` / `video_prompt`. Remove source_kind-based speech re-extraction.
- Author existing scripts incrementally **by entry**: fingerprint each plan entry (`lib/script/script_plan_entries.py`, canonical JSON + sha256 constructors shared with inventory registration/comparison), persisting consumed `script_plan_entry_revision` per script entry (hidden from LLMs/PATCH allowlists). Reruns send only mismatched/new content to prompts/output; unchanged entries preserve `image_prompt` / `video_prompt` / `note` / `end_frame_image` / `transition_to_next` / `generated_assets` / `needs_replan`. Order/sets follow plans; remove deleted entries without deleting artifacts, naturally stale/missing through inventory (`docs/adr/0062`). Changing one `source_text` rewrites only that entry, preserving refined prompts/paid artifacts. `generate_episode_script` `scope` / `entry_ids` explicitly request whole-episode or named rewrites without changing outside-scope decisions. Confirmation gates still block incremental paths. Retain whole-plan `script_plan_revision` for compatibility/quick checks; fingerprintless legacy entries fall back to it without false upgrade invalidation. Workflow-state reads backfill them while whole fingerprints match, proving current-plan consumption, using the same assembly-output values from the sole `lib/script/script_plan_entries.py` constructor. Backfill works only before plan changes; whole-fingerprint mismatches erase per-entry consumption knowledge, leaving whole-episode fallback whose rewrites overwrite refined visuals.
- Preserve passthrough through engineering, not prompt discipline: authoring output schemas contain only `scene_id` (alignment anchor) + visual `image_prompt` / `video_prompt`. Merge by `scene_id`, not list order, into confirmed structures; validate unique/full `scene_id` coverage. Keep `utterances` / `source_text` and other nonvisual fields out of output schemas, structurally preventing Structured Outputs drift. Reference-video follows the principle differently: output same-length/same-order authoring-body lists without driftable IDs, pairing positions with equal-unit-count checks; verbatim diffs reject rewritten dialogue markers. Built-in shared `shared/writing_syntax` is body-syntax truth.
- Add Web review state/confirmation actions between stages (services/routers + frontend); user confirmation triggers authoring.
- See ADR 0040 for drama `utterances` / `source_text` models and restrained novel voiceover permission (produced in plans, passed through authoring).
- Stage names are **script planning (`script_plan`)** and **prompt authoring (`prompt_authoring`)** (see `GLOSSARY.md`). Use these IDs in persisted filenames, `project.json` episode fields, script metadata, and artifact kinds; v9→v10 renames existing projects. Preserve only two fingerprint tokens: `SCRIPT_PLAN_BASIS_KIND` (`structured-content/step1`) and `SCRIPT_PLAN_BASIS_INPUT_KEY` (`step1_content`) in `lib.artifacts.artifact_provenance`. They participate in `basis_digest`; inventories store digests, not inputs, so renaming would stale all existing plans/scripts. These values are persisted formats, unaffected by terminology.
