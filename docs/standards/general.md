# 通用

### 注释只陈述代码现在的行为与约束

读注释的人手里只有这份代码。变更原因、议题与 PR 编号、「最近」「本次」「实测」这类时间性措辞属于 commit message 与 PR 描述；写进注释后，代码一改它就变成错误陈述，而且没有人会去更新它。修改文件时，顺手把已有的这类引用改写成对当前行为的陈述。

放行条件：`docs/` 下的专门文档之间互引 spec。

### 工具报出的问题改代码；豁免只给工具已确认的误报

lint、类型检查、依赖检查报错时修代码，不加 baseline、计数阈值或整条规则关闭。豁免只用于确认过的误报，每一处都带理由，写在被豁免的那一行（行内语法不可用时写在最近的配置条目旁）：

- 没有行内语法的工具：actionlint 写在 `.github/actionlint.yaml` 的 `paths.<文件>.ignore`，按错误消息正则精确匹配；deptry 的 `DEP002` / `DEP004` 写在 `[tool.deptry.per_rule_ignores]`，按包名逐项列出。两处都每条一行注释说明理由。
- 策略阈值类的发现（如 Dependabot 冷却期天数）按工具要求调整配置，不用豁免绕过。
- ESLint 的文件级关闭只能经 `eslint.config.js` 的 `files` override，并在配置注释里说明原因。

判定理由是否成立：理由要说明「为什么这里工具判错了」或「为什么这里只能这样写」。「太麻烦」「暂时这样」「later fix」不成立；「React setter 引用稳定」「mount-only 初始化」「第三方库未提供类型」成立。

### 功能变更与对应文档在同一个 PR 里

下列变更同步修改 `website/docs/` 中对应页面（各页职责见 `CONTRIBUTING.md`「各页职责」）：新增创作类型或生成模式；新增供应商或媒体能力；部署目录、端口、环境变量变化；数据目录、备份方式、迁移行为变化；对外 API、许可证或商业使用方式变化。外部 Agent 的安装方式变化时同步 `public/agent-installation-guide.md`。文档落后于代码的那段时间里，用户按文档操作会失败。
