## 异步任务的结果与异常在每条路径上都有人接

### actor 命令在每条退出路径上都由 `SessionActor._dispatch` 或 `_closed_error()` 完成，取消换成 `_ActorClosed`
模式：在 actor 处理器或退出路径里另写一套 complete 逻辑，漏掉取消、同轮取出或退出后入队的分支；或把 `CancelledError` 原样交给调用方
代价：等待 `cmd.done` 的调用方永久挂住，或 `CancelledError` 越过 `except Exception` 穿出 HTTP 请求，排队消息与幂等键残留（严重度：常规）
可判性：需要判断
- #3139 · 2026-10-13 · 复盘发现（Spec #3101）：actor 被取消时在途、排队与退出后入队的命令拿到 CancelledError 或假成功；同一改动的审查（#3138）又发现与消息流异常同轮取出的命令拿错完成值；漏因：没有对应规则
- 降级 · 2026-10-19 · 自 docs/standards/agent-runtime.md「actor 命令的完成只在 `SessionActor._dispatch` 收口」

### 脱离调用方的共享任务自己取走异常
模式：用 `create_task` 起一份共享计算，调用方只经 `asyncio.shield` 等它；请求全部取消（客户端断开）后计算出错，没有人再取这个任务的异常
代价：每到高峰期日志里留下 "Task exception was never retrieved" 这类误导性的未处理异常（严重度：常规）
可判性：需要判断
- #3304 · 2026-10-19 · 合并后修复：`server/routers/_coalesce.py` 的 `RequestCoalescer.run` 在请求全部断开后计算出错，异常无人取走；由 #3321 的性能基准测出（#3320），2b887a16 补 `add_done_callback` 取走异常；漏因：没有对应规则

## 改动没有覆盖全部同类位点

### 撤掉锁或串行化时，逐条清点原先靠这把锁互斥的操作并补上并发处理
模式：读取从持锁改为无锁时只处理了主路径（原子替换），漏掉原先靠同一把锁才不冲突的操作，例如删除空文件，或打开前后两次身份比对之间被写入方替换；这类冲突只在 Windows 或竞态窗口里出现，Linux CI 测不出
代价：Windows 上删除最后一个条目报错并回滚；并发读取把正常的原子替换误判为篡改，返回 500（严重度：常规）
可判性：需要判断
- #3304 · 2026-10-19 · 审查发现：清单读取改为无锁后，删除空清单的 `os.unlink` 没有处理 Windows 共享冲突，写入方替换落在两次身份检查之间被误报为篡改，修复在 22f796f6；漏因：没有对应规则

### 按导入路径写的 lint 守卫覆盖相对写法、`..` 段与转导出
模式：用 `no-restricted-imports` 或 `ImportDeclaration[source.value=…]` 按 specifier 原文拦截模块时，只写了 `@/` 别名一种拼法，`../ui/toast`、`./../stores/…`、`export { x } from` 都能到达同一模块却不报
代价：守卫形同虚设，还给人已经拦住的错觉（严重度：常规）
可判性：机械（拟用 `lint-class-guards.test.ts`，每条导入守卫都带别名、相对路径、转导出三类用例）
- #3310 · 2026-10-19 · 审查发现：toast 守卫与原语目录依赖边界只匹配 `@/` 别名，相对路径、`..` 段、转导出被连续三轮指出（bd66ff6a、29ff3121、ec553f95）；漏因：没有对应规则

### 用一致性测试锁定两份数据时，从会触发失效的一侧枚举
模式：一致性测试只遍历一侧数据（backend 白名单）的键，另一侧（模型目录）新增的项进不了测试，而 backend 对未登记项丢弃参数
代价：目录新增型号后用户选的分辨率被静默丢弃，测试照常通过（严重度：常规）
可判性：需要判断
- #3310 · 2026-10-19 · 审查发现：vidu 图片一致性测试只遍历 `_RESOLUTION_WHITELIST`，漏掉目录有、白名单没有的型号，9eba0d6b 补按目录遍历的测试；漏因：没有对应规则

## 异常的捕获范围与传递

### 尽力而为的旁路查询按会失败的全部方式兜底
模式：可选的预填或查询要构造带凭证的 backend，却只捕获 `ValueError`，凭证文件不可读抛出的 `OSError` 穿出去阻断主流程
代价：建项目与 `/system/narration-defaults` 直接失败（严重度：常规）
可判性：需要判断
- #3283 · 2026-10-19 · 审查发现：取音色表时只捕获 ValueError，Vertex 凭证文件不可读时阻断建项目，cf672f7b 改为捕获 Exception 并记 warning；漏因：没有对应规则

### 带用户指引的结构化异常，在既有宽捕获之前单独放行，传到每个入口
模式：新增一个带用户指引的异常（如继承 `ValueError` 的 `ModelNotInCatalogError`），只在部分入口处理，其余调用链上已有的 `except Exception` 把它吞成笼统错误
代价：用户看不到「去供应商设置重新选择模型」这类指引（严重度：常规）
可判性：需要判断
- #3248 · 2026-10-19 · 合并后修复：Agent 工具查视频能力、草稿晋升、上传后生成概览、图生图检查四条路径吞掉 ModelNotInCatalogError（#3300，#3314 的 c6040abf 修复）；漏因：没有对应规则

## Agent 流程与规范文档

### Agent 流程文档里的 gh 命令显式指定目标对象与结果范围
模式：写给 agent 无人值守执行的 skill 步骤里，`gh` 命令依赖隐式默认值：`gh pr view`、`gh pr ready` 不传 PR 号时取当前分支的 PR，`gh pr list` 不设 `--limit` 时只返回 30 条；从别的分支运行时操作错误的 PR 或漏掉目标
代价：接手路径检查了错误的 PR，或漏掉已有 PR 而重复创建（严重度：常规）
可判性：需要判断
- #3296 · 2026-10-19 · 审查发现：lessons-sweep 接手旧巡检 PR 时 `gh pr view` 未传 PR 号、`gh pr list` 未设 `--limit`，bd4eca73 修复；漏因：没有对应规则

### 增量处理的检查点在本次处理无产出时也要推进
模式：按窗口增量扫描的周期流程只在有产出时提交检查点，空窗口不推进，下次重扫同一窗口，窗口随安静期无限增长
代价：重复核验已丢弃的候选，API 用量随窗口增长，最终可能整次收集失败（严重度：常规）
可判性：需要判断
- #3296 · 2026-10-19 · 审查发现：lessons-sweep 第 6 步规定无改动时丢弃分支、不推进 reviewed-through，bd4eca73 改为只推进标记；漏因：没有对应规则

### 规范写某项由检查拦截或参照某实现时，与检查的判定范围、实现的实际步骤一致
模式：规范正文把检查的覆盖面写宽，或只摘了参考实现的一半步骤，或放行条件与同文其他规则自相矛盾
代价：reviewer 以为已有机械保证而略过，或照着规范写出不完整的路径安全校验（严重度：常规）
可判性：需要判断
- #3310 · 2026-10-19 · 审查发现：`testing.md` 把收集期 DB 检查写成拦截一切真实 DB 访问；`backend.md` 不可信路径规则漏了打开前逐级拒绝符号链接、限定在数据根内一步；`testing.md` 录制文件放行条件与「不手改」矛盾，fb071eb0 修复；漏因：没有对应规则

## 未分组

### 高频路径上按现状重算的派生结果，在输入未变时复用
模式：认领、请求、轮询这类高频路径按现状重算派生结果（内容哈希、推算供应商、重建快照），没有先比对输入的廉价标识（文件 stat、修订号），开销随调用频率和输入规模相乘
代价：事件循环被占满，同进程的全部 HTTP 请求排队，媒体下载卡顿被放大（严重度：常规）
可判性：需要判断
- #3147 · 2026-10-13 · 事故复盘：worker 每个认领周期都对排队中的参考生视频任务按现状推算供应商、重算资产哈希，开销随排队数线性增长；漏因：没有对应规则
- 降级 · 2026-10-19 · 自 docs/standards/backend.md「派生结果在输入未变时复用」

### 两份数据作废时机不同，就各用一个 AbortController
模式：请求挂错取消域：项目级数据（会话列表、技能列表）和会话级加载共用一个 controller，一次会话操作把慢响应的项目级数据当成过期丢弃；或项目级请求没纳入项目取消域，项目切换后迟到的响应覆盖新项目的数据
代价：界面停在旧列表上，或显示另一个项目的数据（严重度：常规）
可判性：需要判断
- #1280 · 2026-07-24 · 合并后修复：终态会话列表刷新未纳入项目取消域，项目切换后迟到的响应覆盖新项目的会话列表；漏因：没有对应规则
- 降级 · 2026-10-19 · 自 docs/standards/frontend-async.md「取消域按数据生命周期划分」

### 自定义 hook 的函数型 option 列进依赖数组，不用 ref 豁免
模式：自定义 hook 接受 selector、回调等函数型 option 时，用 ref 保存最新值来绕开 exhaustive-deps，调用方传入的不稳定引用被静默吸收
代价：回调可能捕获过期状态，且无从发现（严重度：常规）
可判性：需要判断
- #1648 · 2026-08-05 · 批次复盘：hook 的函数型 option 存进 ref 豁免依赖；漏因：没有对应规则
- 降级 · 2026-10-19 · 自 docs/standards/frontend-async.md「Hook 的函数型 option 列入依赖，不存进 ref」

### 跨后端或跨路径改变同一能力维度的来源或处理口径时，先列出全部读点再改
去向：docs/standards/general.md「改变某个能力维度的来源或处理口径时，列出全部读点一起改」（读点跨 `lib/backends`、`lib/generation`、`server/services` 等多个规范的适用路径，所以放进通用规范）
模式：把能力来源切换为叠加用户覆盖后的有效能力，或把静默丢弃统一改为报错时，只改了显眼的几处，同一维度的其他读点（其余后端的载荷构造、测试连接、提交前预估、结算计量）仍按旧口径工作
代价：缺失的首帧或参考图被跳过后照常出片计费；用户收窄的能力在测试连接里放行并真实扣费（严重度：数据·安全·计费）

### 预填或默认值取自它实际生效的上下文中的合法取值
