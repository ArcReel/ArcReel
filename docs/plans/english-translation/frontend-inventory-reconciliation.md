# Frontend comment inventory reconciliation

The first runtime worker inventory used a bare TypeScript scanner without the parser's JSX and template-literal rescanning context. After some nested templates or JSX, the scanner classified later source as string content and omitted comments. It also omitted entire files with no comments before that boundary.

The earlier completion claims for hooks/stores/actions and pages are superseded as scope-completion claims. They describe translated batches only. The executable TypeScript, unchanged-line and literal checks for those batches remain valid, as do independent reviews of the specific translated pairs. They do not establish coverage of omitted, untouched Chinese maintenance prose.

The replacement [inventory helper](checks/frontend_comment_inventory.cjs) walks parsed syntax tokens and reads leading/trailing comment ranges at node boundaries and starts. It removes contained duplicates and uses JavaScript UTF-16 offsets. It inventories every tracked frontend TypeScript and JavaScript file, including tests, types, locales, configuration and e2e, without directory exclusions. Generated vocabulary and localized values remain protected from translation. Han detection is only a classification signal: preserved syntax examples, proper names and test inputs are legitimate exceptions.

[Regression tests](checks/frontend_comment_inventory.test.cjs) exercise actual JSX, nested template expressions, comments after templates, emoji offsets, regular-expression and string exclusions, JSDoc, directives, trailing comments and end-of-file comments. The replacement's extracted ranges are cross-checked against the coordinator's independently written parser-based extractor across every tracked frontend TypeScript and JavaScript file.

Reconciliation reopened all three worker scopes using their immutable pre-edit snapshots. Workers translated the omitted prose, preserved executable strings and test inputs, retained directive attachments and line counts, reran relevant checks and published refreshed per-file hashes and explicit retained-example classifications. No scope was accepted merely because the earlier scanner reported no pending comments.

The evidence directory contains `frontend-parser-extraction-crosscheck.json`, `frontend-all-parser-inventory.json` and the three `*-parser-reconciliation.json` reports. The latter reports are progress inventories, not release approval. Production CSS still requires separate comparison because Tailwind can consume comment tokens.

Final independent scope acceptance is recorded in [the remaining-source review](frontend-remaining-independent-review.json), [canvas review](frontend-canvas-independent-review.json), [parser repair review](frontend-parser-repair-independent-review.json), [426-pair review](frontend-runtime-parser-426-independent-review.json), [root batches review](frontend-root-batches-independent-review.json), [types/loader review](frontend-types-loader-708-independent-review.json), and [i18n types review](frontend-i18n-types-independent-review.json). Earlier 153-file evidence remains limited to its originally extracted pairs. Five late precision refinements are recorded separately and reconciled to exact tested emitted bytes. Final configuration comments and developer-diagnostic strings receive their own reviews and do not inherit acceptance from this TypeScript-comment inventory.
