# Frontend validation environment

Frontend checks use Node 24.12.0 and the existing frozen installation. Browser rendering acceptance uses the repository's `pnpm e2e:server` and `pnpm e2e:remote` flow with `E2E_SCREENSHOTS=1`, without updating snapshots, fixtures, assertions or timeouts. The browser image is `mcr.microsoft.com/playwright:v1.63.0-noble`, digest `sha256:eff16c30e6f3f4af0a03fa4b706120d5e9b0891c344a27d64559aff5900a4a27`.

## Native onboarding differential

The native macOS Chromium case for onboarding step 10 at 1280×600 failed all five candidate repetitions and all five initial immutable-source baseline repetitions with the same 272px client width and 274px scroll width. Those initial baseline and candidate builds had identical 221,969-byte CSS, SHA-256 `9ccaff6f33408e088c34e47e624c6be8683e5f55884357757c88b29a074db2c7`. This evidence establishes a failure in that measured native environment, without asserting universal platform behavior. The candidate passed all three repetitions in the official Linux Playwright image with screenshots enabled.

A later three-repeat native baseline run was not a controlled CSS comparison. The temporary frontend-only baseline copy lacked the original repository-root `.gitignore`; generated Playwright `test-results/error-context.md` became Tailwind inputs during subsequent builds, increasing CSS to 231,350 bytes. Those three failures remain recorded, but must not be counted as repetitions with identical CSS. Only the temporary baseline harness was repaired: the immutable original root ignore file was copied into its temporary root, generated results were archived and removed, and screenshots reference the immutable original baselines. The immutable source archive was never edited.

## Official full-suite boundary

The first full official suite completed against a frozen candidate build: 1,495 passed, five skipped and one failed in 22.6 minutes. All 161 emitted files were copied to an evidence directory after checking their exact recorded SHA-256 hashes. Late, independently reviewed comment refinements are recorded separately by the coordinator. The final source was rebuilt by the identical official webServer `pnpm exec vite build` command. All 161 emitted files exactly match the tested bytes, including CSS. A clean immutable-source baseline build also matches all 161 final emitted files exactly; no filename normalization was necessary. The final source manifest records nine changed files after the first tested-source capture: five source comment refinements, ESLint diagnostics and its guard test, plus environment/Knip comments. No e2e fixture or scenario file changed. These deltas reconcile to identical emitted bytes.

If only generated chunk names differ, acceptance requires a unique complete bijection of emitted assets. Only exact parsed references to those emitted assets may be mapped; every other byte and the complete ordered reference graph must match. Ambiguous identities, unexplained payload differences and unrecognized reference locations fail that comparison. CSS equality is verified separately. The comparison helper and its adversarial checks live in `checks/compare_emitted_asset_graph.cjs` and `checks/compare_emitted_asset_graph.test.cjs`.

One failure has been observed in the full official run: the 1024×600 long-workspace-notifications scenario retained three toast elements instead of reaching zero within its original 15-second expectation. Its trace and error context were preserved. The same scenario then passed all five narrow candidate repetitions and all five clean baseline repetitions under the same official image, preview port, original assertions and screenshots. The full-suite transient did not reproduce and remains unclassified; it is not labeled preexisting. The unchanged full official rerun passed 1,496 tests, with five existing skips, in 19.8 minutes. The five skipped reference-editor alignment cases require visible scrollbars, which remote run-server filters out; their original native cases then passed all five viewports in 8.6 seconds. The first failure remains separately recorded. Exact commands, image digest, source/fixture hashes, raw asset comparisons and artifact paths are recorded in `frontend-official-e2e-validation.json`.

A final rebuild detected a 42-byte CSS regression after translated ESLint diagnostic prose exposed standalone `z-onboarding` to Tailwind. That comparison was rejected and preserved. The coordinator grouped the same identifiers using the slash-separated form already in the adjacent comment; no stylesheet value changed. Rebuilds after this repair and after the final native tests restored exact equality for all 161 emitted files.

The retained failure trace records `data-expanded` on the viewport and all three toasts, plus the last input point visually over the third toast after the dialog closes. Installed BaseUI 1.9.0 defines expanded as hover or focus and pauses timers in those handlers. This supports the timer-pause hypothesis without proving the exact event or timer state throughout the assertion. Details and original frame are retained in `frontend-toast-trace-observations.json` and `frontend-toast-first-failure-frame.jpeg`.

The owned browser-server process and container were stopped; their ports were checked free. Docker.app remains available.
