# Project Schema Migrations

Follow this document when adding/changing a migration in `lib/project/project_migrations/` or the artifact backfill planner (`lib/artifacts/artifact_planner.py`). Migration-chain structure, `backup` naming, and failure verdicts are in `docs/adr/0022`, `docs/adr/0062`, and `docs/adr/0075`. This document contains conventions not discoverable from code.

## Steps

1. **List every legacy shape this step must handle.** Each is data written by older code that differs from current expectations. Add discoveries to the table below. Completion: every relevant shape has a constructed sample in `tests/legacy_project_shapes.py`.
2. **Implement the migrator with outcomes for registration and skips.** Add at most one step per release. If `CURRENT_PROJECT_SCHEMA_VERSION` exceeds the value at the latest `v*` release tag, amend the unreleased latest step; add a new one only when equal. Manifest-changing migrations return `ArtifactBackfillOutcome` (`lib/project/project_migration_report.py`), folded by the runner into project-local `.migration_report.json`. Every no-registration planner branch calls `_skip(...)` with a reason; user-visible skips also carry `category` `unreadable` (artifact bytes unreadable) or `legacy_audio_basis` (missing historical TTS settings). Skips without `category` lack computable basis, read as missing, and are excluded from reports. Completion: every skip with `category` appears in the report.
3. **Test legacy samples through user-visible results.** Beyond migrator assertions, at least one case uses `WorkflowStateService.get_project_summary`/`get_status` or the demo read model to assert counts, states, and preview availability. Completion: tests under `tests/integration/lib/project/project_migrations/` cover the whole `migrate_project_dir` chain from the previous actual installation or earlier to current, not only one step.
4. **Update user-facing migration guidance.** The “项目结构迁移” section in `website/docs/ops/deployment.md` describes backups, reports, and retries; update it when behavior changes.

## Conventions

- Upgrade paths span versions: handle every older variant, not only the previous release's standard shape.
- Use `lib/project/project_migrations/backups.py`. Register migrators owning input backups in runner `_MIGRATORS_WITH_OWNED_BACKUP`.
- Manifest rewrites use `activate_artifact_target_state(bump_schema=True, target_schema_version=...)`, read-only preflight before writes.
- Full activation registers all present artifacts as current. If only a basis input changes and existing artifacts should remain valid, plan before/after and rewrite only previously current entries with changed targets (v13→v14 style normalization). Never turn already-stale entries current. Envelope archive import stages claims before migration with `stage_preserved_artifact_claims`, so the same chain rewrites them without import-specific branches; import activation restores migrated claims from content evidence.
- Normalize old shapes written by normal flows once at chain start with `legacy_shapes.normalize_legacy_shapes`, at the first version ≥ v6, before script rewrites or target planning. Add discoveries there rather than rejecting independently in each step. Whole-project data rejection is limited to unreadable `project.json`/scripts/`versions.json`/`.arcreel_artifacts.json`, corrupt item structure (schema-6 ad indexes/units or nonobject v8 units), and unsafe imports. Planner tolerance applies only in `_activation_mode`; runtime stays unchanged.
- Record normalization as `MigrationAdjustment` (已调整); unreadable retained files as skips with `category` (未能带入). Reports have only these two columns. Uncomputable basis (input gaps, missing history, bad paths, non-UTF-8 source) has no `category` and is filtered by `write_migration_report`/`extend_migration_report`. Units needing replanning are excluded too: `write_migration_report` centrally removes their image/video/audio skips, not individual branches. Import merges failed registrations and repair placeholders regardless of schema via `extend_migration_report`. Midchain failures write `complete: false` reports and merge them on retry; incomplete reports are hidden. If current schema committed before failure, retry no longer enters the chain; runner completes the outstanding report.
- Preserve displaced content with `backups.set_aside_as_kept_copy` (`<name>.kept.v<N>-<ts>`), not cleaned by `cleanup_stale_backups`; store its path in adjustment backup. Ordinary rewrites still get versioned backups.
- Input gaps do not mean unprojectable basis. They block generation only; build basis from present inputs and record missing items in `absent` (`lib/artifacts/input_gap.py`). Omit absent without gaps, preserving complete-input digests. Pre-schema-18 planning retains old gap-means-unprojectable behavior, leaving earlier activation/provenance unchanged.
- Truly uncomputable targets remain unregistered and read missing, not nonexistent or whole-project failure. Only `artifact_unreadable` file failures enter reports. Archive imports require confirmation only for nonempty reports; healthy current exports reimport without confirmation/report.
- When relaxed planning makes previously skipped artifacts registrable, plan before/after and add only newly projectable, unregistered targets; never touch existing registrations (v17→v18 input-gap backfill in `lib/project/project_migrations/input_gap_backfill.py`). Envelope imports use the same difference for artifacts without claims.
- Migrations never advance project activity: preserve `project.json` and script `metadata.updated_at`; new scripts do not set `updated_at` to migration time. Do not call `lib.project.project_activity.record_project_activity` or business writers that call it (draft/formal-plan transactions, timeline storage, project memory).
